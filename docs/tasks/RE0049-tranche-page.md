# Страница транша: погашение, локальные компоненты, аккордеоны витрины (RE0049)

## Коротко

Страница транша `apps/postrade/deals-app/pages/Tranche.html` докомплектовывается:
погашение транша через контекстное меню кнопки «…» в шапке — с отражением
погашенности на страницах НКЛ и сделки; хедлесс-тайлы раздела «НКЛ» (в контрагента
— риск-метрика) и тайл «Валюта транша» становятся локальными компонентами; ЕТС и
«Техническая информация» переезживают в общие с переключением потребителя
НКЛ/Транш; меню витрины собирает родственные страницы под аккордеоны — правило
фиксируется в «Правилах и паттернах Локальных компонентов». Для финансиста ДИД.

## Решения человека (02.11.2026)

| Вопрос | Решение |
|---|---|
| Погашение транша | Кнопка с тремя точками в хедере страницы транша, справа от кнопки расчёта ОСЗ, открывает контекстное меню с пунктом «Погасить». Механизм погашения **стандартный**. Погашенный транш отображается погашенным так же на странице НКЛ и на странице сделки |
| Хедлесс-тайлы раздела «НКЛ» | Три тайла — в локальные компоненты, единственное состояние. Отображают информацию от родительской НКЛ (Договор займа (НКЛ); НКЛ — невозобновляемая кредитная линия). В тайл контрагента добавить **риск-метрику**; остальные два уже выглядят нормально — лишь бы данные шли от НКЛ |
| Договор и дополнительные соглашения (3.1) | Тайл переиспользуется из локальных компонентов — готовый. У транша свои номера договора и ДС: на каждый транш составляется свой отдельный договор и отдельные доп. соглашения, по которым могут вноситься изменения |
| Валюта транша (3.2) | Локальный компонент: на странице те же два поля, что уже есть; модальное окно шириной **три колонки** с двумя полями — выбор валюты из списка и инпут суммы лимита. Постфикс с валютой у суммы **не отображается**, только сама сумма. Обычно валюта транша соответствует валюте НКЛ, но не всегда — заполняется вручную |
| Фондирующий кредит (3.3) | Информации пока нет, человек вернётся с ней позже. Пока оставить с пометкой «Демо» |
| ЕТС (3.4) | Тайл аналогичен тайлу на странице НКЛ: ЕТС у транша свои, UI тот же — переиспользуем сделанное для НКЛ. Вынести в общие локальные компоненты |
| Техническая информация (3.5) | Аналогично НКЛ, но с дополнительным полем «CRM ID продукта». Вынести в общие; в конструкторе добавить переключение между потребителями (НКЛ и Транш) — потом добавятся и другие |
| Аккордеоны витрины (4) | Страницы, являющиеся частью одного целого, собрать под одним аккордеоном: «Договор и дополнительные соглашения» (включая «Фильтр дополнительных соглашений») и «ЕТС» (четыре пункта: ЕТС, История изменения базового индекса, История изменения ставок, Процентная схема ЕТС). Впредь делать так всегда, когда у тайла есть внутренняя страница с уникальными для неё виджетами. Записать это правило в «Правила и паттерны Локальных компонентов» |

## Решение

**1. Погашение транша.** В шапке Tranche.html справа от кнопки «Расчёт ОСЗ» —
кнопка с тремя точками, контекстное меню (компонент ДС) с пунктом «Погасить».
Механизм погашения стандартный; эталон — открытый вопрос 2, до ответа на него
этап не начинать (§7: не достраивать догадкой). Погашенный транш отображается
погашенным на странице транша, на странице НКЛ (Instrument.html, таблица
траншей LoanNrlTranchesTile) и на странице сделки (Deal.html).

**2. Хедлесс-тайлы раздела «НКЛ».** Новый виджет в `widgets/tiles/` (одна папка,
варианты «Контрагент» / «Баланс и валюта» / «Общая сумма лимита» — состав
вариантов решает исполнитель по образцу CounterpartiesTile): все данные — от
родительской НКЛ; в «Контрагенте» — риск-метрика RiskMetric. Единственное
состояние. Паспорт, страница витрины.

**3. Раздел «Общая информация» (тайлы от «Договор и дополнительные соглашения»
до «Техническая информация»).**

- «Договор и дополнительные соглашения» — готовый InitialAndAdditionalAgreementsTile
  из локальных компонентов, данные транша: свои номера договора и ДС.
- «Валюта транша» — новый локальный компонент: тайл с двумя полями + модальное
  окно шириной три колонки (уровень `modal--w3`, класс сверить по ДС на сборке):
  «Валюта» (выбор из списка) и «Сумма лимита» (инпут; постфикс с валютой не
  отображается). Обычно валюта транша = валюте НКЛ, но не всегда — поле
  заполняется вручную.
- «Связь с фондированием» — без изменений в данных, пометка «Демо».
- «ЕТС» — TransferRateTile: ЕТС у транша свои, UI тот же.
- «Техническая информация» — LoanExternalDataTile: вынести в общие локальные
  компоненты; в конструкторе витрины переключение потребителя «НКЛ | Транш»;
  у Транша добавляется поле «CRM ID продукта» (у НКЛ его нет). Потребители
  потом добавятся и другие — переключение делать расширяемым.

**4. Витрина: аккордеоны.** Пункты меню одного целого — под одним аккордеоном:
«Договор и дополнительные соглашения» (тайл + «Фильтр дополнительных
соглашений»), «ЕТС» (ЕТС, История изменения базового индекса, История изменения
ставок, Процентная схема ЕТС). Впредь так всегда, когда у тайла есть внутренние
страницы с уникальными для страницы виджетами. Правило записать в
`design-system/patterns/LocalComponents/LocalComponents.html` — правка файла ДС
по прямому поручению человека (п. 4). Механику группировки (паспорта и
`kit-build.mjs`) смотрит исполнитель на этапе.

## Вне задачи

- Наполнение «Связи с фондированием» реальными данными и логикой: человек
  вернётся с информацией; в этой задаче — только пометка «Демо».
- Правки дизайн-системы, кроме раздела правил в LocalComponents.html.
- Коммит и пуш — только по прямой просьбе человека.
