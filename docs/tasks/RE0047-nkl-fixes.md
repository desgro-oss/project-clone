# Правки НКЛ и модалки ЕТС (RE0047)

## Коротко

Четыре замечания ревью человека по модулю `apps/postrade/deals-app/`: на страницах
«Договор займа (НКЛ)» и «Договор и дополнительные соглашения» кнопка «Документы по
сделке» открывает пустую модалку контрагентов; модалка ЕТС узкая, лейбл «Рабочих
дней до применения БИ» усекается многоточием без тултипа, первые три поля не
занимают всю ширину. Исправляем в одном заходе, без новых виджетов.

| Первые три поля модалки ЕТС | Растянуть поровну на всю ширину контентной области |

## Как сейчас (замер 02.11.2026)

- Кнопка «Документы по сделке» (InitialAndAdditionalAgreementsTile) диспатчит
  `loanaction {action:'DOCS'}`; страницы Instrument.html:257–258 и
  InitialAndAdditionalAgreements.html:267–268 открывают `#deal-ecm-scrim`
  программно (`DSModal.open`). Список контрагентов рисует `refresh()` в
  CounterpartiesEcmModal.js, но он вызывается только capture-слушателем клика по
  `[data-modal="deal-ecm-scrim"]` (js:126–128) — на Deal.html кнопка имеет
  `data-modal` и список рисуется, на НКЛ/ДС модалка открывается с пустым
  `[data-ecm-items]` в `data-state="data"`. Данные правильные: `members()` у
  CounterpartiesStore — участники всей сделки (Instrument.html:288–292).
- Модалка ЕТС (TransferSchemaModal.html:37) — `modal--w4` (595 px).
- Лейбл «Рабочих дней до применения БИ» (html:54) — `ds-label` без
  модификаторов: `.ds-label__text` в ДС nowrap + ellipsis, тултипа нет. Паспорт
  (TransferSchemaModal.md:151) и комментарий CSS при этом уже заявляли перенос
  на две строки — код им не соответствовал.
- Раскладка: `.lc-transfer-schema-modal__grid` — `repeat(4, minmax(0,1fr))`;
  первые три поля по 1 колонке (3/4 ширины, четвёртая колонка ряда пустая),
  «Комментарий» — `1 / -1`, «Тип ставки» — `span 2`.

## Решение

**Правка 1 — контрагенты по всей сделке.** В `case 'DOCS'` обеих страниц перед
`DSModal.open` вызывать `__dealEcmApi.refresh()` скрима — API виджет вешает сам
(CounterpartiesEcmModal.js:151–152); порядок refresh→open тот же, что в рабочем
capture-слушателе (карточки до открытия, фокус не сносится). Источник данных не
меняется: `members()` уже вся сделка.

**Правки 2–4 — модалка ЕТС.** `modal--w4` → `modal--w5` (747 px); лейблу —
`ds-label--wrap` (перенос до двух строк) + тултип-страховка
`data-tooltip-truncated="only"` на `.ds-label__text`; грид — 12 колонок: три
первых поля по `span 4` (поровну на всю ширину), «Тип ставки» — `span 6`,
«Ставка»/«БИ»/«Спред» — `span 3` (прежние пропорции), «Комментарий» — `1 / -1`.
Проверить то же поле в тайле TransferSchemaTile — при том же усечении тот же
паттерн.

Паспорта, CHANGELOG виджетов и спеки страниц привести к новым фактам; preview
пересобрать `assemble.mjs`.

## Вне задачи

- Не меняем CounterpartiesEcmModal.js (виджет работает; правка на стороне страниц).
- Не меняем дизайн-систему.
- Коммит и пуш — только по прямой просьбе человека.

### Целостность данных (02.11.2026, находка человека)

В тайле «Контрагент» стоял «СамолётИнвестХолдинг Inc», а в документах и составе
его не было. Причины две: в базе было два контрагента с одним именем (`ul-1`,
`ul-10`) — состав сделки ищет по имени и брал `ul-1`, договор ссылался на
`ul-10`; и ни у одного из четырёх договоров НКЛ контрагент не входил в `knr`
сделки. Окно «Контрагент» отмечает выбор только среди участников, поэтому
казалось, что ничего не выбрано.

Исправлено: дубль слит в `ul-10`; контрагент договора добавлен в участники всех
четырёх сделок (1027, 1028, 1024, 1030); правило «имена уникальны, контрагент
договора — участник» записано в шапке `mock-counterparties.js`; инвариант
проверяется шагом постоянного сценария (исходный контрагент снимается до правок
сценария) и доказан откатом. Регресс сценариев: Instrument, ДС, Deal, ЕТС — OK;
FinancialMetrics — 2 блокера, те же на данных до правки (к этой задаче не
относятся).

Не проверено (нет браузера, геометрия в `page-run` нулевая): фактический перенос
подписи и вид тултипа в живом Chromium, пиксельная ширина окна; состояния окна
контрагентов `empty`/`loading` на демо не воспроизводятся — в данных нет сделки
без участников.

Затраты записаны одной строкой Э1: заход непрерывный, между этапами не было
отдельных запросов к модели — окна для пометок Э2 и Э3 пусты.
