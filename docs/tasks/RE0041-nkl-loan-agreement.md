# Страница договора займа (НКЛ) и её внутренние страницы (RE0041)

## Коротко

Страницы договора займа НКЛ нет. Это звено дерева «сделка → договор → транш» между страницей
сделки и уже собранной страницей транша (`Tranche.html`, крошка «2.1.1. Договор займа (НКЛ)»).
Нужно собрать её и две внутренние страницы — «Договор и дополнительные соглашения» и «Единая
трансфертная ставка» — с тайлами, окнами и состояниями по скринам дизайнера. Читатели —
финансист ДИД и агент фронтенд-разработчика.

## Решения человека (26.10.2026)

| Вопрос | Решение |
|---|---|
| Где собирать | в модуле `postrade/deals-app`, рядом с `Deal` и `Tranche`. Трек модуля `product`: каждую правку модуля агент делает с подтверждения человека |
| Тайл «Договор и доп. соглашения» и тайл «Договор» — какие типы продуктов | все 9 типов макета вариантами одного тайла: на странице НКЛ показан вариант НКЛ, в витрине — все |

| Контрагент договора | свой у договора, один; выбирается в окне контрагентов (режим инструмента): из участников сделки или новый — новый тоже становится участником сделки. Один контрагент может быть у нескольких инструментов и КНР сделки одновременно (26.10.2026, вопрос 33) |
| «Погасить», «Перенести» | окна дерева продуктов: погашение и перенос (окно с деревом продуктов, доступных для переноса) |
| Макет | опечатки правим; маска даты — `ДД.ММ.ГГГГ` |
| Вне задачи | «CRM ID продукта» на странице транша пока не делаем |
| Разделы витрины (27.10.2026) | локальные компоненты страницы НКЛ — в новый раздел витрины Post «НКЛ»; тайл «Договор и доп. соглашения» и вся связка договора и ДС (тайл «Договор», карточка ДС, окна) — в «Общие» (решение агента 22) |

### Тайл «Транши»

- Карточки — ровно те транши, что висят под этим договором займа в дереве продуктов
  (`ProductTreeStore`), строками ProductRow, как в «Продуктах сделки»: номер и название, дата
  подписания договора, сумма лимита (ответ 20); заголовок ведёт на `Tranche.html`.

- Изменения видны и на странице сделки: данные одни.

### Поля тайлов договора по типам

Прочитано по матрице `Tile_Contract_&_AdditionalAgreement` и по `Tile_Contract` (26.10.2026).
Подписи полей — как на скрине; тип тайла = тип продукта.

| Тип тайла | Пара в дереве продуктов (`INSTRUMENT_TYPE_CATALOG`) | Поля договора | Есть в |
|---|---|---|---|
| НКЛ | `LOAN_NCL` «Договор займа (НКЛ)» | Номер договора · Дата подписания · Плановая дата погашения | обеих матрицах |
| Deprecated | нет | как у НКЛ | только в матрице тайла договора |
| Транш | узел `TRANCHE` (страница транша) | как у НКЛ | обеих |
| Акции/Доли | `SHARES` «Акции / Доли» | как у НКЛ, затем Дата поставки · Дата перехода прав собственности | обеих |
| Опционы/РЕПО | `PUT_REPO`, `CALL_REPO` | как у НКЛ, затем Срок действия | обеих |
| Корпдоговор | `CORPORATE_AGREEMENT` «Корп. договор» (своей страницы пока нет) | как у НКЛ | обеих |
| Обеспечения | нет в каталоге инструментов (у обеспечений свои страницы) | Номер договора · Дата подписания · Дата окончания | обеих |
| Гарантия с баланса ПАО | нет в каталоге | Номер гарантии · Дата заключения · Дата предоставления · Дата окончания | обеих |
| НКЛ с баланса ПАО | `NCL_PJSC_BALANCE` | Номер договора · Дата подписания · Дата погашения | обеих |
| Соглашение о комп. выплатах | нет в каталоге | Номер договора · Дата подписания | только в `Tile_Contract` |

Общее для всех типов:
- **Тайл на странице договора** («Договор и дополнительные соглашения»): когда есть ДС, к полям
  договора добавляются «Номер последнего ДС» и «Дата подписания ДС». У «Соглашения о комп.
  выплатах» в матрице тайла нет.
- **Кнопка «Документы по сделке»** (скрепка) есть во всех состояниях, кроме «правка недоступна,
  данных нет»: там только «Не заполнено».
- **Стрелка «→» в шапке** — при заполненном договоре, в том числе в просмотре: на макете её при
  просмотре нет, это ошибка макета (ответ 29).
- **Пустой тайл:** при праве на правку — «Заполнить» и «Документы по сделке»; без права —
  «Не заполнено».
- **Тайл «Договор» внутренней страницы** — те же поля, без полей ДС, с кнопкой «Документы по сделке».
- **Окно «Договор»** нарисовано только с «Номером договора» и «Датой подписания» — это вариант
  НКЛ. У других видов инструментов свои особенности и набор полей окна; покажем при сборке их
  страниц, окна по другим типам не делаем (ответ 31). «Плановая дата погашения» у всех типов
  берётся из инструментов и траншей, а не вводится в окне.

### Правила

- **Плановая дата погашения** в тайлах договора берётся из инструментов и траншей (ответ 31).
  У договора займа (НКЛ) — самая поздняя плановая дата погашения среди его траншей; без траншей —
  прочерк. У других видов инструментов свои особенности — разберём при сборке их страниц.
- **Правка недоступна**, если её не позволяет роль, статус сделки или договор погашен. Правила те
  же, что у страницы сделки: договор правят те же роли, что инструменты и транши дерева продуктов
  (ответ 22); сами роли в прототипе не моделируются — вопрос страницы. Режим переключается
  панелью прототипа; на правке погашения `RepaymentModal` тайлы переходят в просмотр.
- **Схема ЕТС** не сохраняется, если не заполнена ставка (Alert «Необходимо заполнить данные
  по ставке»), не заполнены даты начала и окончания, дата окончания раньше даты начала или её
  период пересекается с периодом другой схемы этого договора (Alert «Период пересекается с
  другой процентной схемой», ответ 19). Тексты ошибок дат — как у ставки, согласовать при сборке.
- **Ставка:** фиксированная — значение в %; плавающая — БИ + спред, в тайле «15% КС +5%»:
  первое число — значение БИ на сегодня плюс спред. Справочник БИ — одно значение, КС. Тайл ЕТС
  показывает схему на сегодня, а если сегодняшней нет — последнюю по периоду (ответ 27).
- **Номер ДС** — `<порядковый номер>-<номер договора>` («4-1234567890»): так в карточке ДС, в
  тайле и в окнах (ответ 26). Номер решения — одна строка. Поле «Дата создания» ДС называется
  «Дата подписания» (ответ 25) — и в окне, и в тайле договора.
- **Карточка ДС:** шеврон сворачивает и разворачивает её; карандаш — только с правом.

### Состояния

- Каждый тайл: не заполнено (с правом — «Заполнить», без права — «Не заполнено») · заполнено
  · правка доступна / недоступна; переключение — панелью прототипа и в витрине.
- Пустые: тайл «Транши» без траншей; страница без ДС; страница без схем ЕТС (иллюстрация ДС).
- Окна: пустое и заполненное; окно схемы — фиксированная, плавающая, ошибка без ставки,
  ошибка пересечения периодов.
- Тосты ЕТС на скрине — перечень для разработки, а не одновременный показ.

### Данные

`apps/postrade/deals-app/data/` по образцу `references/data-template.js`: договор, ДС,
процентные схемы, история ставок и БИ, справочники. Имена в стиле API,
