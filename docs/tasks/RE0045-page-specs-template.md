# Спеки страниц: единый канон разделов и миграция (RE0045)

## Коротко

Спеки страниц `*.screen.md` написаны четырьмя семействами структур: агент сборки,
приёмки и фронтенда не может читать их предсказуемо. Нужен один канон разделов —
по образцу паспорта виджета (RE0004): единые `##`, своё — только `###` внутри.
Мигрируются страницы модулей проекта (~19 спек) — там лежат утверждённые
страницы, соответствующие реальному продукту; концепты (drafts) остаются при
своих форматах. Канон стережёт новый сторож сенсора. В канон входит раздел
«Сценарии» — задел под будущий раздел сценариев (как карта экранов), где у
страницы от одного до нескольких сценариев с ролью: точка входа, звено, завершение.

## Решение

### Канон — 16 разделов

Единственный источник — `references/template.md` скилла `screen-spec`
(обновить с 13 до 16). Сторож читает канон из заголовков `##` шаблона, копий
списка нигде нет — как КТ2 читает `Component.md`.

| № | Раздел | Что внутри |
|---|---|---|
| 1 | Назначение (Purpose) | с обязательным `### Бизнес-смысл (Business context)` (RE0038: таблица, Источники, `[[вики-ссылки]]`) |
| 2 | Адрес и навигация (Route) | адрес, пункт меню, крошки; `### Параметры адреса`, если есть |
| 3 | Сценарии (Scenarios) | участие в бизнес-сценариях — ниже |
| 4 | Пары во фронтенде (Frontend pairs) | таблица по элементам; нет пары — «Не применимо: …» |
| 5 | Раскладка (Layout) | дерево, шапка PageHeader, блоки контента из 12 колонок |
| 6 | Компоненты (Components) | таблица компонентов ДС и виджетов |
| 7 | Таблицы (Tables) | таблицы в разметке страницы; виджетные — ссылкой на паспорт |
| 8 | Поведение (Behavior) | пары «триггер → результат»; `### Скрипт экрана` |
| 9 | Модальные окна (Modals) | окна страницы; виджетные — ссылкой на паспорт |
| 10 | Состояния (States) | подразделы Loading / Empty / Error / Disabled обязательны + свои состояния |
| 11 | Тексты интерфейса (Texts) | русский, инфинитив |
| 12 | Данные (Data dependencies) | `### API` / `### Mock` / `### Permissions` |
| 13 | Соответствие файлов (Implementation mapping) | прототип → фронтенд по файлам |
| 14 | Доступность (Accessibility) | разметка, aria, контраст |
| 15 | Осознанные отклонения (Deviations) | `### Дефекты ДС, найденные при сборке`, `### Отклонения от каталога ДС`, `### Ограничения статического сенсора`, `### Отличия от макета`, `### Кандидаты в ДС` |
| 16 | Открытые вопросы и допущения (Open questions) | последний, не удаляется никогда |

Правила — как у паспорта виджета (`design-system/templates/local-component/Component.md`):

- свои темы — только `###` внутри подходящего раздела; новых `##` нет
  (заменяет нынешнее правило скилла «свои разделы вставляются между
  стандартными с перенумерацией»);
- неприменимый раздел — строка «Не применимо: …», раздел не удаляется;
- YAML-шапка обязательна: `screen, kind, title, file, module, frontend, route,
  components, widgets`; `scenarios` — опционально (ниже);
- сопоставление с каноном — по русской части заголовка (англ. имя в скобках
  нестрого; старые спеки без скобок при миграции получают скобки);
- сквозная нумерация разделов сохраняется — на неё указывают кросс-ссылки;
- один канон для `kind: screen` и `kind: document`.

### Раздел «Сценарии (Scenarios)»

- Таблица: `Сценарий | Роль страницы | Переходы (откуда → куда)`; строка на
  сценарий, сценариев у страницы — от одного до нескольких.
- Роль — одна или несколько сразу: точка входа / звено цепочки / завершение.
- Имена сценариев не выдумываются: известные из ТЗ и бизнес-контекста
  пишутся; неизвестное — «Не решено (ДД.ММ.ГГГГ)»; страница вне сценариев —
  «Не применимо: …».
- Резерв в YAML-шапке: необязательное поле `scenarios:` (список имён) — задел
  под агрегацию будущим сценарным разделом (источник истины — открытый
  вопрос №3).
- Сам сценарный раздел (карта сценариев) — вне этой задачи; здесь только
  место в спеках.

### Сторож канона

- Сенсор `layout-check.mjs` (где живут Б-коды) — новый код: «раздел не в
  каноне», «нет канонического раздела», «раздел повторён». Канон — заголовки
  `##` из `references/template.md`.
- Граница проверки — спеки `pages/` модулей проекта, как у паспортов страниц
  (RE0039): концепты и drafts со старыми форматами, фикстуры и корневой хаб
  не проверяются и не краснеют.
- Фикстуры ok/bad в `.agents/tools/fixtures/`, кейс в селфтесте сенсора.
- Вводится после миграции (Э3): до этого гейт не зелёный на новых правилах.

### Миграция

Охват — только страницы модулей проекта, 19 спек: clients-app (3), tasks-app (1),
dashboard-app (1, спец), host-app (1), banker-app (1, спец), funds-app (1),
deals-app (9, из них 3 старого формата), post-reports-app (2). Из них: старый
формат — 3 (deals-app `Deal`, `MainPage`, `Portfolio`, полная перекладка по карте
соответствия); семейство A — 4 (добавить «Сценарии» и «Отклонения»); A′ — 10
(добавить «Пары», «Сценарии», «Отклонения»); спец — 2 (добавить недостающие
разделы, свои убрать в `###` канонических).

- Разовый скрипт `docs/misc/RE0045-page-specs/migrate-specs.mjs` (пишется
  редактором, не шеллом), работает по карте соответствия.
- Сохранность текста доказывается нормализованным сравнением «до/после»:
  меняются только заголовки и позиции разделов, содержимое не теряется;
  отчёт — `docs/misc/RE0045-page-specs/migrate-specs.specs.json` (перенесён
  из docs/tasks 30.10.2026: разовый материал живёт в misc рядом со скриптом).
  Ручные правки — только после чистого отчёта сравнения.
- Кросс-ссылки «раздел N» / «§N» между спеками перенумеровываются, контроль —
  поиском по спекам после миграции.
- YAML-шапки доукомплектуются полями шаблона (`module`, `frontend`, `route`,
  `components`, `widgets`) — по чек-листу MS0003. Пары во фронтенде — по README
  модулей и `docs/misc/project-tree.md`; нет пары — `new`.
- После миграции — пересборка `node .agents/tools/kit-build.mjs` (паспорта
  страниц как раз модулей; рассинхрон ловят КТ3/КТ5) и
  `node .agents/tools/screen-map.mjs` (карты).

## Критерии приёмки

- У каждой спеки страниц модулей (19 файлов из «Миграции») состав заголовков `##` — ровно канон из 16 разделов, порядок канона, без повторов; своё — `###` внутри канонических разделов.
- Концепты, drafts и корневой `index.screen.md` не изменены (в git — только спеки модулей и файлы задачи).
- Содержание не потеряно: нормализованное сравнение «до/после» без потерь для каждого мигрированного файла (отчёт `docs/misc/RE0045-page-specs/migrate-specs.specs.json`).
- Кросс-ссылки «раздел N» ведут на верные разделы после перенумерации.
- Паспорта страниц пересобраны и отражают новую структуру; шаг `kit` гейта зелёный.
- Сторож проверяет канон только у спек модулей (не drafts, не фикстуры) и ловит внесённый вручную дефект (лишний `##` вне канона, пропущенный канонический, повтор) — доказано откатом; селфтест сенсора OK.
- MS0003 — superseded со ссылкой на RE0045.
- `node .agents/tools/kit-build.mjs --selftest` — OK; `node .agents/tools/lessons-cli.mjs gate` — `ВЕРДИКТ: OK`.
