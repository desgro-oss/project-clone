## Принятые решения
- Пользователь: отделить UI инструментария от продукта и ДС; подход `tooling/` поддержан.
- Пользователь: продукт в будущем переходит на React; начат соседний `ibp-design-project-react`.
- По текущему запросу план и структура конкретизированы для React + TypeScript + shadcn/ui + Vite; Basecoat остаётся сравнительной альтернативой.
- Пользователь: нужны 2–3 логических этапа с возможностью остановиться и посмотреть; план содержит три этапа реализации.
- Пользователь: продуктовый харнес и харнес разработки tooling пока долго живут вместе, но должны быть легко отделимы; жёсткого разделения сейчас не делать.
- В задаче: общий вход, два профиля маршрутов и отдельные роли/инструкции/приёмка. Продуктовый харнес использует tooling по публичным CLI/API без зависимости от харнеса его разработки.
- Предложение путей: .agents/routes/product.md и tooling.md; существующие каталоги ролей/скиллов сохраняются, глобального переезда нет. На Э3 — список для будущего выноса и проверка зависимостей.
- Предложение агента: browser-исходники в tooling/src/, Node-CLI в tooling/tools/, поставка в tooling/dist/.
- shadcn: исходники выбранных компонентов в tooling/src/ui/primitives/, CLI-конфигурация в tooling/components.json; зависимости в tooling/node_modules/ (вне git).
- Соседний проект обследован только чтением: React 18.2 + MUI 5, второй renderer и сборка esbuild, просмотр React-страниц через localhost.
- В задачу включён обсуждённый file-просмотр HTML и готовой панели без команд; Vite используется автором для разработки и сборки.
- Детали поставки и совместимость версий проверяются пилотом; правила проекта пока не изменены.
