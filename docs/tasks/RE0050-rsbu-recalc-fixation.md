# Корректировки РСБУ v4: пересчёт с фиксацией одной операцией (RE0050)

## Коротко

Концепт «Корректировки РСБУ v4» работает в два шага: «Зафиксировать РСБУ» (окно с двумя
датами, штамп на тайле) → «Пересчитать платежи» (дельты становятся корректировками).
По решениям человека 03.11.2026 фиксация и пересчёт сливаются в одну операцию
«Пересчитать с фиксацией» с периодом фиксации (диапазон дат), отчёт РСБУ получает
помесячную сетку колонок с 01.2025 по 12.2027, а повторные пересчёты с фиксацией
накапливают корректировки, не удаляя прежние. Пользователь — финансист ДИД.

## Решения человека (03.11.2026)

| Вопрос | Решение |
|---|---|
| Кнопки тайла «Процентные платежи» | Первой — «Пересчитать» (была «Пересчитать платежи»); второй — «Пересчитать с фиксацией» (была «Зафиксировать РСБУ»), транспарентная. Строку «Дата фиксации РСБУ» после пересчёта убрать |
| Окно фиксации | Название — «Пересчет с фиксацией»; кнопка «Сохранить» → «Пересчитать»; дата фиксации — диапазон (компонент date range): изменения касаются определённого периода, пересчитывается весь срок, но реально меняются значения только вне зафиксированного периода |
| Сценарий | Отдельная фиксация и последующий пересчёт не нужны: изменения транша → «Пересчитать с фиксацией» → период фиксации + целевая дата корректировки (на неё переносятся суммы дельт) → сразу пересчёт с выявлением дельт и автоматическим созданием корректировок. Обычная кнопка пересчёта — для обычных операций. В отчётах РСБУ на странице финансовых метрик всё остаётся как было |
| Колонки отчётов РСБУ | С января 2025 по декабрь 2027, по одной колонке на месяц; даты произвольные, но каждые три месяца — последний день месяца. При пересчёте процентных платежей пересчитываются все колонки кроме зафиксированного периода |
| Накопление корректировок | Пересчёт с фиксацией на начало 2026 года пересчитает 12 колонок 2025-го → 12 корректировок (в теории меньше — не на каждую дату есть дельта). Повторный пересчёт с фиксацией (например, через полгода, за 18 прошедших месяцев) добавляет новые строки к имеющимся; прежние не пропадают: они переносят свои дельты на свою дату расчёта, у нового пересчёта другие условия и другие дельты — на более позднюю дату. Причина: система пересчитывает процентные платежи за весь срок отчётности, включая уже выплаченные периоды, но сданную отчётность и налоги нельзя менять ретроспективно — корректировки возвращают за прошлые периоды старые значения. Учитывать в таблице корректировок и в таблице отчётов РСБУ |

## Решения человека (05.11.2026)

## Как сейчас (замер 03.11.2026)

- Тайл «Процентные платежи» (`pages/Tranche.html`): кнопки «Зафиксировать РСБУ» и
  «Пересчитать платежи», при фиксации — штамп «Дата фиксации РСБУ: ДД.ММ.ГГГГ».
- Окно «Фиксация РСБУ» (`widgets/modals/RsbuFixationModal/`): дата фиксации + дата
  корректировки, кнопка «Сохранить»; фиксация хранится в сторе и заменяется повторной.
- Стор (`data/fin-metrics-store.js`): `fixRas` → `recalcPayments` → `createAdjustments`;
  отчёт РСБУ — квартальные даты `QUARTER_ENDS` (2024Q1–2026Q4), у каждого ФИ срез 4–6 дат;
  демо-корректировки — 2 строки (31.12.2024, 31.03.2025 → 01.04.2025).

## Решение

### Экраны и виджеты

- `pages/Tranche.html` — тайл «Процентные платежи»: первая кнопка «Пересчитать»
  (`btn--outline btn--s`), вторая «Пересчитать с фиксацией» (`btn--transparent btn--s`,
  id `ip-fix-recalc`); штамп фиксации убран. Обычный клик — `recalcPayments(fiId)`;
  вторая кнопка открывает окно, подтверждение в окне — `recalcPayments(owner, opts)`;
  лоадер на нажатой кнопке, обе выключены на время пересчёта. Условия видимости второй
  кнопки: сделка в «Ввод изменений», есть право (`?hardsMode=view`); привязка к ФИ
  не требуется — без ФИ корректировки создаются по траншу (решение человека 05.11.2026,
  вторая волна).
- `widgets/modals/RsbuFixationModal/` — заголовок «Пересчет с фиксацией»; поле
  «Период фиксации» — ДС InputDateRange (`.inp-range--date`); «Целевая дата корректировки» —
  InputDate, автоподстановка — первое число месяца после «До» периода; поле
  «Комментарий» — InputText multiline, необязательное: текст попадает во все созданные
  после пересчёта строки; кнопка подвала «Пересчитать» (`btn--accent`). Имя виджета и
  папки оставлены (переименование не поручалось).
- `pages/RsbuInterestAdjustments.html` — над таблицей `.dtable-toolbar` с TableFilter:
  «Фильтр» и чип «Применено: N»; первая колонка — чекбоксы (44px, `.th--center`/`.tc--center`,
  чекбокс шапки «Выбрать все»); фильтр — две InputDateRange (исходная и целевая даты),
  InputAmountRange (сумма корректировки), флажок «Только с комментарием»; выбранные строки
  удаляются пачкой с тем же подтверждением, что и одна строка.
- `widgets/modals/RsbuAdjustmentsFilterModal/` — новый локальный виджет окна фильтра
  (`modal--w6.tfm`), по образцу `FinancialMetricsFilterModal`: поля выше, подвал
  «Очистить фильтр» / «Применить», возврат значения `open(value) → Promise<value|null>`.

### Данные

- `data/fin-metrics-store.js`:
  - сетка РСБУ `RAS_DATES` — 36 дат, по колонке на месяц 01.2025–12.2027; в марте, июне,
    сентябре, декабре — последний день месяца, в остальных — фиксированный день
    (16/13/15/14/16/13/15/14 — решение агента); используется отчётом RAS, `rasEventDates`,
    `rawValue`, `reportedValue`, `rasDates`; `eventDates` (кварталы) остаётся для
    МСФО/KPI и фиксаций ЭПС/ВБС;
  - дельта пересчёта ненулевая на каждой дате сетки и растёт по индексу
    (84 210,50 × (i+1) — демо-рыба, решение агента): «12 зафиксированных месяцев →
    12 корректировок»;
  - единая операция `recalcPayments(owner, opts?)`: `opts = { periodFrom, periodTo,
    adjustmentDate, comment, trancheId }` — пересчёт с фиксацией (значения периода по снимку,
    дельты → строки AUTO на целевую дату корректировки); без `opts` — обычный пересчёт; `fixRas`,
    `rasFixation` и хранение фиксации удалены;
  - `ownerKey(fiId, trancheId) → fiId || 'TRANCHE-' + trancheId`: без ФИ владелец
    корректировок — транш; ключ хранится в `financialInstrumentId` (допущение прототипа),
    отчёт РСБУ по реальным ФИ такой ключ не читает;
  - `createAdjustments` пишет комментарий из окна во все созданные строки; пустое поле —
    прежний «Пересчёт процентных платежей»;
  - `removeRasAdjustments(ids)` — удаление пачки одним событием и одним тостом;
  - `checkRasFixation({ fiId, periodFrom, periodTo, adjustmentDate })` — коды REQUIRED ·
    PERIOD_ORDER · NOT_AFTER_FIXATION;
  - демо: прогон 1 — период 01.01.2025–31.03.2025, корректировка 01.04.2025 (3 строки);
    прогон 2 — период 01.01.2025–30.06.2026, корректировка 01.07.2026 (+18 строк, всего
    21 — демо-допущение по примеру человека); `?rasFix=` удалён, `?rasAdj=` принимает
    `none|created|applied|multi|multi-applied|manual|manual-applied|no-fi` (`no-fi` —
    первый транш сделки без ФИ).
- `data/fin-metrics-notify.js` — `rasFixed` удалён; `paymentsRecalculated`: с фиксацией —
  «Создано корректировок РСБУ: N», без — «Процентные платежи транша пересчитаны».

### Компоненты ДС

InputDateRange (период фиксации), InputDate (целевая дата корректировки), InputText
multiline (комментарий), InputAmountRange (сумма в фильтре), Checkbox (выбор строк и

`btn--loading` на время пересчёта), Modal, Alert. Новый локальный виджет —
`RsbuAdjustmentsFilterModal` (окно фильтра).

- Кнопки версий в каталоге спек остаются (ответ человека 05.11.2026); убраны только
  вкладки версий в просмотрщике `Spec.html`.
- Редактирование строк и дублирование не добавляются; №4 отклонён — позже будет нормальное

- Отображение корректировок без ФИ в отчёте РСБУ не моделируется: отчёт строится по ФИ,
  страница корректировок — по траншу.
- Коммит/пуш — только по прямой просьбе человека.

## Критерии приёмки

- На тайле «Процентные платежи» первая кнопка — «Пересчитать», вторая — «Пересчитать с
  фиксацией» (transparent); строки «Дата фиксации РСБУ» нет ни в одном состоянии.
- Окно: заголовок «Пересчет с фиксацией», «Период фиксации» — InputDateRange (От/До),
  «Целевая дата корректировки», «Комментарий» (необязательный), кнопка «Пересчитать»; после
  подтверждения — пересчёт с созданием корректировок, снек «Платежи пересчитаны. Создано
  корректировок РСБУ: N»; комментарий стоит во всех созданных строках.
- Обычная «Пересчитать» — пересчёт без корректировок, снек без строки о корректировках.
- Отчёт РСБУ: 36 колонок 01.2025–12.2027 (март/июнь/сентябрь/декабрь — последние дни
  месяцев) плюс колонки дат корректировок; МСФО и KPI не изменились.
- Повторный пересчёт с фиксацией добавляет строки к имеющимся, прежние остаются со своей
  целевой датой корректировки (демо `rasAdj=multi`: 3 + 18 = 21, целевые даты корректировок 01.04.2025 и 01.07.2026);
  в отчёте РСБУ после пересчёта метрик — отметки на обеих датах корректировок.
- `node .agents/tools/layout-check.mjs` (изменённые страницы) и прогон
  `node .agents/tools/page-run.mjs` по ним — без дефектов;
  `node .agents/tools/lessons-cli gate` — `ВЕРДИКТ: OK`.
- Без ФИ у транша обе кнопки доступны; «Пересчитать с фиксацией» создаёт корректировки по
