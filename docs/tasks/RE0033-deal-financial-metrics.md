# Финансовые метрики сделки: тайл расчёта и страница отчётов (RE0033)

## Коротко

На странице сделки тайл «Финансовые метрики» (`DealMetricsCalculationTile`) пока заглушка.
Нужно наполнить его по макетам (расчёт метрик, пересчёт, фиксация ЭПС/ВБС, переход к отчётам)
и собрать страницу «Финансовые метрики» с вкладками МСФО · РСБУ · KPI · Фиксации ЭПС/ВБС,
фильтром, выгрузкой отчёта и окном «Фиксация ЭПС/ВБС». Сущностей траншей и инструментов пока
нет: собираем визуальную оболочку и закладываем работу виджетов, логику дописываем по ходу.
Читатели: дизайнер и аналитик, позже — разработчик фронтенда.

## Решения человека (20.10.2026)

| Вопрос | Решение |
|---|---|
| Бизнес-логика | при заведении сделки заполняют транши, инструменты и ФИ; когда данных хватает — считают метрики; после расчёта сделку отправляют на утверждение. Для изменений активную сделку переводят во «Ввод изменений», после правок метрики пересчитывают. Внутри — отчётные данные РСБУ, МСФО, KPI и фиксации ЭПС/ВБС |
| Объём | только визуальная оболочка; работу модулей и виджетов закладываем так, чтобы можно было выполнять хоть какие-то задачи; логику и недостающие части дописываем постепенно |
| Где делать | в модуле `apps/postrade/deals-app/` (трек product — правки модуля с подтверждением человека), не концептом |
| Как разложить | одна задача этапами; окно фиксации ЭПС/ВБС — отдельными этапами внутри неё |
| Откуда «результат расчёта» | мок по карточкам ФИ сделки из `FinInstrumentsStore`; «Рассчитать» — имитация с задержкой; ошибки и состояния ЕТС — сценариями панели прототипа |
| Неоднозначности | все открытые вопросы, неоднозначности и несостыковки логики — в «Открытые вопросы» |

## Решение

### Тайл `widgets/tiles/DealMetricsCalculationTile` (пара — та же)

- Состояния по матрице макета: Заблокировано (нет ФИ) · По умолчанию · Ошибка · На просмотр ×
  Не рассчитано · Рассчитано. Сверх матрицы, по пояснениям листа сценария: «Идёт расчёт» (лоадер
  на кнопке, кнопки disabled). «Нужен пересчёт» не будет (ответ 27).
- «Заблокировано» — серая строка «Отсутствуют ФИ для расчета», без полосы-ошибки и без кнопки
  (ответы 1, 23).
- «Ошибка» — полоса «Расчет не выполнен, некорректные данные в ФИ». Само заполнение ФИ тайл не
  меняет: ошибка снимается только успешным расчётом. После прошлого успешного расчёта, если сделку
  изменили и при пересчёте не посчитался ни один ФИ, — снова «Ошибка»; если посчитался хотя бы
  один — частичный расчёт (ответ 24). «Ошибка» после прошлого расчёта — полоса ошибки над видом
  «Рассчитано» с прежней датой расчёта (ответ 42).
- «На просмотр» — и по статусу сделки, и по роли (ответ 3).
- Действия: «Рассчитать» (первый расчёт) / «Пересчет метрик» — одно действие с одной подписью на
  тайле и странице (ответ 7), «Фиксация ЭПС/ВБС» (окно фиксации), «Отчеты →» (страница метрик).
  Строки: «Рассчитано ФИ: N из M. Последний расчет: дата, время» / в просмотре «Последний
  расчет: …». Тексты интерфейса — через «е» (решение агента 13).
- Частичный расчёт: несчитанный ФИ в отчётах не отображается вовсе; какой именно — сейчас
  выясняют методом исключения (ответ 4). Как это показать — вопрос 5 паспорта тайла, варианты — Э9.
- «На просмотр»: не рассчитано — серым «Расчет не выполнен», без кнопок; рассчитано — «Последний
  расчет: …» и «Отчеты →» (матрица тайла).
- Сообщения расчёта — снеки (SnackBar ДС), не тосты; все с листа сообщений верны, это разные
  ошибки (ответ 25). Снек успеха — «Операция выполнена» / «Рассчитаны метрики для ФИ: …»; при
  частичном расчёте — один снек «Операция выполнена частично» / «Рассчитано ФИ: N из M» (ответ 41).
  Снеки на макетах нарисованы пачкой для передачи разработке, на экране они разом не показываются:
  каждый — по своему исходу. Когда показывается «Расчет финансовых метрик выполнен» — вопрос 41.

### Страница `pages/FinancialMetrics.html` (пара `FinancialMetrics`)

- Модульная, собирается `assemble.mjs` → `FinancialMetrics.preview.html`; спека
  `FinancialMetrics.screen.md`; узел на карте экранов (`apps/screen-map/map.yaml`).
- Шапка: крошки «Текущий портфель ДИД / <сделка> / Финансовые метрики» и чип «↶ В сделку» — оба
  (ответ 20); «Последний расчет», кнопки «Фиксация ЭПС/ВБС», «Пересчет метрик», кебаб «Выгрузить
  в XLSX».
- Кебаб стоит выше вкладок и вкладками не управляется: то, что ниже, не влияет на то, что выше.
  Выгружается вся информация по всем вкладкам. С шифрованием или без — по сети, из которой
  открыта страница (ответ 12): Сигма (сеть банка с выходом в интернет) — с шифрованием; Альфа /
  Омега (внутренние) — без шифрования. В продукте сеть определяется по логину, в прототипе её
  переключает сценарий панели, по умолчанию Альфа (ответ 21 — как в расчёте FV).
- Вкладки по порядку МСФО · РСБУ · KPI · Фиксации ЭПС/ВБС (ответы 8, 22), по умолчанию открыта
  первая. Алерта о пересчёте и warning у ФИ нет (ответ 27).
- Пустая вкладка (любая): кнопка «Фильтр» есть, но заблокирована, колонок дат нет, по центру «Нет
  данных» (ответ 28).
- Фильтр — актуальный TableFilter ДС: кнопка «Фильтр» S и один чип «Применено: N»; чиплиста
  параметров и «+99» нет — на макете устаревший вариант с кнопкой XS (ответ 30). У каждой вкладки
  свои индикаторы и свой чип.
- Колонки дат отчётов — все даты, в которые у какого-либо ФИ есть финансовое событие (выдача,
  погашение, начисление процентов, фиксация ЭПС/ВБС и т. п.). Даты общие для всех ФИ, группы ФИ
  прокручиваются вместе; у ФИ без события на дату — пустая ячейка. Видна отчётность по всем ФИ и
  всем датам разом (ответ 10).

## Критерии приёмки

- На `Deal.preview.html` тайл «Финансовые метрики» показывает все состояния матрицы макета, а
  также «Идёт расчёт»; состояния переключаются данными демо-сделок и сценариями панели прототипа.
  Алерта и состояния «Нужен пересчёт» нет.
- «Рассчитать» на сделке с заполненными ФИ переводит тайл в «Рассчитано»; на сделке без ФИ тайл
  заблокирован: серый текст, без полосы-ошибки и без кнопки.
- Действие пересчёта подписано «Пересчет метрик» и на тайле, и на странице; тексты интерфейса —
  через «е».
- Сообщения расчёта и фиксации — снеки ДС, сообщения о запуске и удалении — тосты.
- В отчётах — общие колонки дат событий всех ФИ, группы ФИ прокручиваются вместе, у ФИ без
  события на дату ячейка пустая.

  зависит от сети, переключаемой сценарием панели.
- «Отчёты →» открывает страницу метрик этой сделки, «В сделку» и крошка возвращают на неё.
- Вкладки МСФО, РСБУ, KPI наполнены по ФИ сделки; ФИ без нужного типа отчётности во вкладку не

- Окно выгрузки одинаковое у вариантов с шифрованием и без, кроме выбора сотрудников.
