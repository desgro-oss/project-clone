# task-cost: читатель журналов ZCode (RE0046)

## Коротко

Сессии идут в CLI ZCode, у которого нет читателя журналов в `task-cost.mjs`:
`mark` отказывается («журналы есть, но ни один не менялся после начала окна»),
затраты задач не считаются. Нужен читатель журналов ZCode, чтобы `mark`/`report`
считали токены и время без `--manual`. Попутно: `.zcode/` (данные сессий CLI) —
в `.gitignore`, чтобы не тащить в репозиторий.

## Решения человека (30.10.2026)

| Вопрос | Решение |
|---|---|
| Затраты должны считаться в ZCode | «Нужно чтобы затраты считались, сделай что нужно, читателя там или что» |
| `.zcode/` в gitignore | Добавить, «если это ничему не навредит» — папка с локальными данными сессий CLI, проекту не нужна |

## Как сейчас (замер 30.10.2026)

- ZCode пишет журнал запросов построчно в `~/.zcode/cli/rollout/model-io-<sessionId>.jsonl`,
  субагенты — отдельными файлами `model-io-sess_subagent_<id>.jsonl`; строка —
  один завершённый запрос: `startedAt`/`completedAt`, `request.messages` (весь
  разговор на момент запроса, последнее сообщение — триггер: `role: "user"` —
  человек, `role: "tool"` — ответ инструмента), `response.usage`
  (`inputTokens` без кэша, `cacheReadTokens`, `cacheWriteTokens`,
  `outputTokens`), `response.toolCalls` (имя и аргументы).
- `task-cost.mjs` знает три источника: журнал JSONL `<дом>/.<CLI>/projects/<корень>/`
  (у ZCode такой папки нет), база opencode, общий читатель (форму
  `inputTokens/cacheReadTokens` не узнаёт). `mark RE0045 Э0` — отказ.
- Проект в журнале ZCode узнаётся только по упоминанию корня в тексте строк
  (system-промпт каждой строки содержит рабочую папку), каталога проекта нет.

## Решение

- Новый источник «zcode» в `task-cost.mjs` (`readZcode`, по образцу `readJsonl`):
  каталог `<дом>/.zcode/cli/rollout` (для копии с другой машины — тот же путь
  от `--home`); свежесть по mtime, окно по `startedAt`; счётчики — Вход =
  `inputTokens + cacheWriteTokens`, Кэш = `cacheReadTokens`, Выход =
  `outputTokens`; ретрай одного запроса (одинаковый `requestId`) считается один
  раз; вызовы — `response.toolCalls`; ожидание вопроса — пауза от запроса с
  инструментом из `WAIT_TOOLS` до следующего; упоминание задачи — текст
  человека (триггер-реплика), текст ответа или аргументы инструментов агента —
  вывод инструментов (`role: "tool"`) не в счёт; субагенты (`_subagent_` в
  имени) — в токенах, не во времени. Проект — по упоминанию корня в тексте
  файла (как общий читатель).
- `probe` показывает источник zcode отдельной строкой; селфтесту — кейс с
  поддельным журналом zcode (токены, кэш, пик, время с ожиданием вопроса,
  субагент, чужой проект, вывод инструмента — не упоминание).
- `.gitignore`: секция про локальные данные CLI — `.zcode/`.

## Вне задачи

- Другие источники данных ZCode (sqlite-индексы задач, логи дня) — не нужны,
  rollout достаточно.
- Перенос уже записанных строк `--manual` других задач — нет.
