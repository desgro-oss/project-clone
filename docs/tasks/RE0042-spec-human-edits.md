# Правка спек на разработку человеком и разбор правок агентом (RE0042)

## Коротко

Сейчас каждую формулировку в спецификации на разработку правит агент, и даже мелкая
правка стоит токенов. Дизайнер правит текст сам — в VS Code, прямо в исходнике
`.dev-spec.md`. Потом агент разбирает правки: записывает, что изменилось, спрашивает
«почему» там, где причина неочевидна, и ищет закономерности. Цель — чтобы следующие
спеки сразу писались без лишнего и без прежних пропусков. Страница спеки не меняется.

## Решения человека (28.10.2026)

| Вопрос | Решение |
|---|---|
| Где править | В VS Code, прямо в `.dev-spec.md`. Сначала решили править на странице спеки рядом со снимками, но передумали: слишком большой объём работ (28.10.2026) |
| Глубина разбора | Журнал + «почему» + закономерности; правило в скилл — только с согласия человека |
| Охват | Только спеки на разработку (`.dev-spec.md`). Если правка задела факт из спеки экрана или паспорта виджета, агент предлагает перенести её в источник |

## Как сейчас (замер 28.10.2026)

- Исходник спеки — `apps/postrade/drafts/dev-specs/refs/<Spec>/<Spec>.dev-spec.md`, его
  пишет агент по скиллу `dev-spec`. Генератор `.agents/tools/dev-spec.mjs` собирает генерат
  `data/<Spec>.dev-spec.js` вида `window.DEV_SPECS.push({… md, html})`. В генерате лежат
  выходные md и html, **исходника в нём нет**: сравнить файл на диске с последней версией
  агента не с чем.
- Git для сравнения не годится: коммит — только по просьбе человека, последняя версия
  агента часто не закоммичена.
- Скилл `lessons` разбирает дефекты, которые ловят проверки (сторожа, фикстуры). Для
  правок текста человеком механизма нет: ни журнала, ни закономерностей.

## Решение

### 1. Последняя версия агента — в генерате

Генератор кладёт в генерат исходник целиком (`src`, с front matter). Тогда генерат и есть
последняя версия агента, а разница «файл на диске ↔ `src`» — это правки человека.
Отдельная копия и состояние вне git не нужны: всё переезжает вместе с репозиторием, в том
числе в контур банка. Выгрузка разработчикам не меняется: страница берёт из генерата
только `md` и `html`.

### 2. Причина правки — в самом файле (необязательно)

Рядом с правкой человек может оставить комментарий `<!-- почему: … -->`. Причина,
записанная сразу, избавляет от вопроса агента. Комментарий относится к блоку над ним.
Разбор переносит причину в журнал и удаляет комментарий из исходника; пока он не разобран,
`--check` о нём напоминает. В .md для разработки он не попадает: `exportMd` его вырезает.

### 3. Сжатая разница для агента

`dev-spec.mjs <исходник> --diff` печатает только изменённые блоки (заголовок, абзац,
пункт списка, таблица — только изменённые строки, цитата, код, маркер снимка): путь
заголовков раздела, вид (изменён · добавлен · удалён), «было → стало» по словам, причину
из комментария. Front matter — одной строкой «изменены поля: …». Агент читает эту
выдачу, а не спеку целиком.

### 4. Разбор — команда `/spec-edits <Spec>`

Процедура — раздел в скилле `dev-spec`.

1. Тип каждой правки: убрано лишнее · добавлен пропуск · исправлен факт ·
   переформулировано · переставлено · опечатка.
2. «Почему» спрашивается только у неочевидных правок без причины — одним пакетом
   вопросов с готовыми вариантами ответа.
3. Охват: **общая** правка (как писать любую спеку: «не лишние подробности», «не хватало
   колонок») или **частная** (факт этой спеки). В закономерности идут только общие.
4. Запись в общий журнал `.agents/skills/dev-spec/references/edits-log.md`: дата, спека,
   раздел, было → стало, тип, охват, причина, вывод. Комментарии `<!-- почему: … -->`
   удаляются из исходника.
5. Куда ещё уходит правка:
   - факт предметной области — скилл `business-context` (бизнес-смысл, глоссарий);
   - факт из спеки экрана или паспорта виджета — предложить перенести в источник.
6. Закономерности — `.agents/skills/dev-spec/references/edit-patterns.md`: ключ, счётчик
   общих правок, примеры со ссылками на журнал. Правки и «почему» человек пишет разными
   словами об одном и том же, поэтому агент сравнивает **смысл**, а не слова: сперва ищет
   похожую закономерность по колонке «Как формулируют», при сомнении спрашивает «это то же,
   что …?», новые слова добавляет в ту же строку (дополнение человека, 28.10.2026). Когда общая правка повторилась
   три раза, агент предлагает правило в `SKILL.md` или `references/template.md`. Если
   правило можно проверить механически — предлагает проверку в `--check`. И то и другое —
   только с согласия человека.
7. `--text` пересобирает генерат, и последняя версия агента обновляется сама.

### 5. Напоминание о неразобранных правках

`--check` печатает замечание «есть неразобранные правки человека», если файл расходится
с `src` генерата или в нём остались `<!-- почему: … -->`. Это замечание, а не провал.
`--text` и съёмка принимают файл за версию агента и тем самым стирают правки человека из
`--diff`, поэтому при неразобранных правках они печатают `ВНИМАНИЕ`. Порядок для агента:
перед своей правкой спеки — `--diff`; есть правки человека — сначала `/spec-edits`.

## Критерии приёмки

- `--diff` показывает только изменённые блоки — с путём раздела и причиной; без правок —
  «правок нет».
- `--check` при правках человека печатает замечание, вердикт не меняется.
- `/spec-edits`:
  - пишет запись в общий журнал, с охватом «общая / частная»;
  - спрашивает только о правках без причины;
  - обновляет `edit-patterns.md`;
  - пересобирает генерат, после чего повторный `--diff` пуст.
- Правило в скилл, шаблон или `--check` попадает только после согласия человека.
- Выгрузка разработчикам не изменилась: `md` и `html` генерата до и после правки
  генератора совпадают, в них нет `src` и журнала.
- `node .agents/tools/dev-spec.mjs --selftest` и `--check` на всех спеках — `ВЕРДИКТ: OK`.
- `node .agents/tools/vendor-scan.mjs` — OK.
- `node .agents/tools/lessons-cli.mjs gate` — `ВЕРДИКТ: OK`.

## Риски

- **Генерат растёт** на размер исходника (около 45 КБ на спеку при 1,7–2,7 МБ генерата).
- **Правка ломает разметку спеки** — маркеры снимков, блок `scenario`, выноски. Защита —
  обычный `--check` (СР5) перед `--text`.

## Решения агента — на разбор

| № | Решение | Где записано |
|---|---|---|
| 1 | Последняя версия агента хранится в генерате (`src`), а не отдельной копией в `refs/`, не в каталоге состояния вне git и не в git: генерат уже есть, руками не правится, переезжает вместе с репозиторием; коммит — только по просьбе человека | Решение, п. 1 |
| 2 | Причина правки — необязательный комментарий `<!-- почему: … -->` в исходнике, а не отдельный файл: человек пишет её там же, где правит | Решение, п. 2 |
| 3 | Закономерности ведутся отдельным файлом в скилле `dev-spec`, а не уроками `lessons`: уроки про дефекты со сторожами, правки текста почти всегда без механической проверки | Решение, п. 4 |
| 4 | Напоминание о неразобранных правках — замечание в `--check` генератора, а не новый шаг гейта (память «не усложнять проверки») | Решение, п. 5 |
| 5 | Комментарии человека читаются по смыслу, а не по подписи: кроме причин в них бывают просьбы (спека, снимки, генератор, макет); разбор выполняет их сразу (замечание человека 28.10.2026). Инструмент по-прежнему узнаёт только `<!-- почему: -->`, остальные комментарии агент удаляет сам | `SKILL.md`, «Правки человека», шаг 2 |
| 6 | Снимок `page-filled` убран из `snaps`, узел схемы «Страница платежей» переведён на `page-empty`: человек убрал маркер снимка из текста, а на него ссылался узел | `edits-log.md`, след. правок |
