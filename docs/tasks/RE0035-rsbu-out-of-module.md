# Корректировки РСБУ — убрать из модуля и витрины (RE0035)

## Коротко

Страница, тайл и окно корректировок начисленных процентов РСБУ попали в модуль `deals-app`
ручным переносом из концепта в октябре, а дизайн в концепте `tranche-page-v03` (RE0034) ещё не
утверждён. Пока дизайн не утверждён, корректировки живут только в концептах; в модуль они
переедут, когда дизайн будет утверждён. Убираем их из модуля, из витрины локальных компонентов,
из карты экранов и из сценариев панели; спеку на разработку «Корректировки РСБУ» переводим на
концепт v3. Отчёт РСБУ на странице «Финансовые метрики» остаётся: он про отчёт, а не про
корректировки.

## Решения человека (23.10.2026)

| Вопрос | Решение |
|---|---|
| Что убрать | Корректировки РСБУ — из проектов (модулей) и из локальных компонентов. Только в концептах |
| Когда вернутся | Когда будет утверждён дизайн |
| Спека на разработку «Корректировки РСБУ» (`drafts/dev-specs`) | Перевести на концепт `tranche-page-v03` и переснять |

## Решение

- Модуль и витрина — как в таблицах выше. Готовой процедуры «обратного /promote» нет: удаляем
  файлами и чиним по проверкам гейта.
- Спека на разработку: `module: postrade/drafts/tranche-page-v03`, `sources` — файлы v3; тексты
  тайла, страницы и окна — по коду v3 и решениям RE0034 («Дельта на дату», «Расхождение после
  переноса», правила дат «с» и «на», отметка «Расхождение с ДД.ММ.ГГГГ»). Фиксация расчёта на
  странице метрик в эту спеку не входит. Пересъёмка: генератор поднимает сервер съёмки, адрес
  открывает в своём браузере человек (агент браузер не запускает).
- В handoff RE0034 — строка: корректировок в модуле больше нет; перенос v3 — вручную (команда
  `/promote` не переносит концепт в модуль, где уже лежат файлы); правка «недоступные ссылки
  тайла выключены разметкой, а не только стилем» переедет вместе с переносом.

## Вне задачи

- Отчёт РСБУ, фиксация расчёта и дельты на странице метрик (концепт v3, RE0034) — кроме Э4: там правятся только старт и сценарий панели, не дизайн.
- Модули `core`, `ib`, `pretrade`: ссылок на корректировки в них нет.
- Перенос концепта v3 в модуль — после утверждения дизайна.

### Э4 · сценарий концепта v3 проходится руками (запись 23.10.2026, реализация — по слову человека)

**Просьба человека (23.10.2026).** Когда со страницы сделки переходишь в отчёты РСБУ, индикатор уже
зафиксирован, хотя по сценарию его должен зафиксировать сам человек. Весь сценарий человек
проходит сам: зафиксировать → пересчитать → пойти в транш и открыть корректировку → внести её →
проверить, что она отразилась в отчётах РСБУ. Нужно изменить весь сценарий.

**Что выяснено по коду (23.10.2026, в браузере не проверено).**

| Наблюдение | Где |
|---|---|
| Фиксация и переносы, сделанные кликами, пишутся в хранилище браузера (`PostApi.finMetrics`, ключ `ibp.post.v03.fin-metrics`) и переживают закрытие вкладки. Состояние из адреса (`rasFix`, `rasMoves`) не пишется и действует только на открытой с ним странице. Поэтому следующий прогон сценария начинается с того, чем кончился прошлый: ссылка «Отчеты →» на странице сделки адреса без параметров не несёт и открывает сохранённое состояние. Это вероятная причина того, что индикатор уже зафиксирован | `data/fin-metrics-store.js` (`commit`, `use`, `applyRasUrl`), `pages/Deal.html` стр. ~790 |
| Сброс есть только в табе System панели («Сбросить») и только на странице «Финансовые метрики»; на странице сделки, где сценарий начинается, его нет | `pages/FinancialMetrics.html` (`PP_SYSTEM`) |
| Сценарий `main` панели не ведёт руками: шаг «Финансовые метрики» открывается с `rasFix=none`, шаг «Корректировки» — с готовым состоянием `rasFix=recalc&rasMoves=partial`, шаг «Транш» — вообще без состояния. Человек видит заготовку, а не результат своих действий | `proto-panel/flows.yaml`, потоки `main`, `rsbu-tile`, `rsbu-page` |
| Сценарий `ras-e2e` проходит те же шаги кликами за человека (`do:`) | `proto-panel/flows.yaml`, поток `ras-e2e` |
| Тайл транша по числу переносов в хранилище сам переходит в «Внесено корректировок: N» и показывает расхождение — для ручного прохождения это нужное поведение | `pages/Tranche.html` (`rsbuState`) |

**Что сделать.**

1. **Чистый старт.** Первая страница сценария (страница сделки 1028) сбрасывает сохранённые
   фиксацию и переносы сделки — параметром адреса (предложение: `?rasReset=1`; хранилище при
   открытии сделки обнуляет `ras`, записывает и убирает параметр из адреса, чтобы обновление
   страницы не стирало ход прохождения). Альтернатива или дополнение — кнопка «Сбросить» в табе
   System на всех страницах концепта, а не только на метриках.
2. **`main` — руками.** Шаги — точки входа на страницы без готовых состояний: сделка (со сбросом) →
   метрики, вкладка РСБУ (`do` — только открыть вкладку) → «Зафиксировать расчёт» → «Пересчет метрик» →

   возврат на метрики. В заметке каждого шага — что человек делает сам и что должен увидеть
   (чип фиксации, дерево «Зафиксировано / После пересчёта / Дельта», подсветка в ячейках «с» и
   «на», уменьшение дельты, отметка «Расхождение с …» в тайле и на странице). Действия человека в

3. **Готовые состояния — отдельно.** Потоки с состояниями из адреса (`rsbu-tile`, `rsbu-page`,

- Страница `Tranche.preview.html` осиротеет, если её оставить: её не видят ни сборщик, ни гейт, а `Deal.preview.html` ведёт именно на неё.
