# banker-app — AI Pitcher (раздел ib)

Модуль раздела «AI Pitcher» в группе «Origination»: инструмент банкира для
подготовки отчётов по компании, группе, бенефициару или рынку — к встрече с
клиентом или для поиска сделок. Пользователь пишет запрос в чате, AI Pitcher
отвечает на вопросы с источниками или готовит материал с продуктовыми идеями.

Модуль — трек `product` (запись `app.json`, на хабе — «AI Pitcher»): агент
правит его только с подтверждением человека. Перенесён из концепта
`apps/ib/drafts/ai-bankster-prototype-mvp/` командой `/promote` 20.10.2026;
версии концепта v01 и v02 остались в `drafts/`.

**Источники:**
- ТЗ (БТ-1 … БТ-11 + единый пользовательский путь и поведение при отказах);
- черновой прототип модуля;
- макеты главной страницы, бокового меню и экрана «Новый отчёт».

## Экраны

Каждый экран — самодостаточный `.html` в `pages/`, открывается двойным кликом
или с хаба проектов (корневой `index.html` → «Проекты» → «AI Pitcher»). Рядом —
полная спецификация `<Имя>.screen.md` для разработки.

| Файл | Экран | Где в навигации | Пара во фронтенде | Закрывает |
|---|---|---|---|---|
| `index.html` | Главная страница IBP | пункт «Главная» | `core/host-app/pages/HomePage` | вход: плитка «AI Pitcher» ведёт в «Новый отчёт» |
| `RequestThread.html` | Новый отчёт — нить запроса | пункт «AI Pitcher» | нет — `new` | БТ-3 диалог · БТ-4.1 история слева · БТ-6 уточнения · БТ-7 подготовка |

«Новый отчёт» открывается пустой нитью — точкой входа в раздел (БТ-4.2, шаг 1).
Слева «Недавние запросы»: последние 10 запросов с состоянием, поиском по чатам и
кебаб-меню; над ними кнопка «Новый отчёт». Состояние экрана задаётся адресом:
`RequestThread.html` — пустая нить, `?id=N` — запрос из истории, `?run=1` —
сразу ход подготовки.

**Запуск подготовки отчёта** — фразой в поле ввода «[Сделай] отчёт по
компании | группе | бенефициару | рынку <название>»: «Отчет по группе
«Черкизово», фокус — M&A, интересуют покупки в регионах». Любое другое
сообщение — вопрос, ответ приходит в диалоге с источниками. Подробно —
`pages/RequestThread.screen.md`, разделы 6 и 13.

Сценарий для показа: главная → плитка «AI Pitcher» → пустая нить → «Показать
пример запроса» → «Отправить» → в нити идёт подготовка → клик по индикатору
завершает её → «Скачать — MD» на карточке материала. Строки истории слева
открывают готовые запросы и ответы в диалоге.

## Данные

Демо-данные — `data/report-requests.js` с JSDoc-typedef (`ReportRequestRsDto`,
`RequestDialogRsDto`), имена придуманы в стиле API (`invented`) — заменить,
когда придёт DTO. Подключается до скрипта экрана. Нить готового запроса и
версии материала пока заданы в скрипте экрана (`RequestThread.screen.md`,
раздел 16, №33).

## Сборка

- ДС подключает загрузчик проекта: `../../../ds-config.js` первым в `<head>` и
  `../../../ds-body.js` вместо тега `ds.js`; адрес ДС — строка `DS_PATH` в
  `apps/ds-config.js`. Строка пользователя в меню ведёт на хаб `../../../../index.html`.
- Компоненты, классы и токены — только из ДС; собственный `<style>` экрана —
  раскладка на токенах. Файлы ДС не изменялись.
- Меню и плитки собраны статической разметкой по каталогу
  `design-system/patterns/HomeRoles/ibp-home.js`: роли и раздела в каталоге
  нет (`HomePage.screen.md`, раздел 13, №12).
- Два блока без компонента в ДС — панель «Недавние запросы» и композер —
  собраны на токенах и описаны в `RequestThread.screen.md` (разделы 3 и 13);
  кандидаты в виджеты модуля или компоненты ДС. Виджетов у модуля пока нет.
- Найденные при сборке дефекты ДС — `RequestThread.screen.md`, раздел 15.
- Пасхалка «хот кореянки» и картинка `refs/girl.jpg` — только прототип, в
  продукт не переносится.
- Проверка страницы: `node .agents/tools/layout-check.mjs apps/ib/banker-app/pages/<Имя>.html`;
  заход закрывается `node .agents/tools/lessons-cli.mjs gate`.
