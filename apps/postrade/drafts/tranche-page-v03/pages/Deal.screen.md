# Page: Deal — Страница сделки

## 1. Назначение (Purpose)

> Концепт v3 (задача RE0034): страница выглядит как страница сделки модуля `postrade/deals-app` (копия от 22.10.2026), но **без окон правки, поповера «Связанные сделки», страницы ФИ и других переходов, которых в концепте нет**. Живые переходы — только сценария RE0034 (раздел 6). До `/promote` модуль не меняется.

Точка входа сценария: сотрудник operations открывает сделку в статусе «Ввод изменений», смотрит её данные, переходит в транш (корректировки процентов РСБУ) или на страницу финансовых метрик (отчёты, пересчёт, фиксация расчёта).

**Роль пользователя:** сотрудник operations (финансист).
**Права:** правка расчёта метрик — по статусу сделки (`DealsStore.isEditable`) и сценарию панели `?fmMode=view`. Остальные тайлы в концепте только для просмотра.

## 2. Адрес и навигация (Route)

- **Адрес в продукте:** не решено — в продукте это страница сделки модуля.
- **Адрес прототипа:** `Deal.preview.html?id=<номер сделки>`; нет `id` или сделки с таким номером нет — открывается сделка **1028** («Ввод изменений»: у неё транш, ФИ с РСБУ, расчёт метрик, полное описание и сведения о проекте). У «Активной» 1024 тайл метрик только для просмотра — пересчёта нет.
- **Параметры сценариев панели:** `fmMode=view` — роль без права на расчёт и фиксацию (тайл «Финансовые метрики» только для просмотра); `rasReset=1` — чистый старт ручного сценария (RE0035, Э4): страница сбрасывает сохранённые фиксацию расчёта РСБУ и переносы этой сделки, записывает пустое состояние в хранилище и снимает параметр из адреса, чтобы обновление страницы не стирало ход прохождения. Расчёт метрик и фиксации ЭПС/ВБС не трогаются.
- **Пункт бокового меню** в состоянии `nav__item--selected`: «Текущий портфель»; ссылка пункта — `#`; строка пользователя ведёт на хаб проектов.

## 6. Поведение (Behavior)

| Триггер | Результат |
|---|---|
| Клик по названию транша в дереве продуктов | переход на страницу транша `Tranche.preview.html?id=<сделка>&tr=<id транша>` (событие тайла `ptreeaction`, `OPEN`) |
| Клик по названию транша в карточке ФИ | тот же переход на `Tranche.preview.html` (событие тайла `fiaction`, `OPEN_NODE`); у стрелки «→» карточки цели нет — она скрыта |
| Клик «Отчеты →» на тайле расчёта | переход на `FinancialMetrics.preview.html?id=<сделка>` (событие `fmcalcaction`, `REPORTS`) |
| Клик «Рассчитать» / «Пересчет метрик» | `FinMetricsStore.calculate()`, лоадер на кнопке, по итогу — снек (`FinMetricsNotify.calculation`). Пока у зафиксированного индикатора РСБУ расхождение не устранено (`rasUnallocated()` не пуст), сначала окно «Пересчитать метрики?» (`RsbuRecalcWarningModal`): «Отменить» — пересчёта нет, «Пересчитать» — пересчёт и снятие фиксации (RE0034, Э5). Алерта на тайле нет |
| Клик «Фиксация ЭПС/ВБС» | окно `PostFixationModal` (событие `fmcalcaction`, `FIXATION`) |
| Стрелка у заголовка «Общая информация» | секция сворачивается и разворачивается |
| Переключение вкладок | показывается панель выбранной вкладки |
| Статус сделки не допускает правку или `?fmMode=view` | тайл расчёта в просмотре: «Рассчитать», «Пересчет метрик», «Фиксация ЭПС/ВБС» скрыты и выключены |
| Кнопки правки, «Развернуть», «Документы ЭКД», «→» у карточки ФИ, ссылка «Связанные сделки» | **убраны**: окон, поповера и страницы ФИ в концепте нет. Страница прячет триггеры, у которых нет цели (`hideDeadActions`) |
| Кнопки «Заведение сделки» | действие не записывается в сделку (окон перехода нет) |
| Клики по крошкам и пунктам меню | `#` |
