# Финансовые метрики

## Описание (Purpose)

Тайл страницы сделки: запускает расчёт финансовых метрик (МСФО, РСБУ, KPI) по финансовым
инструментам (ФИ) сделки и показывает итог последнего расчёта — сколько ФИ рассчитано и когда.
Отсюда же открываются окно «Фиксация ЭПС/ВБС» и страница «Финансовые метрики» с отчетами.

ЭПС — эффективная процентная ставка, ВБС — валовая балансовая стоимость (плашка макета).

Вид тайла задают три вещи:

- **есть ли у сделки ФИ.** Нет — «Заблокировано»: считать нечего, кнопок нет;
- **был ли успешный расчёт.** Не было — «Рассчитать»; был — итог «Рассчитано ФИ: N из M.
  Последний расчет: …», «Пересчет метрик», «Фиксация ЭПС/ВБС», «Отчеты →». Рассчитана часть ФИ —
  тот же вид с N меньше M; несчитанный ФИ в отчетах не отображается (ответ человека 20.10.2026);
- **чем кончилась последняя попытка.** Не рассчитался ни один ФИ — «Ошибка»: полоса «Расчет не
  выполнен, некорректные данные в ФИ» над видом; прежний расчёт и его дата остаются. Ошибка
  снимается только успешным расчётом, само заполнение ФИ тайл не меняет (ответы 24, 42).

«Рассчитать» (первый расчёт) и «Пересчет метрик» — одно действие (ответ 7). Пока идёт расчёт,
на нажатой кнопке лоадер, все кнопки тайла и «Отчеты →» заблокированы. Исход расчёта
сообщает снек.

Когда ФИ «готов к расчёту», решает стор метрик: в прототипе — если к нему прикреплён хоть один
узел дерева сделки (допущение агента 21.10.2026, вопрос 4).

Место на странице и ширина в колонках задаются экраном
(`apps/postrade/deals-app/pages/Deal.html`), не компонентом.

### Свои состояния

Матрица макета «Tile-Deal-Metrics-Calculation» плюс «Идёт расчёт» из пояснений листа сценария.
Свои оси — атрибуты на корне тайла, есть атрибут — да; ставит их скрипт тайла по
`FinMetricsStore.state()`:

| Атрибут | Когда |
|---|---|
| `data-fm-locked` | у сделки нет ФИ (`code: LOCKED`) |
| `data-fm-error` | последняя попытка расчёта не посчитала ни одного ФИ (`code: ERROR`) |
| `data-fm-calculated` | есть успешный расчёт (`calculated`) |

| Состояние | Когда | Вид |
|---|---|---|
| Заблокировано | `data-fm-locked` | серая строка «Отсутствуют ФИ для расчета», без полосы и без кнопок — и в правке, и в просмотре (ответы 1, 23). Уходит, как только у сделки появляется ФИ |
| По умолчанию, не рассчитано | ФИ есть, расчёта не было | «Рассчитать» (`data-state="empty"`) |
| Ошибка, не рассчитано | `data-fm-error`, без `data-fm-calculated` | полоса «Расчет не выполнен, некорректные данные в ФИ» + «Рассчитать» |
| Рассчитано | `data-fm-calculated` | «Рассчитано ФИ: N из M. Последний расчет: ДД.ММ.ГГГГ, ЧЧ:ММ»; «Пересчет метрик», «Фиксация ЭПС/ВБС»; справа «Отчеты →» |
| Рассчитано частично | `data-fm-calculated`, N < M | то же, `data-state="partial"` |
| Ошибка над расчётом | `data-fm-error` и `data-fm-calculated` | полоса ошибки над видом «Рассчитано» с прежней датой (ответ 42) |
| Идёт расчёт | `data-state="updating"` | лоадер на нажатой кнопке расчёта, всё остальное заблокировано (решение агента 9 задачи RE0033) |
| На просмотр, не рассчитано | `view`, без `data-fm-calculated` и `data-fm-locked` | серая строка «Расчет не выполнен», без кнопок и без полосы |
| На просмотр, рассчитано | `view`, `data-fm-calculated` | «Последний расчет: …» и «Отчеты →», без кнопок; полосы ошибки нет и при `data-fm-error` |

«Нужен пересчёт» не будет (ответ 27).

## Обязательность заполнения (Required)

Не применимо: тайл ничего не заполняет — он запускает расчёт. Признак «метрики рассчитаны» для
степпера сделки («Расчет метрик») — `FinMetricsStore.state().calculated`; связь со степпером
пока не сделана (RE0033).

## Переполнение (Overflow)

| Случай | Правило |
|---|---|
| Длинный текст в поле | текстов из данных нет — только числа и дата; строка итога переносится по словам |
| Много строк или записей | не применимо: одна строка итога |
| Узкая ширина | строка итога переносится; кнопки и «Отчеты →» переносятся в следующий ряд, «Отчеты →» прижата вправо. Своих брейкпоинтов нет |
| Полная ширина | тайл на 12 колонках (`colw-12`): строка в одну линию, «Отчеты →» у правого края |

## Поведение (Behavior)

| Триггер | Результат |
|---|---|
| «Рассчитать» / «Пересчет метрик» | `FinMetricsStore.calculate()`: «Идёт расчёт» (в прототипе 1,5 с), затем вид по исходу и один снек |
| Исход OK — посчитаны все ФИ | снек success «Операция выполнена» / «Рассчитаны метрики для ФИ: <имена через запятую>»; вид «Рассчитано», полоса ошибки снята |
| Исход PARTIAL — посчитана часть ФИ | снек error «Операция выполнена частично» / «Рассчитано ФИ: N из M»; вид «Рассчитано частично», полоса снята |
| Исход FAILED — не посчитан ни один ФИ | снек error «Операция не выполнена» / «Не рассчитаны метрики для ФИ: <имена>»; полоса ошибки, прежний расчёт и дата остаются |
| «Пересчет метрик» при неустранённом расхождении РСБУ | если страница передала `opts.confirm` — сначала окно «Пересчитать метрики?» (`RsbuRecalcWarningModal`); подтвердили — расчёт, фиксация расчёта РСБУ снимается; отменили — ничего не меняется. Без `confirm` расчёт идёт сразу (RE0034, Э5) |
| У сделки появился или удалён ФИ | тайл перерисовывается по стору ФИ: «Заблокировано» уходит или наступает, M меняется |
| Сменился статус сделки | страница меняет `data-mode`, вид меняет CSS без перерисовки |

Сообщения расчёта — снеки ДС (SnackBar), не тосты; на макетах снеки нарисованы пачкой для
разработки, на экране — один по своему исходу (ответы 25, 41). Сценарий панели прототипа
`?fmCalc=ok|partial|fail` подменяет исход расчёта.

### Скрипт тайла

`DealMetricsCalculationTile.js`, глобал `PostTileMetricsCalc`; подключается после сторов и
после `FinInstrumentsTile.js`:

| Функция | Что делает |
|---|---|
| `viewOf(state)` | из `FinMetricsStore.state()` — атрибуты корня (`state`, `locked`, `error`, `calculated`, `busy`) и тексты (`done`, `total`, `at` — «ДД.ММ.ГГГГ, ЧЧ:ММ» по местному времени) |
| `render(tile, state)` | ставит атрибуты и тексты; во время расчёта — лоадер на кнопке расчёта, `disabled` у всех кнопок, и у «Отчеты →» |
| `bind(tile, store, opts?)` | связывает тайл со стором метрик (перерисовка на `change`) и стором ФИ (на `use` и `commit`); «Рассчитать» и «Пересчет метрик» — `store.calculate()` и снек по исходу. `opts.confirm(unallocated) → Promise<boolean>` — необязательное подтверждение перед пересчётом: зовётся, пока `store.rasUnallocated()` вернул неустранённое расхождение РСБУ (`{ fiId, date, amount, currencyCode }`); `false` — пересчёта нет (RE0034, Э5). Возвращает функцию отвязки |

Клики по `[data-fm-act]` делегированы на документ: `CALCULATE` выполняет связанный тайл,
`FIXATION` и `REPORTS` уходят событием `fmcalcaction` с корня тайла, `detail = { action }`.

На странице сделки `fillMetricsCalc` ждёт загрузки сторов, зовёт `FinMetricsStore.use(<id
сделки>)` и `PostTileMetricsCalc.bind`; режим ставят `applyRoleMode` (`?fmMode=view`) и
`applyMode` (статус сделки).

## Открытые вопросы (Open questions)

Решение человека 29.09.2026: вопросы не закрываются догадкой и не удаляются, пока человек
не разберёт каждый; ответ записывается у вопроса с датой. Наполнение тайла по макетам — задача
RE0033 (`docs/tasks/RE0033-deal-financial-metrics.md`); вопросы 4–14 перенесены из неё.

1. Состав полей, порядок и источники значений — от владельца продукта.
2. Минимальная высота тайла — закрыт: 200px, задаёт страница сделки (решение человека 21.09.2026).
3. Действия шапки и права на них — от владельца продукта.
4. **Каких данных хватает для расчёта** — дело не только в полях ФИ, а в инструментах,
   прикреплённых к ФИ: ФИ строится именно на них. Что значит «ФИ заполнен» и «некорректные
   данные в ФИ» — точнее пока сказать нельзя, человек вернётся с ответом (20.10.2026; RE0033,
   вопрос 2). Пока — допущение прототипа.
5. **Как показать, какой ФИ не посчитался** — при частичном расчёте («Рассчитано ФИ: 2 из 3»)
   несчитанный ФИ в отчётах не отображается вовсе, и какой именно — выясняют методом исключения
   (20.10.2026; RE0033, вопрос 4). Варианты решения агента (21.10.2026, Э9) — выбирает человек,
   в прототипе не сделано. Исходное: список несчитанных ФИ сейчас известен только в ответе
   расчёта (`failed` у `FinMetricsStore.calculate()`); при частичном расчёте его не показывает
   даже снек («Рассчитано ФИ: N из M» без имён), и ни тайл, ни страница его не сохраняют. В
   сохранённом состоянии (`DealMetricsCalculationRsDto`) остаются только `calculatedFiIds` —
   отсюда «методом исключения». Причины по ФИ на листе «Сообщения по ФИ» уже есть («отсутствуют плановые
   платежи», «не указаны даты ФИ»), значит бэк их знает.
   - **А. Строка под «Рассчитано ФИ: N из M»** — «Не рассчитаны: 1-ПУТ: Репо-4474 и ещё 2».
     Просто и сразу видно; тайл становится выше, при многих ФИ строка обрезается.
   - **Б. «Не рассчитаны: N» — Link, по клику Popover со списком ФИ и причиной у каждого.**
     Тайл не растёт, причина рядом; нужен новый виджет-поповер и поле причины в ответе бэка.
     *Рекомендация агента.*
   - **В. Пометка на карточке ФИ** (тайл «Финансовые инструменты») — бейдж «Метрики не
     рассчитаны» прямо на ФИ, который надо чинить. Самое наглядное, но связывает два тайла
     через стор и тянет правку чужого виджета.
   - **Г. Строка ФИ с пометкой «Не рассчитан» в отчётах.** Противоречит ответу 4 («в отчётах
     не отображается вовсе»), поэтому только если человек его пересмотрит.
   Список несчитанных ФИ стор получает и сейчас вычитанием (карточки ФИ минус `calculatedFiIds`),
   поэтому А и В обходятся без новых данных. Для Б нужна причина по ФИ — состояние дополняется
   полем `notCalculatedFis: [{ fiId, reasonCode }]`.
6. **Какие изменения сделки требуют пересчёта метрик** — точно любые изменения, влияющие на
   плановые платежи по ФИ, но не только они; человек уточнит (20.10.2026; RE0033, вопрос 6).
   Состояния «Нужен пересчёт» и алерта о пересчёте не будет (ответ человека 21.10.2026; RE0033,
   вопрос 27): вопрос нужен, чтобы понять, когда сделке требуется «Пересчет метрик».
7. **Связь с тайлом «Финансовые метрики сделки»** (`DealFinancialMetricsTile`: ВБС, ОСЗ,
   резерв) — его значения результат этого расчёта? Обновляются ли после пересчёта? Названия
   двух тайлов похожи — не решено (20.10.2026; RE0033, вопрос 18).
8. **Права** — кто считает и пересчитывает метрики, фиксирует ЭПС/ВБС, удаляет фиксацию,
   выгружает отчёт — не решено (20.10.2026; RE0033, вопрос 19). Режим просмотра зависит и от
   статуса сделки, и от роли (ответ человека 20.10.2026).
9. **Вид «Заблокировано»** — закрыт: серый текст «Отсутствуют ФИ для расчета» без полосы-ошибки
   и без кнопки (ответы человека 20.10.2026 и 21.10.2026; RE0033, вопросы 1, 23).
10. **Когда снимается ошибка «Расчет не выполнен, некорректные данные в ФИ»** — закрыт: только
    после успешного расчёта, само заполнение ФИ тайл не меняет. Если успешный расчёт был, потом
    сделку изменили и при пересчёте не рассчитался ни один ФИ — снова ошибка; если рассчитался
    хотя бы один — частичный расчёт (ответ человека 21.10.2026; RE0033, вопрос 24).
11. **Какие сообщения у расчёта** — красные и зелёные — снеки (SnackBar ДС), не тосты; все с листа
    сообщений верны, это разные ошибки; снек успеха — «Операция выполнена» / «Рассчитаны метрики
    для ФИ: …» (ответ человека 21.10.2026; RE0033, вопрос 25). При частичном расчёте — один снек
    «Операция выполнена частично» / «Рассчитано ФИ: N из M»; на макетах снеки нарисованы пачкой
    для передачи разработке, на экране разом не показываются (ответ человека 21.10.2026; RE0033,
    вопрос 41). Не решено: когда показывать «Расчет финансовых метрик выполнен» (21.10.2026).
12. **Запускает ли расчёт метрик фиксацию ЭПС/ВБС** — после расчёта на кадре тост «Расчет
    фиксации ЭПС/ВБС не выполнен» — не решено (20.10.2026; RE0033, вопрос 26).
13. **Вид «Нужен пересчёт»** — закрыт: состояния, алерта и warning-иконок у ФИ не будет, в
    референс попал неактуальный макет (ответ человека 21.10.2026; RE0033, вопрос 27).
14. **Что видно в «Ошибке» после прошлого успешного расчёта** — закрыт: полоса ошибки над видом
    «Рассчитано» с прежней датой расчёта (ответ человека 21.10.2026; RE0033, вопрос 42).
15. **«Отчеты →» — ссылка или кнопка.** На макете «Tile-Deal-Metrics-Calculation» это обводная
    кнопка с иконкой документа слева и стрелкой справа; в тайле — Link ДС с иконкой стрелки
    справа (решение при постановке этапа Э3, 21.10.2026). Снят: Link при постановке был ошибкой
    ведущего агента, тайл сделан по макету — обводная кнопка S с иконками `file` и `arrow-right`
    (21.10.2026).
16. **Полоса ошибки в просмотре.** Матрица макета не показывает «Ошибку» в режиме просмотра;
    в тайле полоса в просмотре не показывается, видна только прежняя дата расчёта — допущение
    агента (21.10.2026), не решено.
17. **Время «Последний расчет»** показывается по местному времени. В демо-данных время записано
    в UTC (`…T16:45:00.000Z`), поэтому в часовом поясе Москвы тайл показывал 19:45, а макет —
    16:45. Демо-данные поправлены: время записано с поясом Москвы (`…T16:45:00+03:00`). Открыто
    для разработки: в каком виде бэкенд отдаёт время расчёта и показывать ли его в местном
    поясе пользователя — не решено (21.10.2026).
