# Модальное окно внесения корректировки

## Описание (Purpose)

Артефакт тайла «Корректировки процентов РСБУ». Не компонент: сам по себе не существует и в плоском
списке кита его нет — он принадлежит своему тайлу и живёт под-пунктом его навигации. Заголовок окна —
«Новая корректировка» при внесении и «Редактирование корректировки» при правке, форма одна.

Корректировка — перенос (RE0034): указанная сумма, плюс или минус, переносится с «Исходной даты» на «Целевую дату» —
это меняет начисление на целевую дату, и дельта на всех датах не раньше неё уменьшается сразу, до пересчёта
(чем раньше целевая дата, тем сильнее; модель условная, расчёта процентов в прототипе нет — решение агента 24 задачи).
Целевая дата раньше исходной (может быть раньше даты фиксации расчёта) и
совпадает с датой события индикатора «Начисленные проценты за период». Если у индикатора есть дельта
(расчёт зафиксирован и пересчитан после позднего платежа), под датами показана её дельта на исходную
дату с учётом уже внесённых переносов, и сумма не может её превышать; под суммой — прогноз «Расхождение после
переноса» (дельта на первой дате расхождения, если внести такой перенос). Данные влияют только на отчёт РСБУ.

Транш и таблицу окно не знает: параметры списка берёт у страницы, проверенную запись отдаёт ей же
(`PostModalRsbuAdjustment.bind(scrim, { options, save })`, `RsbuAdjustmentModal.js`). Страница добавляет
или правит строку и показывает тост.

## Раскладка (Layout)

```
Modal w4 (заголовок «Новая корректировка» / «Редактирование корректировки», IconButton L «Закрыть»)
├── modal__alert — Alert error (скрыт, пока ошибки нет)
├── тело — форма в одну колонку
│   ├── ряд из двух колонок: «Исходная дата» (InputDate) · «Целевая дата» (InputDate)
│   ├── «Дельта на дату» — ReadOnlyField, постфикс — код валюты (скрыто, пока нет исходной даты или дельты)
│   ├── «Сумма корректировки» — InputAmount, постфикс — код валюты
│   └── «Комментарий» — InputText multiline
└── подвал: «Отменить» (transparent) · «Добавить» / «Сохранить» (accent)
```

Ширина — `modal--w4`. Раскладку формы (колонка и ряд из двух дат на токенах отступов) задаёт
`RsbuAdjustmentModal.css`, остальное — Modal.

## Поля (Fields)

| Поле | Чем собрано | Источник значений | Обязательное |
|---|---|---|---|
| Исходная дата | InputDate, ручной ввод или календарь | дата события индикатора `ДД.ММ.ГГГГ`; проверяется по `eventDates`; при дельте на эту дату она должна быть (`remaining(iso)` не `null`) | да |
| Дельта на дату | ReadOnlyField, постфикс — код валюты | дельта на исходную дату с учётом уже внесённых переносов (`remaining(iso)` страницы, правимый перенос не учитывается); показывается, когда выбрана исходная дата и дельта есть | нет (только чтение) |
| Целевая дата | InputDate, ручной ввод | дата события индикатора `ДД.ММ.ГГГГ`, вводится руками; проверяется по `eventDates` | да |
| Сумма корректировки | InputAmount, постфикс — код валюты | сумма в валюте инструмента, со знаком «-»; не больше дельты на исходную дату по модулю | да |
| Расхождение после переноса | ReadOnlyField, постфикс — код валюты | прогноз `forecast(end, amt)` страницы → `{ date, amount }`: дельта на первой дате расхождения, если внести перенос с этими датой «на» и суммой; подпись «Расхождение с ДД.ММ.ГГГГ после переноса»; показывается, когда введены дата «на» и сумма ≠ 0 и прогноз есть; пересчитывается при вводе | нет (только чтение) |
| Комментарий | InputText multiline | свободный текст | нет |

Поле «Исходная дата» только для выбора; набранный руками текст принимается, если совпал с датой списка,
иначе откат к выбранной. Сумма форматируется при вводе: разряды неразрывным пробелом, запятая, не более двух знаков.

## Обязательность заполнения (Required)

- Окно обязательно к заполнению целиком: нет.
- Обязательные поля внутри: «Исходная дата», «Целевая дата», «Сумма корректировки»; комментарий необязателен.
- Что показывает, когда обязательное не заполнено: Alert «Введите исходную и целевую даты в формате ДД.ММ.ГГГГ и сумму корректировки числом.» и красные поля.
- Что отдаёт наружу: запись `{ startDate, endDate, adjustmentAmount, comment }` (даты ISO) — странице (`save`).

## Поведение (Behavior)

1. «Добавить» / «Сохранить» проверяют форму:
   - не заполнены даты или сумма — «Введите исходную и целевую даты в формате ДД.ММ.ГГГГ и сумму корректировки числом.»;
   - в исходную дату у индикатора нет события — «В исходную дату у индикатора нет события. Укажите дату начисления процентов.»;
   - у индикатора есть дельта, а на исходную дату её нет — «На исходную дату нет дельты. Укажите дату после фиксации расчёта.»;
   - целевая дата не раньше исходной — «Целевая дата должна быть раньше исходной.»;
   - в целевую дату у индикатора нет события — «В эту дату у индикатора нет события. Укажите дату начисления процентов.»;
   - сумма равна нулю — «Сумма корректировки не может быть равна нулю.»;
   - при дельте сумма по модулю больше дельты на исходную дату — «Сумма больше дельты на дату: <дельта> <валюта>.» Без дельты (расчёт не зафиксирован или не пересчитан) сумма не ограничена.
2. С ошибкой окно остаётся открытым, ошибка — в Alert вверху окна, поля подсвечены; правка поля снимает подсветку.
3. Без ошибки запись уходит странице, окно закрывается, страница показывает тост «Корректировка добавлена» или «Корректировка изменена».
4. «Отменить», крестик и Esc закрывают окно без сохранения.

## Данные (Data dependencies)

### API — что нужно от бэкенда

Даты событий индикатора «Начисленные проценты за период» (для проверки обеих дат), дельта
по датам с учётом переносов, прогноз дельты на первой дате расхождения для черновика переноса,
валюта инструмента, создание и изменение переноса. Имена методов и хуков API не придумываются: их выбирает разработка.

7. **Формула суммы переноса** (вопрос 26 задачи RE0034, 22.10.2026): какая сумма обнуляет расхождение, человек точно не знает; в прототипе — условная модель (чем раньше дата «на», тем сильнее перенос, обнуление — с точностью до копейки), подсказка «Расхождение после переноса» помогает подобрать сумму. Расчёт — на бэкенде.
