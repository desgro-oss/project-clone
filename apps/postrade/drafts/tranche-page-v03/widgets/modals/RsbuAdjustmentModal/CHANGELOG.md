# Модальное окно внесения корректировки (RsbuAdjustmentModal) — журнал изменений

Формат записи: что изменилось · почему · по какому требованию.

## 1.000 — 09.10.2026

Окно заведено локальным компонентом: разметка и поведение формы вынесены со страницы
корректировок (`pages/RsbuInterestAdjustments.html`) в `widgets/modals/`. Страница вшивает
его меткой `ds-include`. Правила проверки и тексты ошибок не менялись; id полей без
префикса страницы (`rsbu-adj-*`), валюта — из параметров списка. *Почему:* окно нужно
в витрине как артефакт тайла «Корректировки процентов РСБУ» и переиспользуется страницей.
*Требование:* решение человека 09.10.2026.

## 1.001 — 12.10.2026

Поля дат переименованы: «Начальная дата корректировки» → «Исходная дата», «Конечная дата
корректировки» → «Целевая дата»; так же — тексты ошибок проверки. Имена полей формы
(`startDate`, `endDate`) не менялись. *Почему:* единый нейминг дат в таблице и окне.
*Требование:* решение человека 12.10.2026.

## 1.002 — 22.10.2026

Корректировка стала переносом суммы (RE0034): добавлено поле «Дельта на дату» (только чтение,
остаток дельты на исходную дату); целевая дата теперь раньше исходной и должна быть датой события
индикатора; сумма не больше остатка дельты по модулю; новые тексты ошибок. Параметры списка
расширены: `eventDates`, `remaining(iso)`. *Почему:* дельты после позднего платежа переносят на
прошлые даты, чтобы итог совпал с «правильным» расчётом. *Требование:* ответы человека 14, 15, 18, 24
(22.10.2026).

## 1.003 — 22.10.2026

«Исходная дата» — обычное поле даты (InputDate, ручной ввод и календарь) вместо выпадающего списка; список `startDateOptions` убран из параметров. Дата проверяется по датам событий индикатора, а при дельте — ещё и на наличие дельты на эту дату; «Дельта на дату» следует за полем при вводе. Текст ошибки о незаполненных полях обновлён. *Почему:* дизайнер попросил обычный датапикер вместо списка. *Требование:* решение человека 22.10.2026.

## 1.004 — 22.10.2026

Под суммой добавлено поле «Расхождение после переноса» (только чтение): прогноз дельты на первой дате
расхождения, если внести перенос с введёнными датой «на» и суммой; параметры списка расширены:
`forecast(end, amt) → { date, amount } | null`. «Дельта на дату» теперь — дельта с учётом уже внесённых
переносов (а не остаток по модулю). *Почему:* перенос меняет начисление на дату «на» и уменьшает дельту на
всех датах не раньше неё, причём одна и та же сумма на более раннюю дату действует сильнее — без прогноза
сумму, нужную для нуля, не подобрать. *Требование:* ответы человека 22.10.2026 (корректировка влияет на
весь последующий расчёт, результат виден до пересчёта); подсказка предложена агентом (решение 25 задачи RE0034).
