# Корректировки процентов РСБУ

## 1. Коротко

- **Что.** Пересчёт процентных платежей с фиксацией закрытого периода — одна операция: кнопка
  «Пересчитать с фиксацией» на тайле «Процентные платежи» транша открывает окно с периодом фиксации,
  целевой датой корректировки и комментарием, подтверждение сразу запускает пересчёт, и дельты дат
  периода становятся корректировками.

- **Зачем.** Пересчёт платежей пересчитывает весь срок отчётности, включая закрытые периоды; закрытую
  отчётность нельзя менять ретроспективно. Значения зафиксированного периода возвращаются
  корректировками, а разница переносится на целевую дату корректировки. Повторные пересчёты накапливают
  корректировки: у каждого пересчёта своя целевая дата корректировки и свои дельты, прежние строки
  остаются.

## 2. Сценарий

Два сценария: корректировки вручную без тайла «Процентные платежи» и автоматическая корректировка через него.

### Сценарий 1. Корректировки вручную, без тайла «Процентные платежи»

```scenario
tile | Тайл «Корректировки процентов РСБУ» | page | tile-none-edit
page | Страница корректировок | page | page-empty
manual | Окно «Корректировка процентов» | modal | adj-filled
saved | Ручная корректировка в таблице | ok | page-manual
del | Удаление корректировки | modal | delete-confirm
report | Отчёт РСБУ после пересчёта метрик | ok | fm-manual
filter | Окно фильтра | modal | filter-modal
filtered | Отфильтрованные строки | ok | filtered
selected | Выбраны строки | state | selected
bulk | Подтверждение массового удаления | modal | bulk-delete
tile -> page | стрелка тайла
page -> manual | «Внести корректировку»
manual -> saved | «Добавить»
saved -> del | корзина в строке
saved -> report | «Пересчет метрик» на «Финансовых метриках»
saved -> filter | «Фильтр»
filter -> filtered | «Применить»
filtered -> selected | чекбоксы
selected -> bulk | «Удалить» в колонтитуле
```

#### Шаги сценария

1. Финансист открывает транш → в секции «Процентная задолженность» тайл «Корректировки процентов
   РСБУ»: «Корректировки отсутствуют», стрелка и кнопка «Внести корректировку».
   <!-- snap: tile-none-edit -->
2. Стрелка тайла → страница корректировок; корректировок нет — пустое состояние таблицы.
   <!-- snap: page-empty -->
3. Кнопка «Внести корректировку» → окно [«Корректировка процентов»](#окно-корректировка-процентов-rsbuadjustmentmodal):
   исходная дата и целевая дата корректировки, шесть видов процентов; «Сумма корректировки» считается
   при вводе.
   <!-- snaps: adj-empty adj-filled -->
4. Кнопка «Добавить» → проверка:
   - исходная дата — дата отчёта РСБУ и не позже даты фиксации;
   - целевая дата корректировки — строго позже исходной;
   - хотя бы одна сумма не ноль.

   Ошибка — Alert вверху окна и красные поля, окно остаётся открытым (тексты — раздел 3,
   [«Проверки окна корректировки»](#проверки-окна-корректировки)).
   <!-- snaps: adj-error-dates adj-error-zero adj-error-report-date adj-error-fixation adj-error-target -->
5. Ошибок нет → окно закрывается, строка появляется в таблице, тост «Корректировка добавлена».
   <!-- snap: page-manual -->

   Колонки таблицы корректировок:

   | Колонка | Ширина | Выравнивание | Формат |
   |---|---|---|---|
   | Выбор | 44 | по центру (`th--center` / `tc--center`) | чекбокс строки; в шапке — «Выбрать все» (частичный выбор — indeterminate); без права колонки нет |
   | № | 72 | справа (`th--right` / `tc--numbers`) | номер строки в текущем виде (после фильтра — с 1) |
   | Исходная дата | 144 | слева | `ДД.ММ.ГГГГ` — закрытая дата, с неё сумма вычитается |
   | Целевая дата корректировки | 176 | слева | `ДД.ММ.ГГГГ` — на неё сумма прибавляется |
   | Сумма корректировки | 176 | справа (`th--right`, `tc--numbers`) | `1 000 000,00`, отрицательная — со знаком «-»; сумма шести видов |
   | Текущие начисленные проценты | 176 | справа | `1 000 000,00` |
   | Кап. текущие начисленные проценты | 176 | справа | `1 000 000,00` |
   | Капитализированные начисленные проценты | 176 | справа | `1 000 000,00` |
   | Кап. капитализированные начисленные проценты | 176 | справа | `1 000 000,00` |
   | Отложенные начисленные проценты | 176 | справа | `1 000 000,00` |
   | Кап. отложенные начисленные проценты | 176 | справа | `1 000 000,00` |
   | Комментарий | 280 | слева | текст; пусто — пустая ячейка; у строк из дельт — комментарий из окна пересчёта, пустое поле ничего не подставляет |
   | Действия | 64 | слева | корзина «Удалить корректировку», видна при праве редактирования; правок строк нет |

6. Корзина в строке → подтверждение удаления; «Удалить» → строка исчезает, тост «Корректировка
   удалена». Правок строк нет.
   <!-- snaps: delete-confirm page-deleted -->
7. «Пересчет метрик» на странице «Финансовые метрики» → в отчёте РСБУ отметка на целевой дате
   корректировки; исходная дата — как до пересчёта.
   <!-- snap: fm-manual -->

### Ветки сценария 1

#### Состояния без права на редактирование ({steps:1,3})

- В тайле корректировок нет кнопки «Внести корректировку», стрелка на страницу корректировок
  остаётся — смотреть можно.
- Страница корректировок: без кнопки «Внести корректировку», без колонки «Действия» и корзин
  в строках — только просмотр. Колонок выбора и массового удаления нет, фильтр остаётся.

<!-- snaps: tile-data-view page-view -->

#### Отмена в окнах ({steps:3,6})

- «Отменить», крестик, Esc — окно закрывается без действий.
- Окно с формой кликом по затемнению не закрывается (правило ДС).

#### Отбор и массовое удаление ({steps:2})

- Страница корректировок: дефолтное состояние.
  <!-- snap: page-multi -->
- «Фильтр» над таблицей → окно: исходная дата, целевая дата корректировки, сумма, «Только с
  комментарием». «Применить» сужает строки; чип «Применено: N».
  <!-- snap: filter-modal -->
- Применён фильтр по целевой дате.
  <!-- snap: filtered -->
- Чекбоксы строк и шапки выбирают строки; в колонтитуле — «Выбрано строк: N» и «Удалить».
  <!-- snap: selected -->
- «Удалить» в колонтитуле → подтверждение на выбранные строки; «Удалить» → строки исчезают,
  тост «Корректировки удалены». Одиночная корзина в строке остаётся.
  <!-- snaps: bulk-delete bulk-deleted -->

### Сценарий 2. Автоматическая корректировка через тайл «Процентные платежи»

```scenario
tranche | Транш — тайл «Процентные платежи» | page | pay-tile
fix | Окно «Пересчет с фиксацией» | modal | fix-filled
err | Ошибка проверки | error | fix-error-order
run | Идёт пересчёт | state | fix-loading
done | Корректировки созданы | ok | recalc-done
page | Страница корректировок | page | page-created
multi | Повторный пересчёт — накопление | page | page-multi
report | Отчёт РСБУ после пересчёта метрик | ok | fm-multi
tranche -> fix | «Пересчитать с фиксацией»
fix -> err | «Пересчитать», проверка не прошла
fix -> run | «Пересчитать», ошибок нет
run -> done | пересчёт выполнен
done -> page | стрелка тайла корректировок
page -> multi | повторный пересчёт с фиксацией
multi -> report | «Пересчет метрик» на «Финансовых метриках»
```

#### Шаги сценария

1. Финансист открывает транш → в секции «Процентная задолженность» тайл «Процентные платежи»:
   «Пересчитать» и «Пересчитать с фиксацией».
   <!-- snap: pay-tile -->
2. «Пересчитать с фиксацией» → окно [«Пересчет с фиксацией»](#окно-пересчет-с-фиксацией-rsbufixationmodal),
   всегда пустое: период фиксации, целевая дата корректировки, комментарий.
   <!-- snap: fix-empty -->
3. Период фиксации («От»–«До»), целевая дата корректировки (вводится вручную) и комментарий
   (необязательный); комментарий попадёт во все созданные строки.
   <!-- snaps: fix-filled fix-comment -->
4. «Пересчитать» → проверка окна. Ошибка — Alert вверху окна и красные поля, окно остаётся
   открытым (тексты — раздел 3, [«Проверки окна фиксации»](#проверки-окна-фиксации)); ошибок нет —
   окно закрывается и сразу запускается пересчёт.
   <!-- snaps: fix-error-empty fix-error-order -->
5. Пересчёт: лоадер на нажатой кнопке тайла, обе кнопки выключены до конца операции.
   <!-- snap: fix-loading -->
6. Пересчёт пересчитывает процентные платежи за весь срок отчётности; значения зафиксированного
   периода возвращаются корректировками: на каждую дату периода с ненулевой дельтой создаётся строка
   корректировок с целевой датой корректировки — заданной в окне — и комментарием из окна. Снек
   «Платежи пересчитаны. Создано корректировок РСБУ: 3»; тайл корректировок — «Внесено
   корректировок: 3».
   <!-- snap: recalc-done -->
7. Стрелка тайла «Корректировки процентов РСБУ» → страница корректировок: строки первого
   пересчёта, у каждой целевая дата корректировки 01.04.2025 и комментарий из окна.
   <!-- snap: page-created -->
8. Повторный пересчёт с фиксацией — позже и за более длинный период — добавляет строки
   к имеющимся: у нового пересчёта другая целевая дата корректировки и другие дельты, прежние строки
   остаются со своей целевой датой корректировки.
   <!-- snap: page-multi -->
9. Отчёт РСБУ: страница «Финансовые метрики», вкладка «РСБУ»; корректировки входят в отчёт только
   пересчётом метрик. До пересчёта отметок нет.
   <!-- snap: fm-before -->
10. «Пересчет метрик» → значения «Начисленных процентов за период» с учётом корректировок: колонки
    зафиксированного периода — как до пересчёта, на целевой дате корректировки — жёлтая ячейка с
    меткой и тултипом. Повторный пересчёт даёт отметки на обеих целевых датах корректировок.
    <!-- snaps: fm-after fm-multi -->

### Ветки сценария 2

#### Условия не выполнены ({steps:1})

- Пока процентные платежи не рассчитаны, тайл корректировок просит расчёт: ни стрелки, ни кнопки,
  на страницу корректировок не попасть.
- Без права на пересчёт нет обеих кнопок тайла «Процентные платежи».

<!-- snaps: pay-view tile-locked -->

#### Отмена в окнах ({steps:2,4})

- «Отменить», крестик, Esc — окно закрывается без действий.
- Окно с формой кликом по затемнению не закрывается (правило ДС).

## 3. Виджеты

### Тайл «Процентные платежи» (`Tranche` — тайл страницы, изменение)

- **Назначение:** пересчёт процентных платежей — обычный и с фиксацией закрытого периода.
- **Где стоит:** страница транша, секция «Процентная задолженность», четвёртый тайл; `col-3 colw-6`.
- **Кнопки:** «Пересчитать» (`btn--outline btn--s`), «Пересчитать с фиксацией»
  (`btn--transparent btn--s`).
- **Режимы:** есть права на редактирование — обе кнопки; идёт пересчёт — лоадер на нажатой, обе
  выключены; нет права — обеих кнопок нет.

<!-- matrix: cols="Есть право пересчёта|Нет права пересчёта" rows="Транш" ids="pay-tile pay-view" -->

<!-- snap: fix-loading -->

**Поведение:** «Пересчитать» — пересчёт без корректировок. «Пересчитать с фиксацией» открывает окно
[«Пересчет с фиксацией»](#окно-пересчет-с-фиксацией-rsbufixationmodal).

### Окно «Пересчет с фиксацией» (`RsbuFixationModal`) — новое

- **Назначение / заголовок:** «Пересчет с фиксацией»: задать период фиксации, целевую дату
  корректировки и комментарий и одной операцией запустить пересчёт с созданием корректировок.
- **Ширина:** `modal--w4`.
- **Открывает:** кнопка «Пересчитать с фиксацией» тайла «Процентные платежи».

<!-- snaps: fix-empty fix-filled fix-comment -->


##### Проверки окна фиксации

По кнопке «Пересчитать»; ошибка — Alert вверху окна и красные поля, окно остаётся открытым.
Снимки состояний — {steps:4}.

| Условие | Текст |
|---|---|
| не заполнены даты периода или целевая дата корректировки | «Укажите период фиксации и целевую дату корректировки в формате ДД.ММ.ГГГГ.» |
| «От» позже «До» | «Начало периода фиксации позже его конца.» |
| целевая дата корректировки не позже конца периода | «Целевая дата корректировки должна быть позже конца периода фиксации.» |



### Окно «Фильтр» (`RsbuAdjustmentsFilterModal`) — новое

- **Назначение / заголовок:** «Фильтр»: отобрать корректировки по исходной дате, целевой дате
  корректировки, сумме корректировки и наличию комментария.
- **Ширина:** `modal--w6 tfm`; раздел один — «Корректировки», бейдж — число заполненных групп.
- **Открывает:** кнопка «Фильтр» (TableFilter) над таблицей корректировок.

<!-- snaps: filter-modal -->


**Поведение:** «Применить» — окно закрывается, страница фильтрует строки и рисует чип
«Применено: N»; «Очистить фильтр» сбрасывает поля окна и не закрывает его; крестик и Esc
закрывают без применения; клик по скриму не закрывает. Фильтр доступен и без права редактирования.

### Тайл "Корректировки процентов РСБУ" (`RsbuInterestAdjustmentsTile`) 

- **Назначение:** показывает, внесены ли корректировки, и ведёт на страницу корректировок.
- **Где стоит:** страница транша, секция «Процентная задолженность», пятый тайл; `col-3 colw-6`.
  Размер в px — в подписи снимков.
- **Режимы:** редактирование доступно — есть кнопка «Внести корректировку»; только просмотр —
  кнопки нет, стрелка остаётся.

### Окно "Корректировка процентов" (`RsbuAdjustmentModal`) — новое

- **Назначение / заголовок:** «Корректировка процентов» — ручная корректировка. Только добавление:
  правки строк нет.
- **Ширина:** `modal--w5`.
- **Открывает:** кнопка «Внести корректировку» в шапке страницы корректировок и в тайле транша;
  только с правом редактирования.

<!-- snaps: adj-empty adj-filled -->

##### Проверки окна корректировки

По кнопке «Добавить»; ошибка — Alert вверху окна и красные поля, окно остаётся открытым. Шесть
сумм по видам приходят с бэкенда готовыми; для ручной корректировки их вводит человек. Снимки
состояний — {steps:4}.

| Условие | Текст |
|---|---|
| не заполнены даты | «Введите исходную дату и целевую дату корректировки в формате ДД.ММ.ГГГГ.» |
| исходная дата не входит в даты отчёта РСБУ | «Исходная дата должна быть датой отчёта РСБУ.» |
| исходная дата позже даты фиксации | «Исходная дата не может быть позже даты фиксации (ДД.ММ.ГГГГ).» |
| целевая дата корректировки не позже исходной | «Целевая дата корректировки должна быть позже исходной.» |
| все суммы нулевые | «Укажите сумму хотя бы одного вида процентов.» |
