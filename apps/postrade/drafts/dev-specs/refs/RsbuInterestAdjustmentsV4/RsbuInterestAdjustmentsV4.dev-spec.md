# Корректировки процентов РСБУ

## 1. Коротко

- **Что.** Пересчёт процентных платежей с фиксацией закрытого периода — одна операция: кнопка
  «Пересчитать с фиксацией» на тайле «Процентные платежи» транша открывает окно с периодом фиксации и
  целевой датой корректировки, подтверждение сразу запускает пересчёт, и дельты дат периода становятся
  корректировками. Корректировки лежат на странице «Корректировки процентов РСБУ», ручные вносятся
  окном, отчёт РСБУ получает помесячную сетку колонок.

- **Зачем.** Пересчёт платежей пересчитывает весь срок отчётности, включая закрытые периоды; закрытую
  отчётность нельзя менять ретроспективно. Значения зафиксированного периода возвращаются
  корректировками, а разница переносится на целевую дату корректировки. Повторные пересчёты накапливают
  корректировки: у каждого пересчёта своя целевая дата корректировки и свои дельты, прежние строки
  остаются.

- **Кто.** Пересчёт и ручные корректировки — сотрудники operations (финансисты ДИД); других ролей
  пока нет.
- **Где.**
  - Тайлы — страница транша, секция «Процентная задолженность»;
  - страница корректировок — с тайла;
  - отчёт — страница «Финансовые метрики», вкладка «РСБУ».

- **Новое:**
  - страница `RsbuInterestAdjustments`;
  - виджеты: тайл `RsbuInterestAdjustmentsTile`, окна `RsbuFixationModal` (окно «Пересчет с
    фиксацией») и `RsbuAdjustmentModal` (окно «Корректировка процентов»);
  - окно подтверждения удаления — разметкой страницы.
- **Изменено:** тайл «Процентные платежи» — кнопки «Пересчитать» и «Пересчитать с фиксацией»;
  без ФИ вторая кнопка видна и заблокирована (раздел 4).

## 2. Сценарий

Два сценария: корректировки вручную без тайла «Процентные платежи» и автоматическая корректировка
через него.

### Сценарий 1. Корректировки вручную, без тайла «Процентные платежи»

```scenario
tile | Тайл «Корректировки процентов РСБУ» | page | tile-none-edit
page | Страница корректировок | page | page-empty
manual | Окно «Корректировка процентов» | modal | adj-filled
saved | Ручная корректировка в таблице | ok | page-manual
del | Удаление корректировки | modal | delete-confirm
report | Отчёт РСБУ после пересчёта метрик | ok | fm-manual
tile -> page | стрелка тайла
page -> manual | «Внести корректировку»
manual -> saved | «Добавить»
saved -> del | корзина в строке
saved -> report | «Пересчет метрик» на «Финансовых метриках»
```

| Комментарий | InputText multiline | нет | свободный текст |

- Даты и суммы — рядами по две колонки, «Сумма корректировки» — на всю ширину.
- Хотя бы одна из шести сумм — не ноль.
- Шесть сумм по видам приходят с бэкенда готовыми; для ручной корректировки их вводит человек.
- Роли: пересчёт и ручные корректировки — сотрудники operations (финансисты ДИД); других ролей
  пока нет.

##### Проверки окна корректировки

По кнопке «Добавить»; ошибка — Alert вверху окна и красные поля, окно остаётся открытым. Снимки
состояний — {steps:4}.

| Условие | Текст |
|---|---|
| не заполнены даты | «Введите исходную дату и целевую дату корректировки в формате ДД.ММ.ГГГГ.» |
| исходная дата не входит в даты отчёта РСБУ | «Исходная дата должна быть датой отчёта РСБУ.» |
| исходная дата позже даты фиксации | «Исходная дата не может быть позже даты фиксации (ДД.ММ.ГГГГ).» |
| целевая дата корректировки не позже исходной | «Целевая дата корректировки должна быть позже исходной.» |
| все суммы нулевые | «Укажите сумму хотя бы одного вида процентов.» |

**Поведение:** «Добавить» — ошибок нет → окно закрывается, строка появляется в таблице, тост
«Корректировка добавлена». «Отменить», крестик, Esc — закрыть без записи.
