# Модальное окно корректировки процентов

## Описание (Purpose)

Артефакт тайла «Корректировки процентов РСБУ»: окно ручной корректировки на странице корректировок.
Заголовок — «Корректировка процентов», окно только добавляет: правки строк в концепте v4 нет.

Корректировка вычитает сумму с «Исходной даты» и прибавляет её на «Целевую дату корректировки» при каждом
пересчёте метрик — так закрытые даты отчёта РСБУ остаются как при закрытии. Сумма раскладывается на шесть видов
начисленных процентов: слева — текущие, капитализированные, отложенные; справа — те же «Кап.»
(капитализированные). «Сумма корректировки» — сумма шести полей, только для чтения, считается при вводе.
Обычно корректировки создаются сами из дельт после «Пересчитать с фиксацией» на транше; это окно — для
ручной.

Транш и таблицу окно не знает: валюту берёт у страницы, проверенную запись отдаёт ей же
(`PostModalRsbuAdjustment.bind(scrim, { options, save })`, `RsbuAdjustmentModal.js`). Страница добавляет
строку и показывает тост.

## Бизнес-смысл (Business context)

| Вопрос | Ответ |
|---|---|
| Зачем существует | [[Закрытый период|закрытый отчётный период]] (данные ушли в 1С) менять нельзя: разницу, найденную после пересчёта транша, переносят на следующий период корректировкой |
| Кто заполняет и когда | финансист — сотрудник [[Operations]] (финансист ДИД), когда строки из дельт не покрывают нужную правку; других ролей пока нет (ответ человека 05.11.2026) |
| Кто пользуется результатом | отчёт РСБУ на странице «Финансовые метрики» — после пересчёта метрик |
| Бизнес-правила | корректировка участвует в каждом пересчёте метрик: −сумма на исходной дате, +сумма на целевой дате корректировки (решение человека 28.10.2026); «Сумма корректировки» = сумма шести видов, считается на фронтенде (ответ человека 05.11.2026); исходная дата — дата отчёта РСБУ, не позже даты фиксации, целевая дата корректировки — строго позже исходной; правок нет, только удаление строки под ответственность пользователя |

Источники: решения человека 28.10.2026 (задача RE0034, раздел «Концепт v4»); ответы человека 05.11.2026 (RE0050); бизнес-требование «Критерии приемки».

## Обязательность заполнения (Required)

- Компонент обязателен к заполнению целиком: нет.
- Обязательные поля внутри: обе даты; хотя бы одна сумма не ноль.
- Что показывает, когда обязательное не заполнено: Alert с текстом правила, поля красные.
- Что отдаёт наружу (признак для экрана или формы): `save({ startDate, endDate, parts, comment })` — даты ISO, части по ключам полей.

1. Пары во фронтенде нет — функционал новый, имя наше (ответ человека 05.11.2026).

4. **Все суммы нулевые** запрещены — допущение агента (28.10.2026).
5. История v3 (перенос «с» → «на» раньше, «Дельта на дату», «Расхождение после переноса», правка) — в концепте `tranche-page-v03`.
