# Окно «Фиксация РСБУ»

## Описание (Purpose)

Перед изменениями транша, которые должны попасть в закрытый период, финансист фиксирует РСБУ: в
окне две даты. **Дата фиксации** — значения индикатора «Начисленные проценты за период» фиксируются с
первой даты отчёта РСБУ по эту дату. **Дата корректировки** — на неё лягут дельты всех зафиксированных
дат, когда после изменений транша нажмут «Пересчитать платежи»; по смыслу это первое число месяца после
закрытого периода. После «Сохранить» на тайле «Процентные платежи» видно «Дата фиксации РСБУ: ДД.ММ.ГГГГ».

Окно не знает стора: правила проверки дат берёт у страницы (`check`), проверенные даты отдаёт ей же
(`save`). Где окно стоит и когда открывается, решает страница.

## Бизнес-смысл (Business context)

| Вопрос | Ответ |
|---|---|
| Зачем существует | [[Закрытый период|закрытый отчётный период]] (данные ушли в 1С) менять нельзя; данные за него, пришедшие позже, пересчитывают в транше так, будто их учли вовремя. Фиксация запоминает значения на момент закрытия, чтобы после пересчёта получить дельты и перенести их на следующий период |
| Кто заполняет и когда | финансист (operations), перед изменениями транша, сделка в «Ввод изменений» |
| Кто пользуется результатом | «Пересчитать платежи» на том же тайле — создаёт корректировки на странице «Корректировки процентов РСБУ»; отчёт РСБУ на странице «Финансовые метрики» после пересчёта метрик |
| Бизнес-правила | дата фиксации — конец закрытого периода, фиксируются все даты отчёта с первой по неё; дата корректировки — первое число следующего отчётного месяца (решение человека 28.10.2026); позже даты фиксации — допущение агента (решение 27 задачи RE0034) |

Источники: решения человека 28.10.2026 (задача RE0034, раздел «Концепт v4»).

| Состояние | Когда | Вид |

## Обязательность заполнения (Required)

- Компонент обязателен к заполнению целиком: да — обе даты.
- Обязательные поля внутри: см. «Поля».
- Что показывает, когда обязательное не заполнено: Alert «Укажите дату фиксации и дату корректировки в формате ДД.ММ.ГГГГ.», пустые поля красные.
- Что отдаёт наружу (признак для экрана или формы): `save({ fixationDate, adjustmentDate })` (ISO) по «Сохранить»; отмена — ничего.

## Поведение (Behavior)

| Триггер | Результат |
|---|---|
| Ввод даты фиксации (с клавиатуры или в календаре) | пока дата корректировки не правилась руками, она становится первым числом месяца после даты фиксации |
| «Сохранить» | проверка; ошибок нет — окно закрывается, страница сохраняет фиксацию (`FinMetricsStore.fixRas`), на тайле «Дата фиксации РСБУ: ДД.ММ.ГГГГ», снек «Фиксация РСБУ сохранена» |
| «Отменить», крестик, Esc | окно закрывается, фиксация прежняя |
| Правка поля с ошибкой | подсветка поля снимается |

### Проверка

Тексты придуманы агентом (решение 29 задачи RE0034):

| Правило | Текст Alert |
|---|---|
| обе даты заполнены и в формате `ДД.ММ.ГГГГ` | «Укажите дату фиксации и дату корректировки в формате ДД.ММ.ГГГГ.» |
| дата фиксации не раньше первой даты отчёта РСБУ ФИ | «Дата фиксации раньше первой даты отчёта РСБУ (ДД.ММ.ГГГГ).» |
| дата корректировки позже даты фиксации | «Дата корректировки должна быть позже даты фиксации.» |
