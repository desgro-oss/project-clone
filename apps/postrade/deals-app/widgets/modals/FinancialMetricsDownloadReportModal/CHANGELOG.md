Формат записи: что изменилось · почему · по какому требованию. Без «почему» правку через

## 0.001 — 21.10.2026

**Окно создано: выгрузка отчета финансовых метрик.** Один скрим `fm-download-scrim` на оба вида.
Без шифрования (сеть Альфа / Омега): шапка «Выгрузка отчета», предупреждение о данных К2 (Alert
warning flush), подвал «Отменить» и «Выгрузить»; `modal--w6`. С шифрованием (сеть Сигма): то же
плюс блок получателей — «Сотрудник» (InputAutocomplete) и «Сотрудник вне штата (по e-mail)» с
кнопками «Добавить» и таблица ФИО · Должность · Почта во внешнем и во внутреннем домене с
чекбоксами; `modal--w8`; «Выгрузить» выключена, пока никто не отмечен. Скрипт
`FinancialMetricsDownloadReportModal.js` (`PostDealDownloadReportModal`): `bind(scrim, { employees, run })`,
`api.open({ encrypted, … })`, `api.load(ctx, recipients)` (живое демо витрины), `preview(scrim, { encrypted, recipients })` для витрины. Паспорт и
образцы данных для витрины — `FinancialMetricsDownloadReportModal.md`, `fixtures.json`. *Почему:* этап Э8 задачи
RE0033 — «Выгрузить в XLSX» из кебаба страницы «Финансовые метрики» открывает окно; на макетах
два вида окна нарисованы по-разному (заголовок и пара кнопок), человек велел сделать одинаково. Имя виджета — не `DownloadReportModal` (пара фронтенда), потому что в разделе Post уже есть виджет с таким именем (окно расчёта FV, `post-reports-app`): id в витрине локальных компонентов уникален в разделе (сторож КТ6).
Логика получателей — по окну расчёта FV соседнего модуля (`post-reports-app`, RE0012), но с одним
скримом вместо двух и своим справочником. *Требование:* задача RE0033, ответы человека 20.10.2026
и 21.10.2026 (12, 21, 31), решение агента 11.
