# Фильтр дополнительных соглашений

## Описание (Purpose)

Артефакт кнопки «Фильтр» ([[ДС]]-списка страницы «Договор и дополнительные соглашения»). Не компонент: сам по себе
не существует и в плоском списке витрины его нет. Заголовок окна — «Фильтр». Кнопка «Фильтр» (TableFilter) и чип
«Применено: N» стоят на странице, в окне их нет.

Окно — штатная модалка фильтра ДС: слева вертикальное меню разделов «Основная информация» и «Решение» со
счётчиками заполненных полей, справа оба раздела подряд (клик по пункту меню доводит до раздела). В разделе
«Основная информация» — номер соглашения, дата подписания (диапазон), тип изменения, ключевые изменения; в разделе
«Решение» — номер решения, дата решения (диапазон), уровень одобрения.

Окно не читает стор. Страница при каждом открытии отдаёт текущий применённый фильтр (`open(currentFilter)`), окно
заполняется им; «Сохранить» проверяет формат дат, закрывает окно и отдаёт новый фильтр событием `agreementsfilter`
на `document`. Стор фильтрует список по этому фильтру (формат — аргумент `LoanAgreementStore.agreements()`), а
число заполненных полей страница показывает чипом «Применено: N».

«Очистить фильтр» очищает только поля окна: окно остаётся открытым, счётчики обнуляются, фильтр не применяется — он
меняется только по «Сохранить». Так же устроено окно фильтра `FinancialMetricsFilterModal`.

## Поля (Fields)

| Поле | Смысл | Тип, единица | Ключ фильтра | Источник | Обязательное |
|---|---|---|---|---|---|
| Номер соглашения | номер ДС, подстрока | строка | `number` | `LoanAgreementStore.agreementNumber(a)` — «порядковый-номер договора» (ответ 13/26) | нет (ответ 28) |
| Дата подписания, от | начало диапазона даты подписания ДС | дата `ДД.ММ.ГГГГ` (в фильтре — ISO) | `signFrom` | `signDate` ДС | нет; заполненная должна быть существующей датой |
| Дата подписания, до | конец диапазона | то же | `signTo` | `signDate` ДС | то же |
| Тип изменения | тип изменения ДС, один | код (`ChangeTypeCode`), в поле — подпись | `changeTypeCode` | `LOAN_CHANGE_TYPE_LABELS` | нет |
| Ключевые изменения | ключевые изменения ДС, несколько; ДС подходит, если у него есть хотя бы одно из выбранных | коды (`KeyChangeCode`)[], в поле — чипы | `keyChangeCodes` | `LOAN_KEY_CHANGE_LABELS` | нет |
| Номер решения | номер решения [[КО]], подстрока | строка | `decisionNumber` | `decisionNumber` ДС | нет |
| Дата решения, от | начало диапазона даты решения | дата `ДД.ММ.ГГГГ` (в фильтре — ISO) | `decisionFrom` | `decisionDate` ДС | нет; заполненная должна быть существующей датой |
| Дата решения, до | конец диапазона | то же | `decisionTo` | `decisionDate` ДС | то же |
| Уровень одобрения | уровни одобрения, несколько | коды (`ApprovalLevelCode`)[], в поле — чипы | `approvalLevelCodes` | `LOAN_APPROVAL_LEVEL_LABELS` | нет |

Порядок строк — порядок отображения. Формат фильтра — `{ number, signFrom, signTo, changeTypeCode,
keyChangeCodes[], decisionNumber, decisionFrom, decisionTo, approvalLevelCodes[] }` (аргумент
`LoanAgreementStore.agreements()`): даты — ISO, у пустого поля ключа нет, пустой фильтр — `{}`. Счётчики разделов
считают заполненные поля: «Основная информация» — `number`, диапазон подписания, `changeTypeCode`,
`keyChangeCodes`; «Решение» — `decisionNumber`, диапазон решения, `approvalLevelCodes`. Диапазон дат — одно поле,
если заполнена хотя бы одна граница. Всего полей — семь (`count` в событии — не больше семи; девять на кадре
макета — демо-значение, не требование). Пересчёт — на вводе.

## Обязательность заполнения (Required)

- Компонент обязателен к заполнению целиком: нет. Пустой фильтр (`{}`) допустим: он показывает все ДС.
- Обязательные поля внутри: нет (ответ человека 26.10.2026, вопрос 28: проверяется только формат дат).
- Что показывает, когда обязательное не заполнено: не применимо.
- Что отдаёт наружу (признак для экрана или формы): событие `agreementsfilter` с `detail { filter, count }`.

| Случай | Правило |

## Поведение (Behavior)

| Триггер | Результат |
|---|---|
| Открытие (`open(currentFilter)`) | поля заполняются текущим фильтром, счётчики пересчитываются; несохранённый ввод прошлого открытия сбрасывается. Окно открыто не через `open()` (например, триггером `data-modal`) — заполняется последним фильтром, который окно получило или сохранило, либо `opts.get()` |
| Клик по разделу в меню | панель прокручивается до раздела, пункт помечается текущим (рантайм ДС) |
| Ввод в поле, выбор в списке, снятие чипа, крестик очистки поля | счётчик раздела и доступность «Очистить фильтр» пересчитываются |
| Правка поля даты при показанной ошибке | ошибка пересчитывается и снимается, когда ввод стал верным |
| «Очистить фильтр» | все поля окна очищаются, счётчики обнуляются, кнопка выключается; окно остаётся открытым, фокус на «Номер соглашения»; фильтр страницы не меняется до «Сохранить» |
| «Сохранить» | четыре даты проверяются: пусто — можно, иначе существующая дата `ДД.ММ.ГГГГ`; неверная — ошибка у поля, окно открыто, фокус на первом неверном поле, события нет. Иначе окно закрывается и на `document` уходит `agreementsfilter` с `detail { filter, count }` |
| Крестик, Esc | закрытие без сохранения, события нет; изменения в окне пропадают |
| Клик по скриму | не закрывает: в окне есть поля ввода (защита включается сама) |

### Событие `agreementsfilter`

| Поле `detail` | Тип | Смысл |
|---|---|---|
| `filter` | объект | фильтр в формате аргумента `LoanAgreementStore.agreements()`; даты ISO; пустое поле — ключа нет; пустой фильтр — `{}` |
| `count` | число | число заполненных полей фильтра (диапазон — одно поле), для чипа «Применено: N» на странице |

Событие уходит и при пустом фильтре (`filter: {}`, `count: 0`): страница сбрасывает фильтр и убирает чип.

| Правило | Как сделано | Почему |

## Открытые вопросы (Open questions)

1. **Справочники** «Тип изменения», «Ключевые изменения», «Уровень одобрения» неполные: в окне только значения со
   скринов (ответ человека 26.10.2026, вопрос 12) — не решено (27.10.2026), какие значения есть на самом деле. Окно
   строит опции из глобалов при привязке; когда справочник изменится — изменится только `data/mock-loan-agreements.js`.
2. **Состояний «Загрузка» и «Ошибка загрузки»** нет: у окна нет сети, на макете их нет. Не решено (27.10.2026), нужны ли
   они, когда справочники придут от бэкенда.
