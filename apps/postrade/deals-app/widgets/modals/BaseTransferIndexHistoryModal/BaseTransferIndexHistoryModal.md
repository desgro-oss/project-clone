# История изменения базового индекса

## Описание (Purpose)

Окно-справка страницы «Единая трансфертная ставка» ([[ЕТС]]): таблица изменений базового индекса
([[БИ]]) — по строке на каждое изменение. Колонки: «Дата изменения», «Базовый индекс (БИ)»
(подпись, сейчас единственная — [[КС]]) и «Значение, %». Строки идут от новых к старым; у каждой
колонки есть сортировка, под таблицей — пагинация (размер страницы по умолчанию 50). Истории нет —
в теле таблицы «Нет данных», пагинации нет. Внизу окна одна кнопка «Закрыть».

Правки в окне нет, поэтому оно доступно и в режиме просмотра страницы: режима прав у окна нет.
Окно ничего не хранит: на каждом открытии читает историю из стора договора
(`LoanAgreementStore.baseIndexHistory()`) и рисует её заново — страница 1, размер страницы 50,
сортировка снята (`PostModalBaseTransferIndexHistory`, `BaseTransferIndexHistoryModal.js`).

## Поведение (Behavior)

### Таблица: сортировка и страницы

1. **Строки.** На открытии окно читает `LoanAgreementStore.baseIndexHistory()` (от новых к
   старым), хранит массив в памяти и рисует текущую страницу. Размер страницы по умолчанию — 50.
2. **Сортировка** — штатная ДС: кнопка в шапке, цикл «нет → по возрастанию → по убыванию → нет»,
   рантайм меняет глиф и `aria-sort`. Порядок строк рантайм не переставляет (`data-sort-rows` не
   стоит): страница в DOM — лишь часть истории, поэтому по событию `sort` (`{ column, dir }`)
   окно пересортирует весь массив и нарисует первую страницу заново — так же сортировал бы
   сервер. Дата — по ISO-строке, значение — числом, БИ — текстом по подписи; «нет» возвращает
   порядок «от новых к старым»; пустое значение всегда внизу.
3. **Пагинация** — `DSPagination.footer`. Смена страницы или размера страницы перерисовывает
   строки; смена размера возвращает на первую страницу. После перерисовки окно заново зовёт
   `dsIcons.apply` и `DSTable.bindAll` / `wireAll` / `wire(...).rowsChanged()`.
4. **Пусто.** Истории нет — «Нет данных» в теле, колонтитул скрыт. Шапка с кнопками сортировки
   на месте (как на макете).
5. **Открытие.** Каждое открытие — свежее: страница 1, размер 50, сортировка снята (шапка
   сбрасывается штатным `DSTable.wire(...).sort(..., 'none')`).
6. **Закрытие.** Крестик, «Закрыть» (`data-modal-close`), Esc и клик мимо окна (полей ввода в окне
   нет, защита от клика по скриму не включается) — штатно, рантайм Modal.

## Для разработчиков (Implementation)

### Параметры метки (Props)

Метка `<ds-include>` атрибутов не несёт: окно открывает страница вызовом, не `data-modal`
(как окна ДС и фильтра): `PostModalBaseTransferIndexHistory.open()`. Режима прав (`data-mode`) и
состояния данных (`data-state` на скриме ставит скрипт: `data` · `empty`) метка не задаёт.

### Скрипт виджета

`PostModalBaseTransferIndexHistory` — `bind(scrim?, { get })`, `open(opts?)`, `use(rows)`:

- `open()` без аргументов читает `LoanAgreementStore.baseIndexHistory()`, рисует таблицу и
  открывает окно; `open({ rows })` подставляет строки (витрина);
- `use(rows)` заполняет окно без показа (витрина);
- `bind()` — идемпотентный; привязка к скриму `#bih-scrim` происходит в самом файле на
  `DOMContentLoaded`, страница может звать `bind()` сама;
- `bind(...).read()` — что сейчас в окне: строки, сортировка, страница, размер, число показанных
  строк (для сценариев проверки).
