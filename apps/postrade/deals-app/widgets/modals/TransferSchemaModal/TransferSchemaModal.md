# Окно «Процентная схема»

## Описание (Purpose)

Артефакт карточки процентной схемы (страница «Единая трансфертная ставка»). Не компонент: сам по себе не существует и в плоском списке витрины его нет — он принадлежит странице и карточке схемы.

Одно окно на создание и правку схемы и подтверждение удаления:

- **Создание** — «Процентная схема», поля пустые, «Рабочих дней до применения БИ» — 0, тип ставки не выбран. Открывает страница: `open({})`.
- **Правка** — то же окно, заголовок тот же, поля заполнены схемой по `id`: `open({ id })`. Кнопки «Удалить» в окне нет (макет её не рисует): удаление — пункт «Удалить» меню ⋮ карточки, страница зовёт `confirmRemove(id)`.
- **Удаление** — подтверждение «Подтвердите действие» («Удаление процентной схемы»; «Отменить» / «Подтвердить»). Подчасть окна: отдельный скрим в том же файле.

Состав окна: «Рабочих дней до применения БИ» (число, по умолчанию 0), «Дата начала», «Дата окончания», «Комментарий» (многострочное поле), «Тип ставки» (список «Фиксированная» / «Плавающая»). Для фиксированной рядом появляется «Ставка» с суффиксом «%». Для плавающей — «Базовый индекс (БИ)» (список; в справочнике сейчас одно значение — «КС») и «Спред» с суффиксом «%».

Окно самодостаточно: читает схему по `id` из `LoanAgreementStore.schemes()`, «Сохранить» зовёт `addScheme` (создание) или `updateScheme(id, …)` (правка), «Подтвердить» удаления — `removeScheme(id)`. После успеха окно закрывается и шлёт на `document` событие `transferschemasaved` с `detail { kind: 'add' | 'update' | 'remove', id }` — по нему страница перерисовывает карточки и показывает тост. Глобал `PostModalTransferSchema` — `bind(scrim?, opts?)`, `open({ id? })` и `confirmRemove(id)` (`TransferSchemaModal.js`).

Если ставка или период не прошли проверку стора, окно остаётся открытым, вверху — один Alert уровня окна со всеми сработавшими ошибками, строкой на каждую.

Отличие от макета (решение человека 26.10.2026, ответ 7): маска даты — `ДД.ММ.ГГГГ`, а не `ММ.ДД.ГГГГ`.

## Обязательность заполнения (Required)

- Компонент обязателен к заполнению целиком: да — схема без ставки и без дат не сохраняется.

| Триггер | Результат |
|---|---|

| «Подтвердить» удаления | `removeScheme(id)`, подтверждение закрывается, событие `transferschemasaved` (`kind: 'remove'`, `id`). В просмотре — только закрытие |
| «Отменить», крестик, Esc подтверждения | подтверждение закрывается, ничего не удаляется |
| Крестик, Esc окна | закрытие без сохранения |
| Клик по скриму | не закрывает: в окне ввод |

### Выбор значений

«Тип ставки», «Базовый индекс (БИ)» — одиночный выбор: опция из списка, набранный текст, совпавший с подписью, выбирается, иначе откатывается к выбранному; крестик очистки снимает выбор (у типа ставки — прячет поля ставки). Числа «Ставка» и «Спред» читаются с запятой или точкой, пробелы игнорируются; значение, которое не разобрать как число, уходит в стор пустым — Alert «Необходимо заполнить данные по ставке».

## Открытые вопросы (Open questions)

1. **Тексты ошибок формата.** «Введите дату в формате ДД.ММ.ГГГГ» и «Введите целое число не меньше нуля» — тексты прототипа, не из макета (по образцу окна ДС). Не решено (27.10.2026). Тексты ошибок схемы (четыре строки Alert) — решение человека 27.10.2026, вопрос 43.
2. **Число, которое не разобрать.** В «Ставке» и «Спреде» значение вроде «abc» уходит в стор пустым, и окно отвечает Alert «Необходимо заполнить данные по ставке», поле не краснеет и отдельного текста нет (допущение 27.10.2026: новых текстов не вводил). Нужен ли отдельный текст — не решено (27.10.2026).
3. **Границы значений.** Допустима ли отрицательная ставка и спред, верхняя граница ставки, спреда и лага, число знаков после запятой — человек не называл; окно не проверяет (отрицательный спред принимается). Не решено (27.10.2026).
4. **БИ по умолчанию.** В справочнике одно значение «КС»; при выборе «Плавающей» оно не подставляется — выбирать нужно руками (на макете в этом состоянии «КС» выбрано, это пример значений). Подставлять ли единственное значение — не решено (27.10.2026).
5. **Исчезнувшая схема.** Если схему удалили, пока окно правки было открыто (`NOT_FOUND`), окно закрывается без сообщения и без события. Текста на этот случай нет — не решено (27.10.2026).
6. **Окно в просмотре** на макете не нарисовано. Допущение 27.10.2026: окно и подтверждение в просмотре не открываются, защита — «Сохранить» и «Подтвердить» только закрывают.
7. **Ошибка формата и ошибки стора не показываются вместе.** При неверном формате даты или лага стор не вызывается, Alert не показывается; Alert со всеми ошибками — только по ответу стора. Допущение 27.10.2026: решение человека 27.10.2026 (вопрос 43) говорит про ошибки схемы; формат дат в нём не назван.
8. **Роли, правящие договор** — не решено (27.10.2026; ответ человека 26.10.2026, вопрос 22).
9. **Рабочие дни.** Как считать «рабочие» (без производственного календаря, суббота и воскресенье выходные) — допущение стора (решение агента 10 задачи), не решено (27.10.2026).
10. **Бизнес-смысл** — не решено (27.10.2026): кто пользуется ставкой схемы, кроме тайла «ЕТС» и окон историй, и как схема попадает в расчёты.
11. **Два скрима в одном файле.** Подтверждение лежит в том же фрагменте соседним корневым узлом, как у окна ДС; ассемблер переносит атрибуты метки только на первый корень. Не решено (27.10.2026), как собирать страницу и витрину.
