# Окно «Дополнительное соглашение»

## Описание (Purpose)

Артефакт тайла «Договор и дополнительные соглашения» (внутренняя страница договора). Не компонент: сам по себе не существует и в плоском списке витрины его нет — он принадлежит своему тайлу.

Одно окно на три сценария макета и подтверждение:

- **Создание** — пустое окно, «Создание дополнительного соглашения». Номер доп. соглашения — следующий порядковый (его даёт страница: `open({ nextSeqNumber })`), дата подписания не подставляется. Заполненное создание на макете — то же окно с введёнными значениями.
- **Редактирование** — «Редактирование дополнительного соглашения»: поля заполнены записью ДС, слева в подвале добавляется «Удалить».
- **Удаление** — подтверждение «Подтвердите действие» («Удаление дополнительного соглашения»; «Отменить» / «Подтвердить»). Подчасть окна: отдельный скрим в том же файле, поднимается поверх окна правки.

Два блока полей: «Информация о доп. соглашении» ([[ДС]]: дата подписания, номер, тип изменения, ключевые изменения, комментарий) и «Информация о решении КО» ([[КО]]: дата решения, номер решения, уровень одобрения).

Окно самодостаточно: читает запись по `id` из `LoanAgreementStore.agreements()`, «Сохранить» зовёт `addAgreement` (создание) или `updateAgreement(id, …)` (правка), «Подтвердить» удаления — `removeAgreement(id)`. Тайлы и страницу перерисовывает страница по событию стора. Глобал `PostModalAdditionalAgreement` — `bind(scrim?, opts?)` и `open({ id?, nextSeqNumber? })` (`AdditionalAgreementModal.js`).

Отличия от макета (решения человека 26.10.2026): подпись «Дата создания» названа «Дата подписания» (ответ 5/25); маска даты — `ДД.ММ.ГГГГ`, а не `ММ.ДД.ГГГГ` (ответы 7, 25); «Номер решения» — одна строка, а не многострочное поле (ответ 14).

## Обязательность заполнения (Required)

- Компонент обязателен к заполнению целиком: нет.
- Обязательные поля внутри: нет (ответ человека 26.10.2026, вопрос 28: проверяется только формат дат).
- Что показывает, когда обязательное не заполнено: не применимо; неверная дата и неверный номер — красное поле и тултип на фокусе («Введите дату в формате ДД.ММ.ГГГГ», «Введите целое число больше нуля»).
- Что отдаёт наружу (признак для экрана или формы): запись ДС в сторе; страница перерисовывает тайлы по событию стора.

## Поведение (Behavior)

| Триггер | Результат |
|---|---|
| Открытие | поля заполняются: создание — пустые, номер = `nextSeqNumber`, дата не подставляется; правка — из записи по `id`; несохранённый ввод прошлого открытия сбрасывается. `id` неизвестен — окно не открывается |
| Правка поля с показанной ошибкой | ошибка пересчитывается и снимается, когда ввод стал верным |
| «Сохранить» | проверка форматов: даты — пусто можно, иначе существующая дата; номер — пусто можно, иначе целое > 0. Есть ошибка — окно открыто, фокус на первое поле с ошибкой. Нет — создание `addAgreement(запись)`, правка `updateAgreement(id, запись)`, окно закрывается. В просмотре — только закрытие |
| «Удалить» (правка) | поднимается подтверждение поверх окна |
| «Подтвердить» | `removeAgreement(id)`, закрываются подтверждение и окно ДС. В просмотре — только закрытие |
| «Отменить», крестик, Esc подтверждения | подтверждение закрывается, окно ДС остаётся |
| Крестик, Esc окна | закрытие без сохранения |
| Клик по скриму | не закрывает: в окне ввод |

### Выбор значений

«Тип изменения», «Уровень одобрения» — одиночный выбор: опция из списка, набранный текст, совпавший с подписью, выбирается, иначе откатывается к выбранному. «Ключевые изменения» — мультивыбор: чекбоксы и «Выбрать всё» в списке, чипы в поле; чип убирается крестиком, Backspace/Delete на чипе или Backspace в пустом поле (последний); крестик очистки поля снимает весь выбор. Набранный текст — запрос к списку (с подсветкой совпадения), а не значение.
