## Описание (Purpose)

Окно «Фильтр» страницы «Финансовые метрики»: открывается кнопкой «Фильтр» над таблицей отчёта
(TableFilter) и сужает отчёт — какие финансовые инструменты ([[ФИ]]) показывать и, по каждому из них,
какие индикаторы (метрики отчёта). Окно — связанный артефакт таблицы: чип «Применено: N» и сама
кнопка «Фильтр» стоят на таблице, не в окне.

Устройство — штатная модалка фильтра ДС (`.modal--w6.tfm`): слева вертикальный таб-раздел
«Основная информация» со счётчиком, справа раздел с тем же заголовком. Раздел один.

- **Финансовые инструменты** — первое поле: мультивыбор с чипами в поле. Варианты — ФИ, которые
  есть в сделке и в этом отчёте (приходят в `indicators`). Пустое поле — фильтра по ФИ нет.
- **По одному полю индикаторов на каждый выбранный ФИ.** Подпись поля — имя ФИ, значения —
  индикаторы этого ФИ (мультивыбор с чипами и поиском по набранному). Пустое поле — «все
  индикаторы» ФИ. Убрали ФИ из первого поля — его поле индикаторов исчезает вместе с выбором;
  добавили — поле появляется следом, в порядке выбора.
- **Счётчик на табе раздела** — число выбранных ФИ (ответ 29, 21.10.2026: «число полей ФИ,
  включённых в фильтр»). Ноль — бейдж скрыт.
- **Подвал:** «Очистить фильтр» сбрасывает поля окна и окно не закрывает; «Применить» закрывает
  окно и отдаёт значение странице.

Окно ничего не хранит и не знает о вкладках: при каждом открытии страница отдаёт ему ФИ и
индикаторы нужной вкладки и текущий фильтр этой вкладки. Окно — компонент без сети и без стора; разбор значения и перерисовка таблицы —
на странице.

Значение фильтра — `FmFilterValue`: `{ fiIds: string[], metrics: { [fiId: string]: string[] } }`.
`metrics[fiId]` — коды выбранных индикаторов ФИ; нет ключа или пустой список — все индикаторы.
Пустой фильтр — `{ fiIds: [], metrics: {} }`. При «Применить» в значение попадают только ФИ из
`indicators` и только коды, которые есть у своего ФИ.

| Состояние | Когда | Вид |
|---|---|---|
| Пустой фильтр | значение `{ fiIds: [], metrics: {} }`; после «Очистить фильтр» | первое поле без чипов, полей индикаторов нет, бейдж скрыт (`hidden`), «Очистить фильтр» — `disabled` |

## Обязательность заполнения (Required)

- Компонент обязателен к заполнению целиком: нет — применить пустой фильтр можно, он равен сбросу.
- Обязательные поля внутри: нет, см. «Поля».
- Что показывает, когда обязательное не заполнено: не применимо.
- Что отдаёт наружу (признак для экрана или формы): `FmFilterValue` по «Применить»; `null`, если окно закрыли без применения. Число параметров для чипа «Применено: N» считает страница по значению; окно отдаёт его же в бейдже раздела — число выбранных ФИ.

## Переполнение (Overflow)

| Случай | Правило |
|---|---|
| Длинный текст в поле | подпись поля — имя ФИ целиком (перенос по правилам ДС); чип усекается многоточием, полное имя — тултипом (Chip); длинная строка списка — многоточие (DropdownList) |
| Много строк или записей | много выбранных значений — чипы в один ряд, остальное в «+N» с тултипом перечня (InputAutocomplete); много ФИ — полей индикаторов столько же, тело окна прокручивается (Modal), шапка и подвал на месте; длинный список — `ddl--scroll` |
| Узкая ширина | окно фиксированной ширины `modal--w6`; при узком экране навигация раздела встаёт над формой (правило `.tfm`) |
| Полная ширина | поля на всю ширину раздела (`tfm__span-2`) |

## Поведение (Behavior)

Открывает окно страница: `PostFinMetricsFilter.open({ title?, indicators, value })`. Окно заполняется
значением вкладки, фокус встаёт на первое поле (Modal).

| Триггер | Результат |
|---|---|
| Клик по строке списка первого поля | ФИ добавляется чипом в поле, под ним появляется поле индикаторов этого ФИ (в порядке выбора); бейдж растёт; повторный клик по строке — ФИ снимается |
| «Выбрать всё» в списке первого поля | выбираются все показанные ФИ (при набранном тексте — только совпавшие) |
| Крестик на чипе ФИ, Backspace или Delete на чипе, Backspace в пустом поле | ФИ снимается: поле его индикаторов исчезает вместе с выбором, бейдж уменьшается |
| Набор текста в поле | список сужается до строк с совпадением; текст — запрос, а не значение: с поля он уходит, когда фокус ушёл из поля и из списка |
| Клик по строке списка индикаторов, «Выбрать всё» | индикатор попадает чипом в поле; «Выбрать всё» — все показанные индикаторы |
| Крестик очистки поля | снимается весь выбор этого поля; у поля ФИ — вместе с полями индикаторов |
| «Очистить фильтр» | сбрасываются ФИ и индикаторы; поля индикаторов исчезают, бейдж скрывается; окно остаётся открытым, фокус — на первом поле; кнопка выключается |
| «Применить» | окно закрывается, `open` отвечает значением; применить можно и пустой выбор — это сброс фильтра |
| Крестик окна или Esc | окно закрывается без применения, `open` отвечает `null`; выбор в окне теряется |
| Клик по скриму | не закрывает окно (в окне есть поля ввода) |
| Повторный `open` при открытом окне | возвращает тот же промис, окно не перезаполняется |
| `open` с пустым `indicators` | окно не открывается, ответ `null` |

## Для разработчиков (Implementation)

### Параметры метки (Props)

Метка `<ds-include>` атрибутов не несёт: скрим стоит на странице один, в конце `body`
(`<ds-include src="../widgets/modals/FinancialMetricsFilterModal/FinancialMetricsFilterModal.html">`,
id скрима — `fm-filter-scrim`); открывает его скрипт, а не `data-modal` триггер.

### Параметры вызова

`window.PostFinMetricsFilter` (`FinancialMetricsFilterModal.js`):

| Вызов | Что делает |
|---|---|
| `bind(scrim)` | один раз привязывает окно; корень — `.modal-scrim` (`fm-filter-scrim`). `open` привязывает окно сам, если нашёл скрим по id |
| `preview(scrim, { title?, indicators, value })` | то же заполнение, что в `open`, но окно остается на месте, без слоя поверх страницы; прежний сеанс сбрасывается. Для витрины локальных компонентов, страница его не зовет; окон на витрине несколько, текущим становится то, в которое зашли (pointerdown, focusin, keydown) |
| `open({ title?, indicators, value }) → Promise<FmFilterValue \| null>` | открывает окно. `title` — заголовок (по умолчанию «Фильтр»). `indicators` — `[{ fiId, fiName, currencyCode, metrics: [{ code, name }] }]`. `value` — текущий фильтр вкладки. Ответ: значение по «Применить» (ФИ только из `indicators`, коды только своего ФИ) или `null` |
| `empty() → FmFilterValue` | пустой фильтр `{ fiIds: [], metrics: {} }` |
| `normalize(value, indicators)` | приводит значение к ФИ вкладки: убирает чужие ФИ и коды, повторы, пустые списки индикаторов |

Рантайм поля (DropdownList) привязывается без режима `multiple`: иначе в этом режиме пробел в поле
выбирал бы строку списка, а не писался в запрос. Чипы, поиск по набранному и состояние выбора
держит скрипт окна.

## Открытые вопросы (Open questions)

Раздел не удаляется. Вопросы 1–4 — вопрос 11 задачи RE0033 в части окна; ответ вписывает человек.

1. **Состав индикаторов по типам ФИ** — полного списка нет: у разных типов ФИ (кредит, акции, РЕПО,
   дебиторская задолженность, доп. доходность) и у разных вкладок (МСФО, РСБУ, KPI) индикаторы свои,
   человек дополнит (ответ 11, 20.10.2026). В прототипе — демо-каталог `FIN_METRICS_CATALOG`,
   состав МСФО придуман по чипам макета.
2. **Общий фильтр или свой у вкладки** — по ответу 30 индикаторы у вкладок свои и чип «Применено»
   у каждой свой; допущение: значение фильтра хранится по вкладке и окно получает значение
   нужной вкладки (допущение 21.10.2026). Не решено, должен ли фильтр одной вкладки влиять на
   другую (например, один и тот же ФИ в МСФО и в РСБУ).
3. **Сохраняется ли фильтр между заходами** — не решено (20.10.2026). Окно ничего не хранит; в
   прототипе значение живёт на странице, пока она открыта (допущение 21.10.2026).
4. **«+99» в чипах фильтра** — снято ответом 30 (21.10.2026): «+99» уходит вместе с чиплистом,
   на таблице один чип «Применено: N». Вопрос оставлен в записи: что он означал на макете, так и
   не названо.
5. **Что считает счётчик раздела.** Ответ 29 (21.10.2026): число полей ФИ, включённых в фильтр;
   в окне это число выбранных ФИ (на макете при трёх выбранных ФИ стоит «9» — это число из трёх
   не получается). Допущение: считается число ФИ, а не число чипов индикаторов; то же ли число
   видно в чипе «Применено: N» на таблице — вопрос к странице. Не закрыто.
6. **ФИ, который выбран без индикаторов, и ФИ, у которого выбраны все индикаторы** — равны по смыслу
   («все индикаторы»), но в значении выглядят по-разному: нет ключа в `metrics` или список всех
   кодов. Допущение: окно отдаёт ровно то, что выбрано, ничего не сворачивая (21.10.2026);
   нужно ли сворачивать «выбраны все» в «нет ключа» — решение человека.
7. **Чипы в поле: один ряд с «+N» или перенос на несколько строк, как на макете.** Допущение:
   по ДС — один ряд, «+N» с тултипом перечня (21.10.2026). Для индикаторов с длинными именами
   («МСФО. ОПУ Процентные доходы по ЭПС») в один ряд помещается один-два чипа; нужен ли перенос —
   решение дизайнера, и тогда это изменение InputAutocomplete в ДС.
8. **Дефект ДС (для передачи владельцам ДС):** в рантайме нет фильтрации списка автокомплита
   по набранному и сборки чипов в поле — обещание «Автокомплит» в спеке InputAutocomplete держится
   кодом каждого экрана. Пока — код в окне.
9. **ФИ без индикаторов** — теоретический случай (`metrics: []`): допущение — поле выключено,
   плейсхолдер «Нет индикаторов» (21.10.2026). Должен ли такой ФИ вообще быть в списке окна.
10. **Применённый фильтр после пересчёта метрик.** После пересчёта состав ФИ и индикаторов
    вкладки может измениться. Окно при открытии и при «Применить» отбрасывает ФИ и коды, которых
    уже нет; чип «Применено: N» на таблице до следующего открытия окна может показывать устаревшее N —
    поведение страницы, решается в её спеке. Допущение, не решено (21.10.2026).
11. **Тексты, которых нет на макете** — допущение (21.10.2026): плейсхолдер первого поля
