# Фиксация ЭПС/ВБС

## Описание (Purpose)

Окно фиксации ЭПС/ВБС (ЭПС — эффективная процентная ставка, ВБС — валовая балансовая стоимость).
Пользователь выбирает финансовые инструменты (ФИ) сделки, дату изменений и вид модификации, при
желании смотрит предварительный расчёт и сохраняет — расчёт фиксации запускается, а результат
попадает в историю фиксаций страницы «Финансовые метрики».

Окно — список карточек фиксации, по одной на ФИ; карточек от одной до сколько нужно (кнопка
«+ Добавить ФИ»). Карточка — подчасть `FixationModalTile`.

**Базовый сценарий** (этап Э6 RE0033):

1. Окно открывается с одной пустой карточкой. Предварительный расчёт недоступен, «⊖» (удалить
   карточку) выключена — карточка единственная.
2. Выбраны ФИ и дата изменений → подтягиваются «ВБС до фиксации» и ЕТС с Δ ЕТС; предварительный
   расчёт становится доступен.
3. «Предварительный расчет» → на кнопке лоадер, затем кнопку заменяет чип «Расчет выполнен»,
   блоки «Несущественная» и «Существенная модификация» заполняются. По результату пользователь
   решает, какой тип модификации выбрать. Типу расчёт не нужен (ответ 35): тип можно выбрать и до
   расчёта.
4. Сброс ФИ или даты сбрасывает предварительный расчёт и данные карточки («ВБС до фиксации»,
   ЕТС); тип и комментарий остаются.
5. «Первоначальная» — дата очищается и блокируется, предварительный расчёт блокируется, значения
   блоков — прочерк. Нужна для нового ФИ, по которому ещё нет первоначальной фиксации.
6. «Сохранить» — проверка (ниже); верно → окно закрывается, тост «Расчет фиксации ЭПС/ВБС
   запущен», расчёт идёт «на бэке»; по его ответу в историю добавляются строки и показывается
   зелёный снек, на каждый ФИ с ошибкой — красный (ответ 32).

Сохранить окно можно, не дожидаясь конца предварительного расчёта: он справочный. Тогда сначала
открывается подтверждение «Процесс предварительного расчета не завершен, сохранить фиксацию
ЭПС/ВБС?» (вложенное окно `FixationConfirmModal`, паспорт общий с окном).

**ЕТС** (этап Э7). Блок ЕТС карточки живёт по статусу ответа `fixationContext`:

| Статус | Вид | Карандаш | «Сохранить» |
|---|---|---|---|
| загрузка | скелетоны вместо ЕТС и Δ ЕТС | нет | алерт «Фиксация не может быть выполнена» / «Выполняется расчет значения ЕТС для ФИ»; гаснет сам, когда ЕТС посчитан |
| `OK` | значение и Δ | нет | можно |
| `EMPTY` (нет или 0) | прочерк, жёлтый треугольник, тултип «Значение ЕТС отсутствует или равно 0» | да | можно |
| `FAILED` | прочерк, красный «!», тултип «Ошибка расчета ЕТС» | да | можно (решение человека 21.10.2026) |
| `MULTIPLE` (разные ЕТС у инструментов ФИ) | до «Сохранить» или предварительного расчёта — прочерк; после — красный «!», тултип «Найдено несколько значений ЕТС для данного ФИ: …» | после | нельзя, пока не введена вручную: алерт «Фиксация не может быть выполнена» / «В инструментах, включенных в ФИ, не совпадают значения ЕТС. …» |
| введена вручную | значение, Δ от прежней ЕТС, иконка скрыта | да | можно |

Ручной ввод: карандаш → вместо значения поле с «%», вместо карандаша галочка. Галочка с пустым
полем — возврат к прежнему виду; с числом — значение подставлено, Δ посчитана, алерт скрыт; не число —
ошибка поля «Введите число». Enter в поле = галочка. Предварительный расчёт при `MULTIPLE` алерта не
показывает: иконка и карандаш появляются сами. Смена ФИ или даты сбрасывает и ручное значение.
Цвет и глиф иконки выбираются по контексту (решение человека 21.10.2026): красная
`alert-circle-filled` для ошибок, жёлтая `alert-triangle-filled` (`rof__icon--warning`) для «нет или 0».

## Обязательность заполнения (Required)

- Компонент обязателен к заполнению целиком: да — хотя бы одна карточка с ФИ, датой и типом.
- Обязательные поля внутри: ФИ, дата изменений (кроме «Первоначальная»), тип модификации.
- Что показывает, когда обязательное не заполнено: красная рамка, тултип «Обязательное поле»,
  фокус на первом незаполненном поле, окно не закрывается.
- Что отдаёт наружу: окно само запускает сохранение в `FinMetricsStore` и закрывается;
  `open()` возвращает промис — `{ started }` или `null`, если закрыли без сохранения.

## Поведение (Behavior)

### Проверка при сохранении

Порядок (вопрос 36 RE0033 открыт — порядок допущение агента):

0. **Порядок:** поля → ЕТС → правила → подтверждение → сохранение.
1. **Обязательные поля и повтор ФИ** — ошибки у полей; окно остаётся. Повтор ФИ проверяется и
   сразу при выборе: «Невозможно рассчитать более одной фиксации для одного ФИ» у второй и
   следующих карточек.
1а. **ЕТС** — пока она считается, алерт «Выполняется расчет значения ЕТС для ФИ»; разные ЕТС у ФИ без
   ручного значения — алерт «не совпадают значения ЕТС», у таких карточек появляются иконка и карандаш.
   Окно остаётся. Ошибка расчёта ЕТС и «нет или 0» сохранение не блокируют.
2. **Правила** (`FinMetricsStore.checkFixations`) — снек на каждое нарушение, окно остаётся:
   - «Первоначальная» уже есть у ФИ → «Расчет фиксации ЭПС/ВБС не выполнен» / «Для ФИ … уже рассчитана
     первоначальная фиксация ЭПС/ВБС.»;
   - другой тип, а первоначальной ещё нет → «…Измените тип модификации на "Первоначальная".»;
   - дата не позже даты последней фиксации ФИ → «Невозможно рассчитать фиксацию для ФИ … на
     ДД.ММ.ГГГГ. Дата новой фиксации должна быть позже даты последней фиксации».
3. **Предрасчёт ещё идёт** → подтверждение; «Отменить» возвращает в окно, «Подтвердить»
   сохраняет без результата предрасчёта.
4. **Сохранение**: окно закрывается, тост «Расчет фиксации ЭПС/ВБС запущен»; по ответу «бэка» —
   зелёный снек «Фиксация ЭПС/ВБС выполнена» / «ФИ: …» и красный на каждый ФИ с ошибкой «Расчет
   фиксации ЭПС/ВБС не выполнен» / «Невозможно рассчитать фиксацию для ФИ … на ДД.ММ.ГГГГ.».
   Успешные ФИ сохраняются, неуспешные — нет.

### Предварительный расчёт

`FinMetricsStore.preliminary(fiId, date)`: ответ `{ ok, … }` или `{ error }`. Нет первоначальной
фиксации — «Предварительный расчет не выполнен» / «Для ФИ "…" еще не рассчитана первоначальная
фиксация ЭПС/ВБС, предварительный расчет невозможен.»; иной сбой — алерт без описания.
Устаревший ответ (ФИ или дату уже сменили) отбрасывается.

## Данные (Data dependencies)

### API — что нужно от бэкенда

Имена методов и хуков выбирает разработка. Нужно: список ФИ сделки с признаком «есть
первоначальная фиксация» и датой последней; по ФИ и дате — ВБС до фиксации, ЕТС и Δ ЕТС;
предварительный расчёт по ФИ и дате (два варианта результата); запуск расчёта фиксации по списку
карточек (ФИ, дата, тип, комментарий, при ручном вводе — ЕТС) с ответом по каждому ФИ. Контекст
карточки несёт статус ЕТС: есть · нет или 0 · ошибка расчёта · разные у инструментов (со списком значений). Typedef: `FixationContextRsDto`,
`FixationPreliminaryRsDto`, `EirIbsvFixationRqDto` (`data/mock-fin-metrics-calc.js`).

### Параметры метки (Props)

Окно не рисуется на странице как тайл: страница вшивает скрим меткой без атрибутов и открывает
его вызовом `PostFixationModal.open()`.

| Атрибут метки | На корне компонента | Значения | Смысл |
|---|---|---|---|
| `class` | `class` (слияние) | не используется | окно вне сетки страницы |
| `state` | `data-state` | не используется | у окна одно состояние показа; состояния — у карточек |
| `mode` | `data-mode` | не используется | в просмотре окно не открывается |

## Осознанные отклонения (Deviations)

| Правило | Как сделано | Почему |
|---|---|---|
| Подвал Modal: «левые и правые кнопки одновременно не используются» | слева «+ Добавить ФИ», справа «Сохранить» | так на макете; «Добавить ФИ» — действие со списком карточек, не отмена |
