# Сводка НКЛ (TrancheNrlSummaryTile)

## Описание (Purpose)

Хедлесс-тайл раздела «НКЛ» страницы транша. До 02.11.2026 три таких тайла стояли на
странице инлайн-разметкой (`pages/Tranche.html`, строки 70–90); стали локальным компонентом
— одна папка, один фрагмент, три варианта (состав вариантов — по образцу `CounterpartiesTile`,
решение исполнителя по ТЗ RE0049, п. 2). Вид переносится с прежней разметки как есть;
единственное видимое отличие — в «Контрагенте» добавлена риск-метрика RiskMetric (решение
человека 02.11.2026).

| Вариант (`data-variant`) | Заголовок секции | Поля |
|---|---|---|
| `counterparty` | «НКЛ» | Контрагент: наименование ↔ риск-метрика |
| `balance` | «НКЛ» | Баланс · Валюта |
| `limit` | «НКЛ» | Общая сумма лимита (+ аффикс валюты) |

Все данные — **от родительского договора займа ([[НКЛ]])**, не от транша (решение человека
02.11.2026). На странице три экземпляра одного фрагмента (`id` — `tile-tr-nrl-counterparty`,
`tile-tr-nrl-balance`, `tile-tr-nrl-limit`); вариант, как у CounterpartiesTile (вариант
`instrument`), атрибутом метки не передаётся — сборщик переносит с метки только `id`,
`class`, `state`, `mode`, поэтому страницу включает скрипт тайла:

```js
PostTileTrancheNrlSummary.render(tile, {
  variant: 'counterparty',                       // 'balance' | 'limit' — у соседних экземпляров
  counterparty: LoanAgreementStore.counterparty(),
  balanceCurrency: LoanAgreementStore.get().balanceCurrency
});
```

Состояние у компонента **одно — «данные есть»** (решение человека 02.11.2026):
loading/empty/error не делаются. Место в ряду и ширину тайлов (по 360px, вне 12 колонок,
`data-off-grid`) задаёт страница — обёртка `.tr-sum` на Tranche.html, не компонент.

## Бизнес-смысл (Business context)

| Вопрос | Ответ |
|---|---|
| Зачем существует | Финансист ДИД на странице транша видит параметры родительского [[НКЛ]]-договора, не уходя со страницы: кто контрагент и насколько он проблемный, по какому балансу и в какой валюте открыт договор, какова общая сумма лимита. Транш — звено дерева продуктов «сделка → договор → транш»; сами параметры принадлежат договору, поэтому все три тайла читают запись родительской НКЛ |
| Кто заполняет и когда | Компонент только показывает. Значения — поля записи родительского договора займа: контрагент и раздел «Баланс и валюта» ведутся на странице [[НКЛ]] (там тайлы «Контрагент» — вариант `instrument` CounterpartiesTile — и «Баланс и валюта» BalanceAndCurrencyTile). Контрагент у договора один (решение человека 26.10.2026, вопрос 33 задачи RE0041) |
| Кто пользуется результатом | Финансист ДИД — на странице транша (ТЗ RE0049). Другие потребители — не решено (02.11.2026) |
| Бизнес-правила | Данные всегда от родительской НКЛ, не от транша (решение человека 02.11.2026). Рейтинг контрагента может быть не рассчитан — риск-метрика показывается без зоны (чип outline, поля поповера прочерком), строка с места не уходит. У компонента одно состояние — «данные есть»; незаполненное значение отдельного поля — прочерк на своём месте (правило ДС ReadOnlyField) |

Источники: `docs/tasks/RE0049-tranche-page.md` (решения человека 02.11.2026, п. 2 «Решения»), `apps/postrade/deals-app/data/loan-agreement-store.js` (`counterparty()`, `balanceCurrency` — ответ человека 26.10.2026, вопрос 24 задачи RE0041), `apps/postrade/deals-app/data/mock-counterparties.js` (поле `risk`), `apps/postrade/deals-app/pages/Tranche.html` (утверждённый вид тайлов)

Проверено: 02.11.2026

## Раскладка (Layout)

```
Tile headless (заголовка нет, действий нет; ширину 360px задаёт страница)
└── тело (.tile__body)
    └── .tile__grid — виден один из трёх вариантов (data-variant):
        ├── --counterparty: одна колонка — .rof «Контрагент»:
        │   значение (наименование) ↔ RiskMetric (чип у правого края)
        ├── --balance: две колонки — .rof «Баланс» · .rof «Валюта»
        └── --limit: одна колонка — .rof «Общая сумма лимита»:
            значение (сумма) + .rof__affix (код валюты)
```

## Поля (Fields)

| Поле | Смысл | Тип, единица | Источник | Обязательное |
|---|---|---|---|---|
| Контрагент | Кто является контрагентом родительского [[НКЛ]]-договора | Текст (наименование) | `LoanAgreementStore.counterparty()` → `name` (запись базы контрагентов, `mock-counterparties.js`) | не решено (02.11.2026) |

| Баланс | Баланс договора | Код + подпись (`window.LOAN_BALANCE_LABELS`, нет подписи — сам код) | `LoanAgreementStore.get().balanceCurrency.balanceCode` | не решено (02.11.2026) |

| Общая сумма лимита | Сумма лимита договора | Число, «1 234 567 890,00» — разряды неразрывным пробелом | `balanceCurrency.totalLimitAmount` | не решено (02.11.2026) |

Порядок строк — порядок отображения. Незаполненное значение — прочерк «—» на своём месте,
поле с места не уходит (правило ДС ReadOnlyField). Наименование и сумма форматируются при
выводе (`PostTileTrancheNrlSummary.formatAmount`).

## Переполнение (Overflow)

| Случай | Правило |
|---|---|
| Длинный текст в поле | Наименование контрагента — одна строка, усекается многоточием; тултип полного текста ставит рантайм ReadOnlyField (`DSTooltip.truncated`). Риск-метрика с места не уходит (чип у правого края, наименование сжимается). Код баланса, валюта и сумма — короткие значения |
