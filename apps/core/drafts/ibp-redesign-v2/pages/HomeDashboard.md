# Дашборд и профиль сотрудника (HomeDashboard)

## Назначение (Purpose)

Главная рабочего пространства сотрудника: оценить нагрузку, увидеть ближайшие встречи, срочные задачи и события клиентов. Общий профиль расположен над вкладками и остаётся видимым при переключении между дашбордом, проектами и поиском клиентов.

## Подключение (Implementation mapping)

| Артефакт | Подключение |
|---|---|
| Стиль | `pages/HomeDashboard.css`, после ДС |
| Скрипт и локальные данные | `data/home-dashboard.js`, после рантаймов ДС |
| API | `window.IBPHomeDashboard.mount({ profileHost, dashboardHost })` |
| Профиль | `profileHost` — отдельный контейнер, например `#home-profile`; имя — кнопка внутри `h2` |
| Дашборд | `dashboardHost` — содержимое панели вкладки; отдельные заголовок и подзаголовок отсутствуют по просьбе пользователя |
| События | `HomeBoard.html` вшивает `V2EventsListTile` и `V2EventDetailsTile` в два `template` через `assemble`; дашборд клонирует их в карточку и вызывает общие `LcEventsListTile.render` / `LcEventDetailsTile.render` с `embedded: true` — без собственных Tile-оболочек. EventsPage использует тот же рендер с самостоятельными Tile |
| Формы | При первом `mount` добавляются в `body`, вне скрываемых панелей |
| Фото | `refs/home-profile-anna-kim.jpg`, извлечено из исходного `mock-profile.js` |

Диаграмма встреч считает реальные записи на семь дней с 09.10.2026. Составная полоса задач показывает количество «В работе / Выполнено / Остальные» из 14 моих задач; числовая расшифровка находится в доступном названии визуализации. Исторические тренды и неподтверждённые проценты не добавлены.

## Поведение и состояния (Behavior / States)

| Триггер | Результат |

Успех — тёмный Toast сверху «Скопировано». При отказе — Toast ошибки «Не удалось скопировать», подтверждения успеха нет. Иконки рядом декоративные и не выполняют действий |

## Источники данных и допущения (Data dependencies / Assumptions)

Агентское решение по раскладке: область списка и подробностей ограничена `calc(var(--space-96) * 6)` (576px), чтобы при выборе нижней строки подробности оставались рядом. Grid растягивает части по общей высоте; цепочка `panel → Tile → body` сохраняет `min-height: 0`, скролл принадлежит штатным телам `.ds-scroll`. При рабочей области <900px общий контейнер имеет автоматическую высоту, каждая часть — `calc(var(--space-96) * 4)` (384px) с внутренним скроллом. Размеры взяты из токенов; Splitter не используется.

- Имена полей и содержимое перенесены из `dashboard-app/data/mock-profile.js`, `mock-meetings.js`, `mock-tasks.js`, `mock-news.js`. Источник вымышленный, отмечен `Source: invented` в JSDoc; контракт API отсутствует.
- События — `data/events.js` (`IBPR_EVENTS`, Source: invented 27.10.2026), тот же набор на странице «События»: проекты, сделки и клиенты — настоящие записи концепта, события вымышлены.
- Новости — общий набор `data/news.js` (`MOCK_NEWS`), тот же на странице «Новости» (27.10.2026): у первых восьми сохранены заголовки и анонсы, источники заменены доменами из макета страницы новостей (Дзен, Заря, Интерфакс, РБК), добавлены 12 новостей и полный текст.
- Демо-срез данных — **9 октября 2026**, как в исходном дашборде. Отдельная строка даты в профиле отсутствует по решению пользователя; данные не привязываются к системной дате.
- Фотография — точная локальная копия исходного портрета. При ошибке загрузки — инициалы «АК».
- Пользователь разрешил авторскую композицию вместо буквального использования тайлов ДС. Приняты крупные KPI, три равные колонки 4/4/4 для встреч, задач и новостей, сиреневые и мятные градиенты, собственные списки и минидиаграммы; значения стилей опираются на токены ДС. Ниже 1200px все три карточки занимают полную ширину. Состояния штатных компонентов не переопределяются.
- Иконки AI и календаря используют яркий `--st-dpurple`, иконки активных задач и новостей — `--primary`. Обводки карточек слабые: `color-mix` с прозрачностью, на сиреневых карточках только `--st-dpurple`, на мятных и нейтральных — `--primary` / `--secondary`; наведение не окрашивает сиреневую рамку в зелёный.
- В исходном `DSCopy` запасной `execCommand('copy')` проглатывает исключение и результат `false`. Локальный адаптер последовательно выполняет попытки, временно наблюдает результат вызова `execCommand`, сохраняет его аргументы и `this`, восстанавливает исходный метод в `finally` и не подтверждает отказ как успех. Файлы ДС не изменены.
- `HomeDashboard.scenario.mjs` проверяет три значения и Toast, отклонённый Promise, `false` и исключение fallback, восстановление метода и очередь быстрых нажатий, неактивные иконки, диалог по ФИО и отсутствие строки демо. Системный буфер и фактическая геометрия не проверяются: `page-run` исполняет DOM без браузера; цвета проверяются по CSS.
- Действия сценария вызывают `.click()` на реальных DOM-элементах с ожиданием микротактов. Текущий проигрыватель панели перед `page.click` вызывает `releasePage`: из-за двух одноимённых функций `own` в `ui.js` цель активного Tooltip ошибочно получает `data-pp-own` и исчезает из поиска проигрывателя. Прямые DOM-события сохраняют настоящие слушатели страницы и обходят этот дефект оснастки; файлы панели не изменены.
- Должность и табельный номер профиля изменены по явному запросу пользователя от 20.10.2026; внутренний employeeId сохранён отдельно от employeeNumber.
- Новые записи живут до перезагрузки и не синхронизируются с отдельными реестрами: их схемы и идентификаторы отличаются. В форме это ограничение указано до сохранения.
- Ссылки на источник есть только на странице «Новости» («Смотреть источник»): в демо — главная страница домена, не статья (решение пользователя 27.10.2026). Карточка главной показывает анонс; полный текст — на странице «Новости».
- Исходные M-0101/T-1001 отсутствуют в реестрах концепта. Строки открывают существующую страницу реестра без ложного параметра `id`.

«Новые рекомендации от AI» берёт данные из хранилища лидов (`window.LEADS`): лиды с `picked` в стадии «Рассмотрение» — тот же набор, что вкладка «Рекомендации от AI» раздела «Лиды». Порядок идей — допущение агента: приоритет клиента (`client.priorityCode`) от максимального к низкому, у идей одного клиента — порядок хранилища (см. «Открытые вопросы»); напротив каждой рекомендации показано название клиента; вся карточка ведёт на вкладку «Рекомендации от AI». Отдельных ссылок в строках и кнопки «Все рекомендации» нет. Показатели пересчитываются по событию хранилища лидов (`LEADS.on`): «Беру» / «Не беру» убирает идею из карточки. Карточка — одна ссылка с тем же hover/focus, что у остальных KPI. В AI и «Активных задачах» пояснение счётчика выровнено влево и стоит в 24px от числа (`--space-24`), включая адаптивные размеры.

## Открытые вопросы (Open questions)

Финальный маршрут карточек встреч/задач и единая схема данных главной и реестров определяются при переносе в продукт. «Топовые идеи» в карточке «Новые рекомендации от AI»: по какому признаку ИИ ранжирует сами идеи (а не клиентов) и сколько их показывать — не решено (26.10.2026); в прототипе — три по приоритету клиента. Серверного сохранения и реальной публикации новостей у концепта нет.
