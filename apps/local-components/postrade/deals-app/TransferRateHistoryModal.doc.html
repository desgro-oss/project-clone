Описание

Окно-справка страницы «Единая трансфертная ставка»: таблица периодов и ставок ЕТС договора займа. Колонки — «Дата начала», «Дата оконч.», «ЕТС, %»; строки идут от новых периодов к старым; внизу — пагинация («Показывать строк», страница из страниц, номера страниц); в подвале — «Закрыть». Окно ничего не правит и не сохраняет: открывается и в режиме просмотра.

Строка — одна процентная схема договора: период схемы и её ставка (для фиксированной — значение схемы, для плавающей — ставка на дату начала схемы). Так сделано временно: что именно должна показывать строка — не решено (см. «Открытые вопросы», 1).

Окно открывается вызовом страницы PostModalTransferRateHistory.open() без аргументов: оно само читает LoanAgreementStore.rateHistory() на каждом открытии. Для витрины open({ rows }) подставляет свои строки. Все строки хранятся в памяти окна, страницами и сортировкой управляет скрипт окна.

Поведение

Открытие

open() читает LoanAgreementStore.rateHistory() заново, сбрасывает сортировку и страницу (первая, 50 строк) и показывает окно. open({ rows }) — те же действия над переданными строками. Строк нет — «Нет данных» под шапкой, пагинация скрыта.

Сортировка

Клик по кнопке в шапке — цикл «нет → по возрастанию → по убыванию → нет». Рантайм ДС красит глиф и шлёт событие sort с { column, dir }; скрипт окна пересортировывает весь массив строк (даты сравниваются как ISO, ставка — как число) и перерисовывает первую страницу. Выбор: не data-sort-rows ДС, а событие sort — data-sort-rows переставляет только строки в DOM, то есть одной страницы, а страниц несколько.

Страницы

Номер страницы, стрелки и выбор размера страницы — DSPagination.footer; смена перерисовывает строки текущей страницы, тело таблицы прокручивается к началу.

Закрытие

«Закрыть», крестик, Esc, клик по скриму — окно закрывается, состояние не хранится (следующее открытие читает данные заново).

Открытые вопросы

  1. Что должна показывать строка — не решено (26.10.2026; вопрос 32 задачи RE0041). Вариант А (сейчас): одна строка на процентную схему — её период и ставка; у фиксированной это значение схемы, у плавающей — ставка на дату начала схемы (БИ на эту дату плюс спред). Вариант Б: плавающая схема разбивается на отрезки по датам вступления в силу изменений БИ внутри периода — в истории виден каждый шаг ставки (схема «КС + 2» на 2024 год при изменениях КС 26.07, 13.09 и 25.10 — четыре строки вместо одной). От ответа зависят подписи колонок («ставка на дату начала» или «ставка на отрезке») и подсказка в окне. Пока — вариант А, решение временное; к вопросу вернётся человек.
  2. Пара во фронтенде — не подтверждена: имя TransferRateHistoryModal по догадке (ответ человека 26.10.2026). Сверить с фронтендом.
  3. Пустое состояние. На макете «Нет данных» — тонкая строка под шапкой; у .dtable__empty ДС отступы больше, без иллюстрации. Допущение 27.10.2026: берётся ДС как есть, под шапкой, без иллюстрации (как у окон «Финансовые метрики»). Нужна ли иллюстрация — не решено.
  4. Сортировка по умолчанию. На макете не видно, по какой колонке и в каком направлении упорядочены строки. Допущение 27.10.2026: порядок стора (от новых к старым), ни одна колонка не активна.
  5. Ставка без нормирования знаков. На макете «88,888» (три знака); окно показывает значение как есть, без добавленных нулей («16,5», «4»). Сколько знаков показывать у ставки — не решено (27.10.2026).
  6. Бизнес-смысл — не решено (27.10.2026): зачем история ставок отдельным окном, кто и когда ею пользуется.
  7. Ошибка и роли. Состояние ошибки не нарисовано; какие роли видят страницу ЕТС и это окно — не решено (27.10.2026).
  8. Размеры страницы. Список размеров — штатный Pagination ДС (5, 10, 15, 20, 50, «Все»); на макете виден только «50». Какие размеры нужны продукту — не решено (27.10.2026).
