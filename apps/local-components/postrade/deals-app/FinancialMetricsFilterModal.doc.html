Описание

Окно «Фильтр» страницы «Финансовые метрики»: открывается кнопкой «Фильтр» над таблицей отчёта (TableFilter) и сужает отчёт — какие финансовые инструменты (ФИ) показывать и, по каждому из них, какие индикаторы (метрики отчёта). Окно — связанный артефакт таблицы: чип «Применено: N» и сама кнопка «Фильтр» стоят на таблице, не в окне.

Устройство — штатная модалка фильтра ДС (.modal--w6.tfm): слева вертикальный таб-раздел «Основная информация» со счётчиком, справа раздел с тем же заголовком. Раздел один.

  • Финансовые инструменты — первое поле: мультивыбор с чипами в поле. Варианты — ФИ, которые есть в сделке и в этом отчёте (приходят в indicators). Пустое поле — фильтра по ФИ нет.
  • По одному полю индикаторов на каждый выбранный ФИ. Подпись поля — имя ФИ, значения — индикаторы этого ФИ (мультивыбор с чипами и поиском по набранному). Пустое поле — «все индикаторы» ФИ. Убрали ФИ из первого поля — его поле индикаторов исчезает вместе с выбором; добавили — поле появляется следом, в порядке выбора.
  • Счётчик на табе раздела — число выбранных ФИ (ответ 29, 21.10.2026: «число полей ФИ, включённых в фильтр»). Ноль — бейдж скрыт.
  • Подвал: «Очистить фильтр» сбрасывает поля окна и окно не закрывает; «Применить» закрывает окно и отдаёт значение странице.

Окно ничего не хранит и не знает о вкладках: при каждом открытии страница отдаёт ему ФИ и индикаторы нужной вкладки и текущий фильтр этой вкладки. Окно — компонент без сети и без стора; разбор значения и перерисовка таблицы — на странице.

Значение фильтра — FmFilterValue: { fiIds: string[], metrics: { [fiId: string]: string[] } }. metrics[fiId] — коды выбранных индикаторов ФИ; нет ключа или пустой список — все индикаторы. Пустой фильтр — { fiIds: [], metrics: {} }. При «Применить» в значение попадают только ФИ из indicators и только коды, которые есть у своего ФИ.

Общий ли фильтр у вкладок или свой и влияет ли фильтр одной вкладки на другую — не решено (допущение: свой у вкладки)

Все состояния рядом

Каждая комбинация состояния данных и режима прав — копия фрагмента виджета.

Обязательность заполнения

  • Компонент обязателен к заполнению целиком: нет — применить пустой фильтр можно, он равен сбросу.
  • Обязательные поля внутри: нет, см. «Поля».
  • Что показывает, когда обязательное не заполнено: не применимо.
  • Что отдаёт наружу (признак для экрана или формы): FmFilterValue по «Применить»; null, если окно закрыли без применения. Число параметров для чипа «Применено: N» считает страница по значению; окно отдаёт его же в бейдже раздела — число выбранных ФИ.

то же заполнение, что в open, но окно остается на месте, без слоя поверх страницы; прежний сеанс сбрасывается. Для витрины локальных компонентов, страница его не зовет; окон на витрине несколько, текущим становится то, в которое зашли (pointerdown, focusin, keydown)
open({ title?, indicators, value }) → Promise<FmFilterValue \| null>
открывает окно. title — заголовок (по умолчанию «Фильтр»). indicators — [{ fiId, fiName, currencyCode, metrics: [{ code, name }] }]. value — текущий фильтр вкладки. Ответ: значение по «Применить» (ФИ только из indicators, коды только своего ФИ) или null
empty() → FmFilterValue
пустой фильтр { fiIds: [], metrics: {} }
normalize(value, indicators)
приводит значение к ФИ вкладки: убирает чужие ФИ и коды, повторы, пустые списки индикаторов

Рантайм поля (DropdownList) привязывается без режима multiple: иначе в этом режиме пробел в поле выбирал бы строку списка, а не писался в запрос. Чипы, поиск по набранному и состояние выбора держит скрипт окна.

Открытые вопросы

Раздел не удаляется. Вопросы 1–4 — вопрос 11 задачи RE0033 в части окна; ответ вписывает человек.

  1. Состав индикаторов по типам ФИ — полного списка нет: у разных типов ФИ (кредит, акции, РЕПО, дебиторская задолженность, доп. доходность) и у разных вкладок (МСФО, РСБУ, KPI) индикаторы свои, человек дополнит (ответ 11, 20.10.2026). В прототипе — демо-каталог FIN_METRICS_CATALOG, состав МСФО придуман по чипам макета.
  2. Общий фильтр или свой у вкладки — по ответу 30 индикаторы у вкладок свои и чип «Применено» у каждой свой; допущение: значение фильтра хранится по вкладке и окно получает значение нужной вкладки (допущение 21.10.2026). Не решено, должен ли фильтр одной вкладки влиять на другую (например, один и тот же ФИ в МСФО и в РСБУ).
  3. Сохраняется ли фильтр между заходами — не решено (20.10.2026). Окно ничего не хранит; в прототипе значение живёт на странице, пока она открыта (допущение 21.10.2026).
  4. «+99» в чипах фильтра — снято ответом 30 (21.10.2026): «+99» уходит вместе с чиплистом, на таблице один чип «Применено: N». Вопрос оставлен в записи: что он означал на макете, так и не названо.
  5. Что считает счётчик раздела. Ответ 29 (21.10.2026): число полей ФИ, включённых в фильтр; в окне это число выбранных ФИ (на макете при трёх выбранных ФИ стоит «9» — это число из трёх не получается). Допущение: считается число ФИ, а не число чипов индикаторов; то же ли число видно в чипе «Применено: N» на таблице — вопрос к странице. Не закрыто.
  6. ФИ, который выбран без индикаторов, и ФИ, у которого выбраны все индикаторы — равны по смыслу («все индикаторы»), но в значении выглядят по-разному: нет ключа в metrics или список всех кодов. Допущение: окно отдаёт ровно то, что выбрано, ничего не сворачивая (21.10.2026); нужно ли сворачивать «выбраны все» в «нет ключа» — решение человека.
