Описание

История фиксаций ЭПС/ВБС по ФИ сделки. Карточка «История фиксаций» с переключателем вида в шапке: «По ФИ» — группа на каждый ФИ (название и валюта), в группе его фиксации; «По дате» — один плоский список всех фиксаций с колонкой «Наименование ФИ» второй. Вид по умолчанию — «По ФИ». Фильтра у таблицы нет.

В колонке «№» — порядковый номер строки (ответ 13 задачи): в «По ФИ» внутри группы, в «По дате» сквозной; номер фиксации ФИ не показывается. Порядок строк по умолчанию — дата изменений по возрастанию; кнопка сортировки даты в шапке идет по кругу «нет → по возрастанию → по убыванию → нет» (нет — порядок по умолчанию, то есть возрастание). Сортировка и свернутые группы запоминаются и не сбрасываются при смене вида.

Корзина стоит у каждой строки и активна у всех, тултипа у нее нет (ответ 33 задачи). Сам виджет ничего не удаляет: клик по корзине отправляет событие fmfixationaction, а решает страница — у непоследней фиксации показывает снек ошибки, у последней открывает подтверждение и после него удаляет и показывает тост. Пока идет пересчет метрик, корзины выключены атрибутом disabled; в режиме просмотра колонки «Действия» нет в разметке вовсе.

Новая строка появляется, когда приходит ответ бэка, вместе со снеком о выполненной фиксации (ответ 32); виджет перерисовывается целиком из списка, который ему передала страница. Что видно, пока фиксация считается, — вопрос 2.

Вид («По ФИ» / «По дате») переключает SegmentControl ДС размера XS в действиях шапки карточки (tile__actions). Карточка «История фиксаций» — содержимое вкладки «Фиксации ЭПС/ВБС» страницы «МСФО · РСБУ · KPI · Фиксации ЭПС/ВБС»; своих вкладок внутри карточки нет, второй уровень навигации не нужен.

Где виджет стоит на странице и какую высоту ему дает страница — решает страница, не он.

Удалить можно только последнюю фиксацию ФИ; у не последней клик по корзине даёт ошибку «Вы можете удалить только последнюю фиксацию для каждого ФИ» (ответ человека 21.10.2026). Что такое «последняя» — в прототипе с самой поздней датой изменений (допущение 21.10.2026); при равных датах и для единственной «Первоначальной» — не решено. Все состояния рядом

Каждая комбинация состояния данных и режима прав — копия фрагмента виджета.

Обязательность заполнения

  • Компонент обязателен к заполнению целиком: нет — он показывает данные, ничего не заполняет.
  • Обязательные поля внутри: Не применимо — полей ввода нет.
  • Что показывает, когда обязательное не заполнено: Не применимо.
  • Что отдаёт наружу (признак для экрана или формы): событие fmfixationaction (см. «Поведение»); признака для формы нет.

Открытые вопросы

Решение человека 29.09.2026: вопросы не закрываются догадкой и не удаляются, пока человек не разберёт каждый; ответ записывается у вопроса с датой. Вопросы 1–2 перенесены из задачи RE0033 (docs/tasks/RE0033-deal-financial-metrics.md, вопросы 19 и 32).

  1. Права (RE0033, вопрос 19): кто фиксирует, удаляет фиксацию, выгружает отчет — оставлено открытым (21.10.2026). В прототипе (допущение 21.10.2026): удалять может тот, кто может править сделку по статусу, и роль с правом на расчет; иначе view без колонки «Действия» (на странице — сценарий панели ?fmMode=view).
  2. Что видно, пока фиксация считается, и при ошибке расчета (RE0033, вопрос 32): строка появляется, когда приходит ответ бэка, вместе с зеленым снеком о выполненной фиксации (ответ 21.10.2026); что видно, пока расчет идет (скелетон строки, отдельное состояние таблицы, ничего), и что при ошибке «Расчет фиксации ЭПС/ВБС не выполнен» — оставлено открытым. В прототипе сейчас: строка появляется по ответу расчёта фиксации (окно собрано в Э6), промежуточного вида нет; вид ошибки получения истории не нарисован.
  3. Что такое «последняя» фиксация. В прототипе — с самой поздней датой изменений у ФИ (допущение 21.10.2026). Не решено: что при равных датах, считает ли признак бэкенд или клиент, можно ли удалить последнюю фиксацию «Первоначальная», если по ФИ нет других.
  4. Первый клик по сортировке даты. По умолчанию строки идут по возрастанию, а кнопка в состоянии «нет» (так ведет себя рантайм ДС: нет → по возрастанию → по убыванию → нет), поэтому первый клик строки не меняет. Допущение 21.10.2026 по заданию; альтернатива — стартовать с «по возрастанию»; нужен ли ответ человека — не решено.
  5. Что меняется после удаления фиксации. В прототипе из отчетов МСФО, РСБУ и KPI уходит колонка даты этой фиксации, если на нее нет другого события (так строит даты мок); пересчет метрик не запускается и не требуется. Не решено: влияет ли удаление на значения отчетов и метрик, нужен ли пересчет, как это видит пользователь.
  6. Колонка «Комментарий», ширины колонок, единицы значений (проценты — число без знака «%», суммы — без кода валюты) и длинные значения — по макету не уточнены; ширины колонок в прототипе — допущение 21.10.2026, определяются по размеру заголовков и значений.
  7. Счетчики у сегментов переключателя («По ФИ» · «По дате») — на макете нет, в прототипе нет; нужны ли (например, число ФИ или фиксаций) — не решено (21.10.2026).
  8. Вид по умолчанию и его запоминание. По умолчанию — «По ФИ» (первая на макете; допущение 21.10.2026). Запоминается ли выбор между заходами — не решено.
  9. Закрепление первой колонки, настройка таблицы, ошибка получения истории — те же вопросы, что у FinancialMetricsTable (паспорт, «Открытые вопросы»); отдельных ответов для истории фиксаций нет (21.10.2026). Закрепленных колонок в прототипе нет: таблица шире экрана прокручивается целиком.
