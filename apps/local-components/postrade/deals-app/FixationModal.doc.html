Описание

Окно фиксации ЭПС/ВБС. Пользователь выбирает финансовые инструменты (ФИ) сделки, дату изменений и вид модификации, при желании смотрит предварительный расчёт и сохраняет — расчёт фиксации запускается, а результат попадает в историю фиксаций страницы «Финансовые метрики».

Окно — список карточек фиксации, по одной на ФИ; карточек от одной до сколько нужно (кнопка «+ Добавить ФИ»). Карточка — подчасть FixationModalTile.

Базовый сценарий (этап Э6 RE0033):

  1. Окно открывается с одной пустой карточкой. Предварительный расчёт недоступен, «⊖» (удалить карточку) выключена — карточка единственная.
  2. Выбраны ФИ и дата изменений → подтягиваются «ВБС до фиксации» и ЕТС с Δ ЕТС; предварительный расчёт становится доступен.
  3. «Предварительный расчет» → на кнопке лоадер, затем кнопку заменяет чип «Расчет выполнен», блоки «Несущественная» и «Существенная модификация» заполняются. Тип модификации можно выбрать и до расчёта.
  4. Сброс ФИ или даты сбрасывает предварительный расчёт и данные карточки («ВБС до фиксации», ЕТС); тип и комментарий остаются.
  5. «Первоначальная» — дата очищается и блокируется, предварительный расчёт блокируется, значения блоков — прочерк.
  6. «Сохранить» — проверка (ниже); верно → окно закрывается, тост «Расчет фиксации ЭПС/ВБС запущен», расчёт идёт «на бэке»; по его ответу в историю добавляются строки и показывается зелёный снек, на каждый ФИ с ошибкой — красный (ответ 32).

Сохранить окно можно, не дожидаясь конца предварительного расчёта. Тогда сначала открывается подтверждение «Процесс предварительного расчета не завершен, сохранить фиксацию ЭПС/ВБС?» (вложенное окно FixationConfirmModal, паспорт общий с окном).

Вопрос
Ответ
Зачем существует
Зафиксировать ЭПС и ВБС по одному или нескольким ФИ сделки на дату изменений с видом модификации (первоначальная, несущественная, существенная): расчёт фиксации запускается, результат попадает в историю фиксаций страницы «Финансовые метрики». Предварительный расчёт справочный: по его результату пользователь решает, какой тип модификации выбрать; самому предварительному расчёту тип не нужен (ответ человека 21.10.2026)
Кто заполняет и когда
Пользователь с правом на расчёт и фиксацию, в режиме правки: в просмотре (по статусу сделки или по роли) кнопки «Фиксация ЭПС/ВБС» выключены или не показываются, окно не открывается. Окно открывают с тайла «Финансовые метрики» страницы сделки и из шапки страницы «Финансовые метрики» (аналитик ДИД). Первоначальную фиксацию делают для нового ФИ, по которому её ещё нет. Кто вправе фиксировать — не решено (21.10.2026)
Кто пользуется результатом
История фиксаций на вкладке «Фиксации ЭПС/ВБС» страницы «Финансовые метрики» («По ФИ» и «По дате», счётчик вкладки — число фиксаций): новые строки появляются, когда приходит ответ расчёта; тайл «Финансовые метрики» перерисовывается по событию стора. Кто читает фиксации дальше — не решено (23.10.2026)
Бизнес-правила
Одна фиксация — один ФИ, повтор ФИ в окне запрещён. «Первоначальная» — дата не вводится; если у ФИ она уже есть, вторую рассчитать нельзя; если её нет, другой тип выбрать нельзя («Измените тип модификации на Первоначальная»). Дата новой фиксации должна быть позже даты последней фиксации ФИ. Фиксацию считает «бэк»: успешные ФИ сохраняются, неуспешные нет, на каждый ФИ с ошибкой красный снек. Предварительный расчёт возможен только у ФИ с первоначальной фиксацией. Значение ЕТС: нет, ноль или ошибка расчёта сохранению не мешают (значение вводят вручную), разные ЕТС у инструментов ФИ — сохранить нельзя, пока значение не введено вручную. Как называется ЕТС, когда появляется «ВБС до фиксации» и что сбрасывает смена ФИ или даты — не решено (21.10.2026)

Все состояния рядом

Каждая комбинация состояния данных и режима прав — копия фрагмента виджета.

Обязательность заполнения

  • Компонент обязателен к заполнению целиком: да — хотя бы одна карточка с ФИ, датой и типом.
  • Обязательные поля внутри: ФИ, дата изменений (кроме «Первоначальная»), тип модификации.
  • Что показывает, когда обязательное не заполнено: красная рамка, тултип «Обязательное поле», фокус на первом незаполненном поле, окно не закрывается.
  • Что отдаёт наружу: окно само запускает сохранение в FinMetricsStore и закрывается; open() возвращает промис — { started } или null, если закрыли без сохранения.

Поведение

Проверка при сохранении

Порядок (вопрос 36 RE0033 открыт — порядок допущение агента):

  1. Порядок: поля → ЕТС → правила → подтверждение → сохранение.
  2. Обязательные поля и повтор ФИ — ошибки у полей; окно остаётся. Повтор ФИ проверяется и сразу при выборе: «Невозможно рассчитать более одной фиксации для одного ФИ» у второй и следующих карточек. 1а. ЕТС — пока она считается, алерт «Выполняется расчет значения ЕТС для ФИ»; разные ЕТС у ФИ без ручного значения — алерт «не совпадают значения ЕТС», у таких карточек появляются иконка и карандаш. Окно остаётся. Ошибка расчёта ЕТС и «нет или 0» сохранение не блокируют.
  3. Правила (FinMetricsStore.checkFixations) — снек на каждое нарушение, окно остаётся:
    • «Первоначальная» уже есть у ФИ → «Расчет фиксации ЭПС/ВБС не выполнен» / «Для ФИ … уже рассчитана первоначальная фиксация ЭПС/ВБС.»;
    • другой тип, а первоначальной ещё нет → «…Измените тип модификации на "Первоначальная".»;
    • дата не позже даты последней фиксации ФИ → «Невозможно рассчитать фиксацию для ФИ … на ДД.ММ.ГГГГ. Дата новой фиксации должна быть позже даты последней фиксации».
  4. Предрасчёт ещё идёт → подтверждение; «Отменить» возвращает в окно, «Подтвердить» сохраняет без результата предрасчёта.
  5. Сохранение: окно закрывается, тост «Расчет фиксации ЭПС/ВБС запущен»; по ответу «бэка» — зелёный снек «Фиксация ЭПС/ВБС выполнена» / «ФИ: …» и красный на каждый ФИ с ошибкой «Расчет фиксации ЭПС/ВБС не выполнен» / «Невозможно рассчитать фиксацию для ФИ … на ДД.ММ.ГГГГ.». Успешные ФИ сохраняются, неуспешные — нет.

Предварительный расчёт

FinMetricsStore.preliminary(fiId, date): ответ { ok, … } или { error }. Нет первоначальной фиксации — «Предварительный расчет не выполнен» / «Для ФИ "…" еще не рассчитана первоначальная фиксация ЭПС/ВБС, предварительный расчет невозможен.»; иной сбой — алерт без описания. Устаревший ответ (ФИ или дату уже сменили) отбрасывается.
