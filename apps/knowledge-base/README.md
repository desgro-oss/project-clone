# База знаний

Колонка «База знаний» на хабе проектов (`project.json → knowledgeBase`). Здесь
лежит знание о предметной области, которое не принадлежит ни одному экрану и
компоненту. Сейчас — один пункт: **Глоссарий и термины**.

Это не приложение и не экран: страницы собирает `node .agents/tools/kit-build.mjs`
(гейт, шаг `kit`), руками их не правят.

## Глоссарий

| Что | Где |
|---|---|
| Страница на хабе (генерат) | `glossary/index.html` |
| Термин — один файл | `glossary/terms/<Термин>.md` |

Файл термина: имя файла — сам термин; в шапке `aliases: [...]` — другие формы слова
(«деск», «дески»); в теле — определение и строка «Источники: …». Определения нет
в источниках — пишется `не решено (ДД.ММ.ГГГГ)`, а не догадка.

## Ссылки на термин

В паспортах виджетов и спеках страниц слова предметной области не объясняются, а
отсылаются на глоссарий вики-ссылкой, как в Obsidian:

- `[[Деск]]` — ссылка с названием термина;
- `[[Деск|деска]]` — та же ссылка с другим текстом (падеж, число);
- имя ищется по названию файла и по `aliases`, регистр не важен.

Obsidian находит файл по имени сам (откройте корень репозитория как хранилище).
На страницах витрины ссылка становится переходом на плитку термина в глоссарии.
Ссылка на несуществующий термин — дефект КТ7 шага `kit`.

Новый термин — новый файл в `glossary/terms/`, затем `node .agents/tools/kit-build.mjs`.

## Пополнение по ходу работы

Термины и «Бизнес-смысл» паспортов и спек пополняются по ходу других задач. Как — скилл
`.agents/skills/business-context/SKILL.md`; что ещё не решено —
`node .agents/tools/business-context.mjs --unresolved` (`--find`, `--uses`, `--terms`); ревизия устаревшего — `--stale` и `--mark`, команда `/know-sweep`.
