# Иллюстрации: варианты, правки, тёмная пара

Иллюстрация — не картинка «от руки», а **сцена**: набор готовых изометрических предметов (мотивов) в одной из
раскладок. Модель не считает координаты и порядок слоёв: она выбирает раскладку и мотивы, генератор расставляет,
масштабирует, проверяет числами и собирает тёмную пару. Правка человека — правка описания (или кода мотива) и строка
в журнале, а не ручная правка SVG.

| Что | Где |
|---|---|
| Правила стиля (холст, проекция, палитра, прозрачности, мотивы, чек-лист) | `design-system/foundations/Illustrations/illustration-style.json` |
| Запуск и параметры | `.agents/skills/illustration-design/tooling/illustration-gen.mjs` (формат — в его шапке) |
| Каталог мотивов | `tooling/motifs.mjs`; список с паспортами — `illustration-gen.mjs --motifs` |
| Раскладки и основания | `tooling/layout.mjs` (`solo`, `pair`, `trio`, `diagonal`; `none`, `slab`, `disc`, `radar`) |
| Автопроверка | `tooling/check.mjs`; пороги — `references/check-thresholds.json` (генерат `--calibrate` по 32 эталонам ДС) |
| Движок: проекция, примитивы, вывод SVG, тёмная пара | `tooling/lib.mjs` |
| Темы | `tooling/themes/<тема>.json` (описание сцен — по умолчанию) и `<тема>.mjs` (код — утверждённые «Радар», «Фонды») |
| Эталоны и что из них взято | `references/reference-catalog.md` |
| Журнал правок человека и усвоенные правила | `references/edits-log.md` |
| Результат (только он) | `tmp/<имя>/`: `<имя>.svg`, `<имя>-dark.svg`, `index.html` — вкладки по темам; один вариант — одна строка: светлый рисунок и тайл ДС, справа тёмные; итог проверки у заголовка; `ds/` — копия стилей и шрифтов ДС, обзор самодостаточен и открывается из архива одной папки; `архив/` — сцены с `keep: false` |

В `tmp` ничего, кроме результата, не лежит: ни кода, ни журнала. Эталоны (`design-system/assets/illustrations/*`) только читаются.

## Процедура

1. **Прочитать** «Усвоенные правила» в журнале и каталог эталонов: что в продукте уже рисуют и каким составом (почти везде один главный предмет). `illustration-gen.mjs --motifs` — какие мотивы есть.
1а. **Спросить человека, что изображать**, если суть карточки не названа: что делает раздел, какие ассоциации, что главное (по центру), какие детали пояснят суть (галочка, лупа, часы…). Без этого образы выходят случайными (журнал: правила И11–И12). Поясняющие детали — часть мотива-композиции, а не отдельные фигуры.
2. **Описать сцену** в `themes/<тема>.json` (образец — `themes/primer.json`). Тема: `id`, `title`, `dir`, `order`, `tile { title, desc }`. Сцена — одна запись:
   ```json
   { "file": "fonds-9-trio", "keep": true, "layout": "trio", "base": "none",
     "hero": { "motif": "building" }, "mid": { "motif": "docStack", "opts": { "n": 6 } }, "small": { "motif": "cube" } }
   ```
   Роли: `hero` — главный (в центре), `mid` и `small` — по бокам; какие нужны, определяет раскладка (`--motifs` печатает). Размеры 1 : 0,6 : 0,4 по видимой площади, позиции, зазоры и порядок «дальние первыми» считает генератор. Не хватает мотива — только тогда пишется код (шаг 6).
3. **Собрать:** `node .agents/skills/illustration-design/tooling/illustration-gen.mjs --out tmp/<имя>`. Тёмная пара собирается всегда — это скрипт, токенов не тратит.
4. **Читать `ВЕРДИКТ` и причины.** Сцена из описания с нарушением — `FAIL` с числами («объект small: 2,6 % видимой площади, не меньше 5,0 %»). Править **параметры описания**, не геометрию: другой мотив, другая раскладка, `opts`, основание. Только проверки: `--check` (файлов не пишет).
5. **Посмотреть глазами, если картинки читаются.** Снимок `index.html` в headless-браузере (адрес вкладки — `#<тема>`) в папку scratchpad. Проверка числами обязательна и без картинки; картинка ловит то, что числами не измерить (вкус, читаемость мотива).
6. **Нужного мотива нет** — добавить его в `tooling/motifs.mjs` по образцу соседних: функция `draw(s, opts)` в натуральном размере по центру (0, 0), основание на z = 0, паспорт `title`, `depicts`, `from`, `fp`. Примитивы — таблица ниже. Цвета — только роли палитры (`COL.*`, `L('<роль>')`).
7. **Показать человеку обзор** (`tmp/<имя>/index.html`), честно назвать слабые места. У варианта рядом с рисунком — NavTile ДС (светлый и тёмный) с текстом `tile`: **заголовок — как в задаче** («Фонды», `Фонд "Радар"`), **описание придумать из контекста**, одна-две строки, не длиннее 50 знаков (генератор не пропустит длиннее: NavTile обрежет его многоточием).
8. **Правки.** Каждый комментарий: правка описания или кода → пересборка → строка в `references/edits-log.md`; общее правило — в «Усвоенные правила». Отвергнутые варианты — `keep: false` (в архив, не удалять).

## Что проверяет автопроверка

| Правило | Условие | Для чего |
|---|---|---|
| Палитра, запреты | только цвета палитры стиля; нет обводок, градиентов, фильтров, текста | Стиль ДС |
| Рисунок | центр и размер рамки, доля закрашенного — в пределах эталонов ДС (у сцены с основанием — только верхняя граница доли) | Не крошечный, не в углу, не пустой и не забитый |
| Главный объект | заметно крупнее остальных (≥ 1,5×) | Один акцент |
| Мелочь | у каждого объекта ≥ 5 % видимой площади объектов | Без россыпи мелких предметов (И2) |
| Видимость | каждый объект виден не меньше чем на половину | Никто не спрятан за соседом |
| Основания | не пересекаются; объектов не больше трёх | Раскладка не сломана |

Утверждённые сцены кодом (`.mjs`) получают те же замечания как `ВНИМАНИЕ` и не роняют сборку: их принял человек.
Проверка живёт внутри инструмента, в общий гейт проекта не встроена.

## Запуск

| Что | Команда (из корня репозитория) |
|---|---|
| Все темы | `node .agents/skills/illustration-design/tooling/illustration-gen.mjs --out tmp/<имя>` |
| Одна тема | `… --out tmp/<имя> --theme fonds` |
| Темы и сцены | `… --list` |
| Каталог мотивов и раскладок | `… --motifs` |
| Только проверить | `… --check` · рисунок любого SVG: `… --check-svg <файл.svg>` |
| С архивными сценами | `… --out tmp/<имя> --all` (архивные — в `tmp/<имя>/архив/`) |
| Без тёмной пары | `… --no-dark` |
| Пересобрать пороги по эталонам | `… --calibrate` (эталоны только читаются) |
| Самопроверка | `… --selftest` (плохие сцены обязаны упасть, хорошие пройти) |

## Примитивы `lib.mjs` (для новых мотивов)

Мир — оси x, y (в плоскости пола) и z (вверх); проекция изометрическая, `dy = dx · 0,577`.
Все примитивы принимают сцену `s` первым аргументом; положение и размер мотива задаёт раскладка через `Scene.frame`.

| Примитив | Что рисует |
|---|---|
| `box(s, x, y, z, w, d, h, COL.cube, { edge, glass:[a,b], stripes })` | Параллелепипед: верх, левая, правая грани, скос ребра, стеклянный блик, полосы на левой грани |
| `cyl(s, cx, cy, z, r, h, COL.coin)` · `coinStack(…)` | Монета и стопка монет |
| `prism(s, pts, z, h, цвета)` | Призма по многоугольнику (шестерня, зубцы) |
| `sectorPrism(s, cx, cy, z, r0, r1, a0, a1, h, цвета, explode)` | Сектор кольца с высотой — кусок объёмного «пончика» |
| `ring`, `sector`, `disc`, `sweepTrail` | Кольцо, сектор, круг, развёртка со шлейфом (плоские, на горизонтальной плоскости) |
| `beamCone`, `beamWedge` | Конус-луч из точки и клин-луч (полупрозрачные слои) |
| `wallRect`, `wallLine`, `wallDisc` | Плоские виджеты на вертикальной грани (экран, карточки, график, кольцо) |
| `topLines` | Строки «текста» на верхней грани |
| `extrude`, `circ`, `ept`, `arcE` | Выдавленный диск и низкоуровневые эллипсы/дуги |
| `poly3`, `pv` | Многоугольник в мире и проекция точки |

## Правила

- **Ничего не выдумывать:** цвета и прозрачности — только из `illustration-style.json`; нет нужного — спросить.
- **Не менять файлы ДС** без явной просьбы человека. Генератор и скилл живут в `.agents/`; готовые SVG в `design-system/assets/illustrations/` попадают только по решению человека и вместе с `-dark` (карта и список `DARK` — `design-system/tools/illustration-dark.mjs`, `Illustrations.js`).
- **Утверждённый рисунок не менять:** мотивы `monitor`, `docStack` и утверждённые сцены `radar`, `fonds` правятся только по комментарию человека.
- **Композиция:** мало и крупно, одна главная фигура (правила И2–И9 в журнале).
- **Результат — в `tmp/<имя>/`**, в репозиторий не коммитится; не коммитить и не пушить без просьбы человека.
- **Без имён вендоров, ассистентов и моделей** в содержимом файлов (сторож `vendor-scan`).
