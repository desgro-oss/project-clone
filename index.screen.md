# Хаб проектов

## 1. Назначение

Служебная стартовая страница рабочего пространства: одна точка входа в
документацию дизайн-системы, базу знаний и работу команд — проекты, концепты и
спецификации на разработку. Не экран продукта — в разработку не уходит.

| Блок | Что в нём | Где |
|---|---|---|
| Общий ряд | то, что не принадлежит команде: документация ДС, глоссарий базы знаний, витрина локальных компонентов раздела «Общие» | `design-system/` · `apps/knowledge-base/glossary/` · `apps/local-components/common/` |
| Проекты | витрина локальных компонентов команды первой строкой; приложения трека `product`: соответствуют настоящей системе, строго на компонентах ДС; карта экранов проекта (`project.json → screenMap.maps`) | `apps/<раздел>/<id>/`, `track: "product"` в `app.json` · карта — `apps/screen-map/<раздел>/index.html` |
| Концепты | приложения трека `rnd`: концепты на ДС; кастомные решения — только если ТЗ прямо их просит. Версии одного концепта — одна плитка | `apps/<раздел>/drafts/<id>/`, `track: "rnd"` в `app.json` |
| Спецификации на разработку | сценарии Post и других команд для разработки (RE0016); версии одного сценария — одна плитка | `<приложение>/refs/<Spec>/<Spec>.dev-spec.md` |

**Роль пользователя:** дизайнер, ведущий проекты и концепты на ДС.

Раскладка — по концепту `apps/postrade/drafts/hub-redesign/` (24.10.2026); его паспорт
`Hub.screen.md` описывает ту же раскладку на снимке данных.

## 4. Структура контента

Контентная область — `.home-wrap` с фоновой иллюстрацией, внутри `.tile-group`
(зазор 16px между блоками, сетка 12 колонок у рядов Tile).

| № | Блок | Компонент | Колонок из 12 | Содержимое |
|---|---|---|---|---|
| 1 | Общий ряд | Tile `--headless`, по одному на запись | 3 (`col-3`), ≤1240px — 12 (`colw-12`) | одна строка Entity M `--interactive` в `.entity-list`: записи `group: 'ds'` без витрины, затем `group: 'kb'`, затем витрина раздела, который не команда (Общие) |
| 2 | Выбор команды | SegmentControl M | по ширине контента | Post · Pre · IB · Core; Badge `--text --s` — число плиток команды (проекты + концепты + спецификации); раздел вне списка, где есть записи, — отдельным сегментом в конце. Изначально выбрана Post |
| 3 | Проекты | Tile | 4 (`col-4`), ≤1240px — 12 | счётчик Chip S у заголовка; `.entity-list` Entity M: витрина раздела первой строкой, затем записи `group: 'projects'` раздела (приложения и карта экранов) |
| 4 | Концепты | Tile | 4, ≤1240px — 12 | счётчик Chip S у заголовка; в `tile__actions` SegmentControl XS «Актуальное N / Архив N»; под ним стопка плиток `.tile-stack` выбранной полки |
| 5 | Спецификации на разработку | Tile | 4, ≤1240px — 12 | счётчик Chip S у заголовка; стопка плиток по тем же правилам, без полок |

Колонки не прячутся: у команды нет записей — в колонке EmptyState M. Вертикальный скролл —
у контентной области, крошки залипают. Горизонтального скролла нет.

**Раздел записи** — второй сегмент пути `apps/<раздел>/…`; у карты экранов и витрины
локальных компонентов — третий (`apps/screen-map/<раздел>`, `apps/local-components/<раздел>`).
Раздел спеки — первый сегмент её `module`.

**Плитка концепта или спецификации.** Одна версия — карточка (`tile--card`, корень `<a>`, ссылка
на страницу версии): заголовок, описание, справа в шапке Chip S с подписью версии; за чипом зарезервировано место под стрелку аккордеона (невидимый `ibtn--m`, `aria-hidden`), правое поле карточки добрано до поля аккордеона (+4px), чтобы чипы карточек и аккордеонов стояли по одной линии. Версий
несколько — аккордеон (`tile--accordion`, свёрнут): заголовок, описание, справа Chip «N версий»
перед стрелкой; в теле `.entity-list` версий, новая первой — подпись версии и описание.
Запись без `concept` — своя плитка-карточка с названием
приложения и без подписи версии. Концепты связывает поле `concept` в `app.json` (название
концепта; ему в пару — `version`, подпись версии: `v3`); версии сортируются по подписи как
по числам, от новой к старой.

**Полки.** Полка группы — полка её последней версии (`shelf` в `app.json`; без поля — «Актуальное»).
Пустая полка — EmptyState M. Спецификации полок не имеют.

**Каталог спек** (приложение со спеками, `dev-specs`) в колонку концептов не попадает —
он и есть колонка «Спецификации на разработку»; в меню остаётся пунктом.

**Строка (Entity M)** общего ряда и проектов:

| Слот | Значение | Класс |
|---|---|---|
| Контейнер строк | список, зазор 16px | `.entity-list` |
| Корень | ссылка на стартовую страницу (`href` реестра) | `a.entity.entity--interactive` |
| Ведущий | глиф `icon` реестра | `.entity__lead > .entity__icon` |
| Header | папка записи (`root`; у ДС — папка стартовой страницы) | `.entity__header` |
| Label | название (`title`), усечение в строку + тултип | `.entity__label--truncate` + `data-tooltip-truncated="only"` |
| Subheaders | описание (`desc`), одна строка | `.entity__subs--single > .entity__subs-list` |

Строка версии в аккордеоне — тот же Entity M без Header: Label — подпись версии, Subheaders —
описание; метки архива у версии нет — полку показывает сегмент колонки.

## 5. Поведение

| Триггер | Результат |
|---|---|
| Клик по строке, карточке, строке версии | переход на стартовую страницу записи |
| Клик по пункту меню записи | то же |
| Выбор команды кликом, стрелками, Home / End | колонки перерисовываются для команды; аккордеоны свёрнуты, полка — «Актуальное»; выбор, фокус и индикатор ведёт рантайм ДС (`DSTabs.segment`, коллбэк `onChange`) |
| Выбор полки концептов | показ стопки выбранной полки; тот же рантайм |
| Клик по шапке аккордеона | раскрывается или сворачивается: экран передаёт клик стрелке `.tile__toggle` (рантайм Tile ведёт `aria-expanded`); клик по самой стрелке, ссылке или кнопке не дублируется; курсор у шапки — указатель (`[data-acc-header]`). Выбор не запоминается |
| Наведение на строку | фон `--bgtable-row-hover`; подложка стыкуется с соседней строкой, не накрывая её (`.entity-list`) |
| Бургер / пин панели | rail ↔ drawer ↔ fixed (рантайм NavPanel) |
| Рабочая область ≤ 1240px | плитки рядов в одну колонку (`colw-12`) |
| Новое приложение (`app.json` + пересборка `hub.js`) | строка и пункт меню появляются без правки страницы |
| Новая версия концепта (`concept` + `version` в `app.json`) | карточка становится аккордеоном |
| Новая спека (`<Spec>.dev-spec.md` + пересборка `hub.js`) | плитка в колонке спецификаций команды |
| Новая карта экранов (`screenMap.maps` + пересборка `hub.js`) | строка сразу под записью приложения `after`, в его колонке |

## 6. Данные

Источник — `hub.js` в корне: `window.IBPHub` (одна запись на приложение) и
`window.IBPHubSpecs` (одна запись на спеку). Реестр собирается генератором
`hub-build.mjs` из `apps/<раздел>/<id>/app.json`, `project.json → hub.ds` (запись ДС),
`project.json → localKit` (витрина локальных компонентов — по записи на раздел,
`apps/local-components/<раздел>/index.html`), `project.json → knowledgeBase` (глоссарий),
`project.json → screenMap` (карта экранов проекта — сразу под записью приложения
`after`, `apps/screen-map/<раздел>/index.html`) и `refs/<Spec>/<Spec>.dev-spec.md`
приложений; руками не правится.

| Поле `IBPHub` | Тип | Обязательное | Примечание |
|---|---|---|---|
| `id` | строка | да | уникальный ключ |
| `group` | перечисление | да | `ds` · `projects` · `concepts` · `kb` |
| `title` | строка | да | название строки и пункта меню |
| `desc` | строка | да | описание одной строкой |
| `href` | строка | да | стартовая страница, путь от корня |
| `root` | строка / null | да для `projects` и `concepts` | каталог приложения от корня, `apps/<раздел>/<id>`; группа записи — группа трека из его `app.json`; у карты экранов — папка карты `apps/screen-map/<раздел>` (без `app.json`, группа — колонка записи `after`) |
| `icon` | строка | да | имя глифа из `design-system/foundations/Icons/Icons.md` |
| `shelf` | `actual` · `archive` | нет | полка концепта; у группы версий — полка последней |
| `concept`, `version` | строки | нет, только вместе | название концепта и подпись версии (`v3`); записи с одним `concept` — одна плитка |

| Поле `IBPHubSpecs` | Тип | Обязательное | Примечание |
|---|---|---|---|
| `id` | строка | да | имя спеки (`spec` в front matter) |
| `title` | строка | да | название сценария; спеки с одним `title` — версии одной плитки |
| `module` | строка | да | раздел и модуль, чьи страницы сняты (`postrade/drafts/…`); первый сегмент — команда |
| `version`, `stage`, `date` | строки | `version` да | подпись версии — `stage`, иначе «Версия `version`» |
| `href`, `root` | строки | да | страница спеки `<root>/pages/Spec.html?spec=<id>` и каталог приложения со спеками |

Полноту реестра и обратные переходы проверяет сторож
`.agents/tools/registry-check.mjs` (шаг `registry` гейта).

## 9. Доступность

- `<main>` для контентной области, `<nav aria-label="Хлебные крошки">`,
  `<nav aria-label="Главное меню">`;
- заголовки колонок — `h2`, заголовки плиток концептов — `h3`; `h1` нет, как на стартовой странице;
- строка и карточка — настоящие ссылки: фокус с клавиатуры и Enter без скрипта;
- аккордеон раскрывается с клавиатуры кнопкой `.tile__toggle` (`aria-expanded`, `aria-controls`);
  клик по шапке — дополнение для мыши;
- контейнер колонок несёт `role="status" aria-live="polite"`: смена команды объявляется;
- ведущая иконка `aria-hidden`, смысл несёт Label.
